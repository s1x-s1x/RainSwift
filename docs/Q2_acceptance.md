## 2. 测试结果

服务器：AMD EPYC 7R32（192 个逻辑核），Linux 5.15，工具链 Zig 0.13.0（目标 linux-gnu.2.35）、meson 1.5.2、ninja 1.11.1，与 P0 相同。主测试用 -O2 手工构建（开断言），另用 P0 release 选项复测。

| 项 | 要求 | 结果（六组，B1=0） |
|---|---|---|
| T1 | VOLE_ROWS = 128R + 256 + 8·B，签名长度等于冻结值 | 全部相等：688 / 816 行；4,146 / 3,706 / 3,014 / 4,112 / 4,080 / 3,190 B；编译期 `static_assert` 与运行时双重检查 |
| T2 | 签名方 V、u 与验证方重构 Q 逐行核对 Q = V ⊕ Δ·u | 每组 3 个签名，见证段、QuickSilver 掩码段、VHash 掩码段及末行**全部 0 不一致**。填充行（Rain-3 第 688–767 行、Rain-4 第 816–895 行）每组约 6,400–6,900 位不满足该式，**在所有计算中被忽略**（不是全零）：VOLE 检查与 QuickSilver 只读有效行，签名也不含这些行，验签照常通过 |
| T3 | 代码中构造 k = pt ⊕ rc_t(0)，`faest_pubkey` 返回 false | 每组 4/4 被拒（R=3、4 均覆盖） |
| T4 | 脚本随机源：先给零输入密钥，再给正常密钥，`crypto_sign_keypair` 返回第二组 | 每组通过：返回的 sk、pk 恰为最后一个候选，且能签能验 |
| T5 | 逐字节异或 0x01、0x80；截断 1 字节、多 1 字节；换消息、换公钥、换参数集 | 每组在全部字节上翻转两次（6,028–8,292 次），**0 次被接受**；其余五类篡改全部被拒 |
| T6 | 每组 1,000 次随机密钥签名—验签；同一消息签两次结果不同 | 每组 1,000/1,000；同一消息两次签名不同且都能验过 50/50 |
| T7 | `faest_pubkey` 与 Q1 Rain KAT 一致；固定随机源下各生成签名 KAT 并存哈希 | Q1 KAT 每组 11/11（含拒绝用例）；签名 KAT 可复现且能验过，已入库 KAT/（内部记录，未随仓库公开）（含 SHA256SUMS.txt） |
| T8 | 同一 pt、不同 k、相同 μ 与 ρ，派生的 (r, iv_pre) 不同；审查 H₃ 吸收 k | 每组派生值不同；解包后的 `sk.sk` 等于打包私钥第 16–31 字节（即 k），不等于 pt。代码审查：faest.inc:53–58（内部记录，未随仓库公开） 依次吸收 `sk.sk`、μ、ρ 与字节 3。T2 另核对签名中的 iv_pre 等于按 H₃(k‖μ‖ρ) 重算的值 |

B1=1（`-DRAIN_SHRUNK_KEYSPACE=1`）：同一程序同样 6,582 项 0 失败。约束数变为 Rain-3 为 4、Rain-4 为 5；T4 依次跳过零输入密钥和“ψ(k) 第 0、1 位同为 1”的密钥，返回第三个候选；Q1 KAT 中分别有 3 把（Rain-3）、1 把（Rain-4）密钥落在缩小后的密钥空间之外，均按预期被拒；签名长度不变。B1=1 的 KAT 另存（文件名带 `_b1`）。B1=1 只是工程开关，Q4 的证明按完整密钥空间（B1=0）写成。

## 4. 约束证明微基准（参考，非正式性能结果）

只计时 `owf_constraints`（证明方、验证方），每组 2,001 次取中位数；-O2 构建，单线程，服务器同时有他人负载（load 约 37）。

| 组 | 证明方 | 验证方 |
|---|---|---|
| Rain-3（三组） | 约 2.0 µs；约 1,830–1,850 TSC 周期/轮 | 约 1.6 µs；约 1,440–1,460 TSC 周期/轮 |
| Rain-4（三组） | 约 2.8 µs；约 1,930 TSC 周期/轮 | 约 2.2 µs；约 1,500–1,520 TSC 周期/轮 |

方案模型按每轮约 1 万周期估计，实测约为其五分之一。TSC 周期在频率变化时不等于核心周期；这一组件计时只作参考，正式的建钥、签发、验签时间以 Q3 的完整调用为准。
