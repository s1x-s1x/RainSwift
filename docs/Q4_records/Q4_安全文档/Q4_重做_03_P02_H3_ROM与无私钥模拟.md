# Q4 重做 03：H₃、ROM 与无私钥签名模拟

2026-10-14，路线 A，候选 v4，提交阶段 04。对象为 00b 六个冻结实例，B_bytes=6、全密钥空间；按固定单参数、单公钥分别证明。本文给出可运行的 pk-only 模拟、逐游戏距离和与 01/02 合并的 OWF 归约。通过状态由 04 对实际版本裁决，本文不自行宣布具体 128 位强度或 QROM 安全。

## 1. 真实接口与证明边界

用 01 的单一 XOF 随机预言、双向理想分组密码及 Rain 原像关系。目标优势明确记为 Adv^{OWF,IC}_{Rain}(B)：B 的辅助 IC 与 KeyGen 挑战独立，B 只作普通正/逆访问，并本地模拟向 A 提供的可编程 RO；该模型接口与普通无 oracle 的同价 Rain 假设分开陈述。本文将每叶 tape 的 AES 块数记为 r_blk=ceil(L/λ)=6/7（即 01/02 的 r），将 H_s 的根种子记为 s_root，二者类型不同。源码秘密派生 H_s（原注释 H₃）与最终 H_Δ（H₂³）不同：

\[
\mu=H_\mu(pk\Vert msg\Vert08),\quad
(s_{root},iv_{pre})=H_s(K_T\Vert\mu\Vert\rho\Vert03),\quad
iv=H_4(iv_{pre}\Vert04).
\]

deterministic 模式完全省略 ρ；randomized 公共 API 每次独立生成 16 字节 ρ。本文分别覆盖这两种接口；不把任意长度、攻击者指定随机种子的底层辅助接口默认为公开签名 oracle。测试中固定 ρ 的入口只用于核对重复派生的分布。

真实见证 W 有 ℓ=384/512 位，随机带 u 有 L=688/816 位：

\[
d=W\oplus u[0:\ell],\qquad |d|=\ell.
\]

d 在 chall2 之前已经生成，且进入 H₂ 输入。ũ 是 176 位 VHash 输出，chall2 是 448 位挑战；旧 `d=chall2⊕ũ` 被完全弃用。

一次签名 oracle 调用按标准 CMA 游戏原子完成，攻击者在调用前后可自适应查询 RO/IC。模拟器可以选择 Δ 后编程 RO，这项权限只属于签名模拟证明；01 的在线提取器仍严格在普通挑战回答前运行，绝不读取未来 Δ/open。

## 2. 秘密前缀检测器与精确缓存

归约在 A **首次触达每个完整 H_s 输入、回答任何长度前缀之前**解析前 16 字节作为候选 K_T（不足则普通回答）；相同输入的重复查询或 XOF 补长复用已判结果。首次检测用公开 pt、ct 计算真实 Rain 关系，包括非零 S 盒输入条件。若成立就输出该 Rain 原像并停止。它可以捕获与原秘密不同的另一个合法密钥，不需要唯一性假设，也不把“任何成功伪造都查询过 H_s”当作命题。

在未命中检测器的执行前缀内，A 从未触达真正 `K_T‖μ‖ρ‖03`。故每个新的 `(μ,ρ)` 的 H_s 响应可按两枚独立均匀 λ 位值隐式采样，B 无需知道其完整秘密输入。B 以 `(μ,ρ)` 缓存派生值和最终签名：deterministic 的 ρ 是空串，randomized 的 ρ 是 16 字节，二者不混淆。

**缓存等价的理由。**同一 `(μ,ρ)` 在真实实现使用相同 H_s 输入，因而 s_root、iv_pre、IV 相同；全部 IC/RO 值保持一致，见证固定，首个成功 grinding 位置及同批额外行也相同。因此真实重复响应逐字节一致，即使其间 A 做了其他查询。模拟缓存返回原响应恰好复现该分布。randomized 仍先独立取新 ρ，再查缓存；重复消息本身不会触发缓存。

不同 `(μ,ρ)` 的 s_root 或 iv_pre 仍可能碰撞。s_root 碰撞属于 §5 的隐藏标签事件，iv_pre 碰撞/旧 H₄ 输入属于 §4；缓存不消除这些生日项。μ 可由 A 的选择消息和查询完全知晓，本文不用 μ 提供秘密熵。

## 3. pk-only 模拟算法与可执行实现

输入仅为 P、pk、msg、签名模式、普通 IC/可编程 RO 访问、随机币及有限 grinding 上限 G。G 是正的 4 倍数，G≤2^32。模拟过程如下。

```text
SimSign(pk,msg,mode):
  rho = absent if deterministic else fresh 16 uniform bytes
  mu = RO(pk || msg || 0x08)[0:32]
  if (mu,rho) cached: return cached signature
  sample latent s_root, iv_pre uniformly (each 16 bytes)
  if iv_pre || 0x04 has any previous XOF record: abort_program
  iv = RO(iv_pre || 0x04)[0:16]
  sample Delta uniformly from {0,1}^D || 0^g
  sample opening = D sibling seeds || tau hole commitments, in source order
  sample c[1..tau-1] uniformly (each L bits)
  sample chi1 (704 bits), chi2 (448 bits), d (ell bits), a (128 bits), ut (176 bits)
  run the actual public VOLE reconstruction on (iv,Delta,opening,c)
  obtain hcom,Q and the verifier's exact X2 using chi1,ut,d
  apply d to Q; run actual Rain/QS verification using chi2,a to obtain b
  X1 = mu || hcom || c || iv || 0x09
  program_fresh(X1,chi1,signer-H1)
  program_fresh(X2,chi2,signer-H2)
  prefix = chi2 || b || a
  for ctr = 0..G-1:
    Y = fresh uniform 128-bit value
    if high_g(Y) != 0:
      program_fresh(prefix || ctr_LE32 || 0x0B,Y,signer-failed)
    else:
      program_fresh(prefix || ctr_LE32 || 0x0B,Delta,signer-success)
      fill up to the end of this x4 batch with independent uniform responses
      assemble c || ut || d || a || opening || Delta || iv_pre || ctr_LE32
      cache and return signature
  abort_tail
```

任何编程点若已被任何长度的 XOF 查询触达，立即产生编程冲突；不会覆盖旧答案。H₁/H₂ 的协议输出之外的 XOF 尾部按需独立延长。普通哈希查询按同完整输入保持一致。所有 H_Δ 成功、失败及同批后续行均带签名来源标记。

可执行实现为 [pk_only_simulator.py](%E7%A0%94%E7%A9%B6%E6%9C%AD%E8%AE%B0_20261014/H3%E6%A8%A1%E6%8B%9F/pk_only_simulator.py) 和 [pk_only_native.cpp](%E7%A0%94%E7%A9%B6%E6%9C%AD%E8%AE%B0_20261014/H3%E6%A8%A1%E6%8B%9F/pk_only_native.cpp)。适配层直接包含冻结 VOLE、Rain、QS 和 `faest_verify`，仅将 hash_state 的输出接到真正的 RO 表回调；IC 动态检查使用冻结 AES 实现，数学分布证明另外明确采用 ideal cipher。既不调用 KeyGen/Sign，也不输入 sk 或见证。生成签名需要与其编程 RO 一同验证；这不是对普通 SHAKE 的签名伪造。

算法每次未缓存签名只调用一次公共重构。测试为核对行为另多次调用 Verify，不属于算法本身。洞零种子的临时承诺计算也实际执行，随后被 opening 中的洞承诺覆盖；该已知零 key 必须在隐藏分析计入。

## 4. RO 编程与 grinding 的精确距离

### 4.1 新鲜编程位置

一次新的缓存键对应独立均匀 iv_pre。命中既有 H₄ 输入的概率至多 h₄/M；未命中时新 IV 是均匀 λ 位，命中既有合规 H₁ 输入的 IV 字段概率至多 h₁/M。后者是充分的粗冲突事件，未借用 h_com 的熵。

chi1 在其使用前独立均匀；一个旧 H₂ 输入只有一个 chi1 前缀，故本次 H₂ 编程碰旧点概率至多 h₂/2^{L₁}。chi2 同理给 H_Δ 前缀碰撞界 h_Δ/2^{L₂}。本次全部 grinding 计数器共用一个 chi2 前缀，故不再为当前 G 个计数器额外乘 G；h_Δ 已含过去全部原始查询。其余字段可以依赖 chi1/chi2，匹配完整输入仍须先匹配该前缀。

这四项均在本次调用开始前的历史上计费；调用内部仅有不同域的普通聚合查询，不插入新的旧 H₁/H₂/H_Δ 目标。于是

\[
\epsilon_{program}=Q_{sig}\left(\frac{h_4+h_1}{M}
+\frac{h_2}{2^{L_1}}+\frac{h_\Delta}{2^{L_2}}\right). \tag{C1}
\]

采用 02 的全程预算比使用每次之前的计数更松，仍合法。所谓新挑战均匀性在抽样时使用；不在条件于**未来所有冲突都不发生**之后再次宣称无偏。所有游戏采用首次坏事件的耦合/并合论证。

### 4.2 首成功位置、x4 行与尾项

六组使用 ggm_forest，满足高 g 位零的挑战都有合法长度的开示。新 H_Δ 的成功概率 p=2^{-g}。真实第一个成功计数器 C 的质量为 `(1−p)^c p`；成功输出在 D 位子空间内均匀，与 C 独立；此前输出独立条件于高位非零，同批后续输出无条件均匀。

模拟器用独立原始 λ 位 Y 判断成功/失败，失败时保留 Y，成功时以预选均匀 Δ 代换。上述三种联合分布逐项相同。x4 预先计算的后续至多三行也写入表中。固定 ctr=0 或只保存成功行均不具有这个分布。

若在 G 次内没有成功，耦合距离至多

\[
\epsilon_{tail}=Q_{sig}(1-2^{-g})^G. \tag{C2}
\]

G 为 4 倍数，成功同批不会越过上限。真实 32 位计数器耗尽包含在这个事件内。冻结底层 `faest_sign` 此时返回 false，上层 API 对失败返回的处理另有工程边界；本证明按整个事件付 C2，不声称精确模拟未完成签名的缓冲区。

可审计的整数选择为

\[
G=\min\left(2^{32},\;4\left\lceil\frac{2^g(\lambda+\lceil\log_2\max(1,Q_{sig})\rceil)}4\right\rceil\right).
\tag{C3}
\]

由 `ln(1−p)≤−p≤−p ln 2`，总尾项还可界为 `Q_sig·2^{-floor(G/2^g)}`。未触及 32 位上限时至多 2^{-λ}，Q_sig=0 时取 0。数值账本可以使用这个有证明的二进制上界，无需对百万次幂作浮点近似。

一般参数族要求 g=O(log λ)，故 G 是多项式。若声称该族的尾项渐近可忽略，计数器字段也须有 O(log λ) 位且容量至少 G；冻结 λ=128 的字段仍是 32 位。固定 32 位容量不自动支撑无限 λ 的安全族声明。

## 5. 隐藏路径的 ideal-cipher 耦合

本节先比较**未运行提取器**的 A 与签名 oracle 视图。Ext′ 会读取完整内部表；若先把它加入真实签名游戏，再声称它对真实隐藏 key 的读取仅是猜测，将出错。§7 最后才在 Sim 游戏加入非干预读取。

### 5.1 虚拟隐藏路径游戏

固定新签名的 Δ。在每棵树上只保留通往洞叶的隐藏路径，其他子树由公开兄弟种子按真实 IC 展开。引入互相独立、暂不供公开计算使用的隐藏标签（phantom labels）：H_s 的 s_root，以及每树根到洞叶的 k_t+1 个 seed；每签名共

\[
S_0=1+D+\tau.
\]

虚拟游戏给 D 个公开兄弟种子独立均匀值，给 τ 个洞承诺及每洞 r_blk 块原始 tape 独立均匀值。截取 tape 前 L 位；公开子树、聚合哈希及全部其他计算保持真实。缓存重复签名复用原虚拟对象，不重采样。

每个隐藏 key 最终需要植入的指定明文—输出单元为：s_root 下的 τ 个树根、D 个隐藏内部节点各两个孩子、τ 个洞 key 各一个承诺及 r_blk 个带块，总数

\[
J_0=\tau+2D+(r_{blk}+1)\tau=2D+(r_{blk}+2)\tau.
\]

固定 IV 下这些同 key 明文互异，由 00b 的 counter/tweak 检查保证。根展开无多余块。隐藏标签本身不参与虚拟游戏的公开输出计算；必要时可将这些标签的抽样延迟到公开轨迹之后，再检查可否植入。

### 5.2 三类冲突与覆盖

在时间 0 将 `0^λ` 加入已知 key 集合，覆盖实际 Verify 的 dummy 调用。植入失败只需以下三类事件：

1. 隐藏标签彼此相等，包括不同新缓存键产生相同 s_root；同一缓存项复用不算新标签。
2. 某个隐藏标签等于普通 IC 查询使用的 key。普通调用包括 A 的正/逆查询、公开兄弟子树的展开、leaf/tape、dummy 和最终 Verify。公开兄弟 seed 都会在真实重构中用作 IC key，因此其与隐藏标签碰撞也在此类。标签生成前的旧 key 与生成后的新 key 两个方向都检查。
3. 同一个隐藏 key 的不同明文被安排到相同输出。根的多个孩子、路径的两孩子、洞承诺和长 tape 块共同检查，未把 com 与 tape 分成独立实际置换。

没有这些事件时，每个隐藏 key 既未被普通表使用，又不同于其他隐藏 key，其需植入的输入和输出各自互异。因此可以把所需单元逐项填入该 key 的随机置换，剩余单元按均匀补全；获得真实树、真实洞承诺与 tape，公开兄弟子树及对手全部已有回答保持一致。逆查询同样显式指定 key，若不命中隐藏标签，不接触这些植入单元。

这种构造无需把已经公开的兄弟 seed 查询当作坏事。公开 key 可以反复被 A 正常使用；仅与仍隐藏的标签重合才触发事件。跨 IV 共享明文亦不破坏“不同 key 的独立置换”；相同隐藏 key 跨新签名出现已单列为标签碰撞。

### 5.3 条件概率与保守总界

记真实 Sign 的调用数 `A_S=(r_blk+3)N−τ`，真实 Verify 次数为 02 的 A_V。取

\[
P_H=a_{IC}+Q_{sig}(A_S+\tau)+A_V,\qquad
T=1+P_H+Q_{sig}S_0. \tag{C4}
\]

P_H 上界虚拟游戏普通 IC 调用与受保护的植入单元数之和：每个新签名的公共重构需 `A_V=A_{V,effective}+τ` 次，植入需 J₀ 个单元，故两者共 `A_V+J₀=A_S+τ`。这里的 Q_sig·τ 逐次覆盖 dummy，末尾 A_V 仅覆盖最终验签。T 另外计全部隐藏标签与零 key。它不包含真实游戏的 Ext′，因为本节尚未运行 Ext′。

在虚拟游戏中，隐藏标签不决定公开数值；对手适应性只依赖普通表和已给出的虚拟输出。将未使用标签延迟抽样，或逐次在首次冲突前保持其剩余候选对称性：每个新标签撞已有候选的条件概率至多 T/(M−T)；每个普通 key 撞某个隐藏标签的条件概率至多 T/(M−T)。各自至多 T 次，因此标签/旧表别名与后续 key 触达各至多 T²/(M−T)。这项条件化针对可见轨迹及已排除候选，不声称在把隐藏标签也固定的完整私有记录下仍有猜测熵。

对单隐藏 key，在其普通表为空且明文互异时，置换的连续输出为不放回均匀抽样。将它与虚拟独立输出耦合，仅在后者命中该 key 已使用输出时失败；累计至多 `Σ_K binom(j_K,2)/(M−T)≤T²/(2(M−T))`。任何输出作为后续隐藏/公开 key 的相等，已由前两类处理。分母使用同一较小剩余规模，保守并合留出余量可取

\[
\epsilon_{hide}=\begin{cases}
0,&Q_{sig}=0,\\
\min\{1,4T^2/(M-T)\},&Q_{sig}>0,T<M,\\
1,&Q_{sig}>0,T\ge M.
\end{cases} \tag{C5}
\]

这是经典有界查询耦合；不是“真实 transcript 下隐藏 seed 显然均匀”的断言。即使某些公开掩码泄露了洞 tape 的全部值，虚拟标签仍不用于生成这些值，只有通过该 key 的 IC 查询才能验证关联，已在第 2 类收费。C5 很宽，04 必须独立检查本节的事件覆盖和计数；它不代表同成本实际攻击。

## 6. 三角双射给出完整联合掩码分布

在 §5 虚拟游戏中固定 Δ、公开 opening/子树、c、chi1、chi2。每棵树的洞 tape 独立均匀。令 B_t 为该树全部公开叶 tape 的 XOR，则

\[
u_t=B_t\oplus m_{t,hole},\qquad c_t=u_0\oplus u_t.
\]

映射 `{m_{t,hole}}↔(u=u₀,c₁,…,c_{τ−1})` 可逆：洞 0 的 tape 为 u⊕B₀，洞 t 的 tape 为 u⊕c_t⊕B_t。因此 u 和所有 c_t 联合独立均匀。

将 u 分成 `u_W`（ℓ 位）、`u_QS`（λ 位）、`u_VH`（λ+b 位）。由真实 VOLE 式，在固定 Δ 和公开 Q 后，`V=Q⊕uΔ^T`。给定有效真实 W，签名可见掩码满足

\[
d=W\oplus u_W,\qquad
\tilde a=Z_1(W,V_W,chi2)\oplus u_{QS},\qquad
\tilde u=VH'_{chi1}(u_W\Vert u_{QS})\oplus u_{VH}. \tag{C6}
\]

Z₁ 仅使用前 ℓ 行约束 MAC，故不含后面的 u_QS/u_VH。给任意 (d,ã,ũ)，按顺序唯一恢复 u_W，再由 V_W 恢复 Z₁ 和 u_QS，最后恢复 u_VH。三个对角映射均是恒等 XOR。因此 `(d,ã,ũ)` 是**联合**均匀串，维度相加恰为 L，分布不依赖 W。

这比逐项宣称“每个 mask 均匀”更强，也没有把 d 与 chall2 混用。chi1/chi2 的新鲜性来自 §4 的游戏重排，而非从真实自适应 transcript 凭空假设。

对于有效 W，01 式 (5) 的 e=0；代入真实 `qs.prove/verify` 有 `b_verify(Δ)=Z₀+η₀=b_real`。因此所有其他量均可由公开 Q、d、ã、chi2 算得，正是 §3 的 native 调用。H₂ 中的 Ṽ 也由 `VH(Q)⊕Δũ` 唯一算出，与真实 sender 逐列一致。故将隐藏 u 换成独立抽样的 `(d,ã,ũ)` 是精确变量代换，没有另付“VHash/ZHash 隐藏假设”或不可见 sk。

## 7. 逐游戏合并，避免 H₃ BAD 的循环归约

设 HitKey 为“A 的 H_s 查询带有任意合法 Rain 密钥前缀”的检测事件。在分析用真实游戏中也安装同一公开检测器，一旦 HitKey 发生即把归约记为成功并停止；这只能把原伪造成功事件扩大为 `HitKey ∨ Forge`。

| 游戏 | 知识与变更 | 与前项的关系 |
|---|---|---|
| G0 | 真实 KeyGen/Sign；普通 XOF/IC；尚无 Ext′ | 原 EUF-CMA 游戏 |
| G1 | 仅在 A 的 H_s 查询回答前运行公开 Rain 检测器，命中即成功停止 | 原 Forge 优势≤Pr[HitKey∨Forge]；非假定每个伪造都触发 HitKey |
| G2 | 未命中 HitKey 的新 (μ,ρ) 用隐式均匀 s_root/iv_pre；重复项保持缓存 | 可见轨迹完全相同；此时 A 尚未查询真实秘密前缀 |
| G3a | 在新编程点预抽 chi1/chi2，按真实首成功分布抽 Δ/ctr；记录失败及 x4 行，G 次截断 | 差异≤C1+C2；没有用 μ 的熵 |
| G3b | 顶向下的隐藏路径改为 §5 虚拟标签及独立输出，公开子树仍查询真实 IC | 差异≤C5，计正逆/长 tape/零 dummy/跨签名碰撞 |
| G4 | 对隐藏 u 作 §6 三角变量代换，按公开 Verify 算 b | 精确等分布；到此可运行 B 仅需 pk |
| G5 | 在 G4 加入 01 的内部 Ext′ 普通 IC 读取、程序行标记和新消息链检查，任何合法提取密钥也输出 | 非干预读取不改 A 视图；剩余失败由 02 的 B9 覆盖 |

G0–G3b 中的 sk 仅存在于分析游戏，G4/G5 的实际 B 没有它。所有分布比较在检测器成功前耦合；不先用一个“知道 sk 的签名模拟器”去证明 BAD 可归约，再循环声称已有 pk-only 模拟。

令 U 为停止游戏的胜利谓词 HitKey∨Forge。由逐游戏耦合，

\[
\Pr[Forge_{real}]\le\Pr[U_{sim}]+\epsilon_{program}+\epsilon_{tail}+\epsilon_{hide}.
\]

在 G5，HitKey 立即给 B 合法原像；若最终新消息伪造成功且 HitKey 没发生，02 的程序行隔离和事件覆盖保证，除 B9 误差外已有有效 W*，其首字段经真实关系核验给另一个合法原像。两条成功路径属于**同一个** B，所以

\[
\Pr[U_{sim}]\le Adv^{OWF,IC}_{Rain}(B)+\epsilon_{extract}.
\]

这里没有把 Pr[BAD] 与 Pr[Forge] 等同，也没有为两个独立归约各收一次 OWF 优势。

## 8. 合并定理与资源

对上述固定实例、经典有界查询 A，存在 pk-only 归约 B，在已明示的 ideal-cipher/ROM 中满足

\[
\boxed{
Adv^{EUF-CMA}_{P}(A)\le
Adv^{OWF,IC}_{Rain}(B)+
\epsilon_{hide}+\epsilon_{program}+\epsilon_{tail}+
\epsilon_{chain}+\epsilon_{pair}+\epsilon_{late}+
a_1{\tau\choose2}\epsilon_V+a_2\epsilon_Z+
\frac{3a_\Delta+1}{2^\lambda}}
\tag{C7}
\]

各项取自 C1–C5 与 02 B2–B8；最终右侧截到 1。P≥M/T≥M 时使用所规定的平凡项。所有概率单位是位：λ=128、b=48、L₁=704、L₂=448，R=3/4。公式本身仍须通过 04 才进入 05 的数值验收。

B 的实际 IC 调用为 01/02 的 P，不是用于耦合的 P_H；P_H 含分析用真实 Sign 隐藏调用，T 只服务 C5，二者不可混用。B 每个新签名公共重构一次、最多 G 个 H_Δ 点；H_s 检测加提取密钥核验最多 a_s+a₂ 次 Rain 公开关系。总时间为 A 时间加上多项式哈希/域运算、`r_blkNa₁` 个 tape 调用及签名/验证成本，存储包含快照与至多 Q_sig G 个编程行。

B 以外部理想 IC 的正/逆回答维护表，不用无界拒绝采样模拟置换；预言成本按查询模型计费。01 的 k_max=O(log λ)、N=poly(λ) 加上 g=O(log λ)、明确计数器族，使 B 为 PPT。对六个固定程序，本文还给出具体有限次数，不用渐近用语隐藏大常数。

带独立辅助 IC 的 Rain 单向性、具体 AES/SHAKE 的理想化适用性是条件，尚无 QROM 归约。C5、B3/B4 的宽损失即使正确，也可能令目标预算的界饱和。05 应分别报告剩余误差、OWF 依赖和适用预算；`−log₂(误差界)` 不是攻击工作因子。
