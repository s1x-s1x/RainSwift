# Q4 阶段 05 精确账本

本脚本从正式 02 的 B0–B9、正式 03 的 C1–C7 逐项计算归约误差。它仅做有限算术核验，不运行冻结签名代码、不执行性能实验、不提供新的 Rain 单向性估计。审查门控与实际文件 SHA-256 一致后，主账本才开始计算。

所有概率都用 Python 标准库 Fraction。JSON 中分子、分母及大整数查询数保存为十进制字符串；Decimal 只生成显示字段，所有大小比较、截断与通过判定均用整数或有理数。尾项使用已经证明的 Q_sig/2^floor(G/2^g) 上界，并同时保存真正尾项的表达式。无需构造百万次精确幂。

## 示范预算

| profile | 各个 RO 域预算 | 正逆合计 IC 预算 | 签名请求预算 |
|---|---:|---:|---:|
| KO20 | 每域 2^20 | 2^20 | 0 |
| CMA20 | 每域 2^20 | 2^20 | 2^10 |
| CMA32 | 每域 2^32 | 2^32 | 2^20 |
| CMA48 | 每域 2^48 | 2^48 | 2^32 |

七个域分别是 H_c、H_mu、H_s、H_4、H_1、H_2、H_delta。预算是每域首次触达完整输入的上界；包括同域不合规输入，以及只索取短前缀或零长度输出的请求。H_delta 计全部原始 grinding 查询，含失败、预计算和 x4 额外行。这些示范设置中的其他 RO 域请求数设为 0。

因此“每域 2^q”与“总查询数 2^q”有区别。每个结果同时报告七个域之和、RO 加 IC 之和、再加签名请求数之和。合计只是调用计数，未将异构操作折算为相同时间成本。上述四种设置全部标为示范，未把它们作为用户已批准的安全目标。

## 公式覆盖

参数仅保留六组冻结的 R、tau、g；树高按 D=128-g 与 divmod(D,tau) 推导，N 为各树叶数之和。带块数 r=ceil((128R+256+48)/128)。真实 Sign/Verify 的分类调用数与阶段 00b 已保存的 R6 记录逐项比对；这里复用 R6，不重新运行原生代码。

特别地，C4 使用 P_H=a_IC+Q_sig*(A_S+tau)+A_V。每个模拟签名重构的 tau 个零 key dummy 调用已经计入。P、P_H 与 T 分开报告，耦合分析成本不会冒充归约 B 的实际 IC 调用。

九项 C7 误差全部保留：hide、program、tail、chain、pair、late、VHash AU、ZHash 和挑战项。chain 的七个子项、program 的三个子项及两个通用哈希界的子项也全部输出。

pair/late 在 P>=M 时，hide 在 Q_sig>0 且 T>=M 时，直接采用定理规定的 1。越界的原始有理式记为 null 并给原因；不构造零或负分母。Q_sig=0 时，hide/program/tail 均为 0。保存每个适用原始式、规定的局部截断、局部截断后的总和、可定义时的截断前总和、最终 min(1,...) 以及全部饱和标记。

默认 OWF 优势为 unknown，不填 0。结果给出 min(1,Adv_Rain^{OWF,IC}(B)+error_sum)。如另有明确的有理 OWF 上界，可用 --owf-bound NUM/DEN 显式输入；输出会注明它是调用者给出的条件。

存储结果给出快照、IC 三元组、RO 协议前缀、模拟 grinding 行及签名缓存的整数核心数据量。未指定的输入总长度、XOF 延长长度和数据结构开销另外保留为未知量；因此不把核心数据量称作整机内存上界。脚本自身运行的实测内存另列。

## 运行

运行输出必须是原始数据/重做05 下一个尚不存在的新子目录。每次运行保留新目录；失败也保留部分结果。单 Python 进程，120 秒、512 MiB，按每个读哈希块、核验组与参数预算组合检查资源。程序为小规模精确算术，不创建子进程、不分配与预算值成比例的表。

门控通过后执行：

~~~powershell
python -X utf8 '<工作区>\迭代\迭代030_高把握方案\Q4_安全文档\脚本\重做05\run_ledger.py' run --output '<工作区>\迭代\迭代030_高把握方案\Q4_安全文档\原始数据\重做05\R1_精确账本'
~~~

省略 --profile 和 --set 时执行四个示范预算与六组参数，共 24 条结果。可重复指定 --profile 或 --set 选择其中有限子集；这不是参数搜索。默认未给 OWF 数值条件。

只检查算术边界、尚不计算任何正式预算时：

~~~powershell
python -X utf8 '<工作区>\迭代\迭代030_高把握方案\Q4_安全文档\脚本\重做05\run_ledger.py' self-test --output '<工作区>\迭代\迭代030_高把握方案\Q4_安全文档\原始数据\重做05\边界自检_新目录'
~~~

主程序自动包含同一套有限边界核验：零签名、P=M/T=M、ceil(log2) 的二次幂边界、x4 向上取整、32 位计数器上限、小参数真实尾概率与 dyadic 界的精确比较，以及指数显示的整数上下界。自检不证明密码学定理。

## 输出文件

- run_started.json：输入命令、Python/系统、脚本哈希和资源上限。
- gate_checked_before.json、gate_checked_after.json：通过审查的真实版本与哈希。
- parameters_and_native_counts.json：六组推导值与 R6 复用比对。
- boundary_selftest.json：有限边界核验的每组数量和失败清单。
- case_PROFILE_SET.json：逐参数、逐预算的完整精确结果。
- ledger.json：合并结果，保留全部精确分数。
- ledger_summary.csv：便于报告引用的显示摘要。
- run_finished.json：实际运行时间、峰值内存和合并结果哈希。
- failure.json：若发生失败，保留异常、已有输出数量与资源状态。

PASS 只表示算术与已审输入一致。误差界的负二进制对数不是攻击工作因子；界饱和不构成同成本攻击。经典理想模型定理、具体 Rain 优势、具体 AES/SHAKE 适用性、QROM 与 Q2/Q3 的工程验收继续分别表述。
