## 3. 调用者及最终Verify

脚本把各a_j设为同一个示范上限a：A的七类RO域分别各≤a；A正逆IC调用总和≤a。这不是七域请求总和≤a。

~~~text
a_j：A首次触达该域的完整输入数；
h_j：包含模拟器与最终Verify的总数。
q₀ = a_IC+(Q+1)A_V；
q_anchor = a_IC+Q A_V；
h_Δ = a_Δ+QG+1。
~~~

与共享地址05及新总界02已明确的caller约定一致：仅A输出前的普通首次H₁/H₂建立和执行提取钩子，最终Verify的新记录不产生额外角色完备化根。Verify所有普通IC/RO仍记入q₀、h_j；Full缓存命中照常首次提升为Source。

好链上的旧HΔ已关联唯一的较早A侧H₂/H₁；逆序补链由epsChain支付；最终全新HΔ命中签名已经固定的Δ另付1/M。因此q_anchor排除末次A_V，与AU使用a₁、ZHash使用a₂及挑战使用a_Δ相容。

## 4. 尾界、显示与有限核验范围

设m=2^g。由(1−1/m)^m≤1/2：

~~~text
Q(1−2^−g)^G ≤ Q·2^−floor(G/2^g)。
~~~

脚本使用右侧二进制有理数。四个固定示范Q对应G覆盖128+ceil(log₂Q)个这样的块；Q=0时尾项显式取0。G为正4倍数、G≤2^32及tail≤2^−128均设置断言。该尾项衡量grinding模拟截断，不代表整个方案的安全位数。

fr函数用整数比较确认floor(log₂(denominator/numerator))，包含分数大于1的情形。log2_display只是展示；Rain_OWF_advantage和complete_forgery_probability_or_security_bits均保留None，未以加性误差直接输出安全位数。

残余置换枚举核对的是“前r−1整块、末块b位”的补全数；MITM枚举使用非单射线性H，核对保留首个代表的存在性与实际见证。两者均属有限代数检查，未代替一般证明。

helper按非main名称加载，只调用process_limits；未见隐式运行其R1主实验的调用。本审查没有实际执行这一import。
