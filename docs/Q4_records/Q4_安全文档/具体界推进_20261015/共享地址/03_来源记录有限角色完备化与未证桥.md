# 来源记录的有限角色完备化与最小未证桥

2026-10-15；C030-RFAEST128-EQUIV-TIGHT1；equality_adversarial_review。新候选：**确定性的有限完备化及其覆盖引理已证明；把覆盖剩余项收紧为128位完整安全界尚未证明。**

本稿基于root提出的role completion方向及[来源隔离资源稿](../%E6%8F%90%E5%8F%96%E8%B5%84%E6%BA%90/01_%E6%9D%A5%E6%BA%90%E9%9A%94%E7%A6%BB%E7%BC%93%E5%AD%98%E4%B8%8E%E6%83%B0%E6%80%A7%E6%8F%90%E5%8F%96%E8%B5%84%E6%BA%90.md)。只读数学研究；未运行计算或密码实验，协议源码保持原字节。

## 1. 固定地址恒等式

固定一个参数集。r是每条有意义tape的AES块数，H是该参数的树高集合，d_H=|H|；本轮六组d_H=2。所有加减均在对应32位lane模运算中进行。

对任意完整叶承诺输入x_C及树高k，令：

~~~text
δ_k = 2^31 − (k+1)τ mod 2^32；
x_tape(c) = x_C ⊞ (c,0,0,δ_k)，0≤c<r。                (12)
~~~

对底层父节点的左输入x_0：

~~~text
x_1 = x_0 ⊞ (1,0,0,0)，
x_C = x_0 ⊞ (0,0,0,τ)。                                (13)
~~~

树号、IV在这些相对式中消去。k仅保留在叶tape的δ_k中。这里的消元已经由真实源码地址式及root的有限lane核对支持，一般成立来自模加恒等式。

## 2. Source根、有限模板及Full缓存

沿用资源稿的Source/Full区分：

- Source记录只能由A、pk-only模拟器的公开重构或Verify首次触达产生。
- Full可以多含提取器普通私有读取的结果。
- 私有成功、缓存命中与这些模板的计算不改变来源流程、RO编程或停止规则。
- 私有记录随后被来源触达时仍作新Source曝光；从这次曝光起可以作为一个新的Source根。

规范Source根是ρ=(s,x,y)，满足E_s(x)=y。只对每个Source根执行下述三种有限模板。由模板生成的私有行不会自动再次作为Source根。某模板内部允许有限个明确的派生读取；深度和分支由参数固定，不是递归闭包。

### 2.1 C模板：把来源行解释为叶承诺

对每个k∈H：

1. 登记候选叶描述符(s,x,y,k)，其中x是其叶承诺地址。
2. 依式(12)读取并缓存整条tape，或保存同一固定函数的惰性描述符。

每个Source根至多d_H r次外部IC读取。Source行本身的y已经给定。

### 2.2 T模板：把来源行解释为某一tape块

对每个k∈H和c=0,…,r−1：

~~~text
x_C = x ⊟ (c,0,0,δ_k)。
~~~

读取com=E_s(x_C)，登记(s,x_C,com,k)，并按式(12)补齐这个描述符的tape。其第c块正是原Source行，已在Full缓存。每种解释的新增外部读取至多1+(r−1)=r次，因此每个Source根至多d_H r²次。

这里给新com行只附加其指定k的tape，不将它重新送入全部C/T/P模板。若另一模板独立产生同一行和描述符，缓存合并。

### 2.3 P模板：把来源行解释为底层父节点的一边

将Source的key s记为父节点p。分别取ε=0,1：

~~~text
x_0 = x ⊟ (ε,0,0,0)，x_1=x_0⊞(1,0,0,0)，
x_C = x_0⊞(0,0,0,τ)。
~~~

原Source值是第ε个孩子。读取另一边，得到有序child seed(s_0,s_1)；读取com_0=E_s0(x_C)、com_1=E_s1(x_C)，登记父节点描述符：

~~~text
(p,x_0,x_C,s_0,s_1,com_0,com_1)。
~~~

再为每个孩子、每个k∈H登记叶描述符并补齐相应tape。每个方向至多1次另一边、2次承诺及2d_H r次tape读取。两个方向总计至多6+4d_H r次。

高度不用出现在父节点展开式(13)中；为叶tape登记全部k，是为了覆盖同一x_0在不同合法IV/树号下被解释为不同高度的情况。上层子树节点不在本模板中递归展开；本命题只处理底层兄弟对。

## 3. 明确的资源界

采用Full缓存，三个模板的每个Source根新增外部IC调用最多：

~~~text
c_role = d_H r² + 5d_H r + 6。                          (14)
~~~

若累计参与完备化的来源根至多q_anchor、全部来源IC调用至多q_0，则：

~~~text
P_full ≤ q_0 + c_role q_anchor。                         (15)
~~~

Rain-3的(r,d_H)=(6,2)，c_role=138；Rain-4为(7,2)，c_role=174。这是容易核验的先验上界，并非实测性能或紧界。缓存重合可减少调用，但式(15)已经将所有私有读取保留在归约资源中。直接取q_anchor≤q_0安全；若最终Verify以后没有新H₁快照，是否排除该部分根按实际调度决定。

每个Source根的叶描述符数至多d_H(r+5)，父节点描述符数至多2；树高相关tape引用至多再乘d_H。匹配索引与聚合CPU、H₁快照的持久化版本、H₂时的候选枚举成本另外计入总时间。式(15)仅计IC，不据此把B和A当作相同运行成本。

模板可在Source根产生后立即执行，也可在首次H₁响应前完成相关历史前缀。在数学上采用惰性版本时，每个描述符的根序号及角色解释先冻结，数值是同一预选理想密码E的确定函数；于H₂前普通读取求值。其挑战前AU固定性须使用资源稿F_allE论证，不能以H₂时的当前Source表代替历史前缀。

为每个派生描述符保留其Source根及source_time。某个后来生成的相同私有行不使旧快照自动升级；只有旧时刻Source根按既定模板本来会生成的描述符，才属于旧快照。新Source曝光可以产生新的有限模板，累计数仍受q_anchor约束。

## 4. 可证的确定性覆盖引理

固定一个H₁前Source历史前缀，按第2节得到冻结候选池。给定其后要解释的某树t、对应高度k、x_C及tape地址。定义K(x_C,com,k)为候选池中在该地址确实给出com的seed集合，按seed去重。

**引理RC1。**

(a) 若某叶seed在这个Source前缀中，已经有其真实承诺输入x_C的记录，则C模板把它纳入对应K。

(b) 若Source前缀已经含这个叶seed任意一个真实tape块的记录，则T模板的实际(k,c)解释恢复准确x_C，普通查询给出其实际com；它也在对应K中。这里只要求一个块，不要求整条tape已经公开。

(c) 若某个底层父节点的两个孩子输入中，任意一个在Source前缀已经触达，则P模板的实际ε解释恢复准确(x_0,x_1,x_C)，该父节点的两个seed、两个com及所有相关高度的tape都在冻结池中。

(d) 因而，对于一个实际叶seed，如果它在目标com的冻结K之外，则在H₁前Source中，其真实com输入及全部真实tape输入都未触达；它也没有作为第(c)款匹配父节点的孩子被登记。

证明：(a)直接用C模板；(b)对实际k和c代入式(12)的逆平移得到原x_C；(c)对实际左右ε代入式(13)，每次普通查询读取同一固定E，所以得到实际孩子与实际叶承诺；(d)为前三款的逆否命题。不同模板中的地址重合只触发缓存，不改变返回值，故不影响结论。

**RC1有两个直接用途。**

1. 旧OldTape/NewCom时序里，若挑战前任意相关tape块已经是Source记录，该seed的对应承诺将提前纳入冻结池；“只有旧tape而com没登记”的路径被显式覆盖。
2. 第02稿的半查询父节点，在χ前已有一边Source记录，故两个孩子及其承诺会在旧快照完整确定。它之后第一次公开补另一边不再是“首次未覆盖的匹配父节点”。

RC1只是一条覆盖引理，没有说未来所有相关seed都属于K。完全新出现的leaf或父节点仍存在，只是落在下一节描述的剩余类别。

## 5. 新候选的使用与限制

采用本候选池时，[仿射引理](01_%E6%9C%89%E9%99%90%E5%80%99%E9%80%89%E6%97%8F%E4%B8%8E%E4%BB%BF%E5%B0%84%E6%8F%90%E5%8F%96%E6%9B%BF%E4%BB%A3%E5%BC%95%E7%90%86.md)里的K可包含受控私有生成的叶seed，且从P模板选择的canonical pair两片seed均在同一冻结池中。因此该稿§4.1“基线属于相应K桶”的去重前提得到一个具体实现接口。

全局父节点索引包含完整上下文(x_C,k,com_0,com_1)；在固定树/快照中再按有序(com_0,com_1)对去重。若冻结池内同一对的所有父节点产生相同有序tape对，可以把这一对当作canonical；不同父节点但同tape无需收费。若出现不同有序tape对，记录语义歧义事件；它尚需概率界。若某对无匹配父节点，沿用第01稿的缺失对分支。

为维持AU时序，旧快照的K和canonical选择规则在χ前固定，或以历史根和E的确定函数在χ前语义固定。后来发现新parent或新leaf时，记录其是否落入剩余事件；不按最终开示重新选择旧canonical。

全域com桶帽可以约束本候选池每个K的大小，因为池中成员都是真正的叶承诺前像。然而桶帽本身不保证式(8)/(9)已经符合128位等强标准，应使用去重族大小和完整资源核算。

## 6. 最小未证桥：还缺哪些具体概率定理

### 6.1 冻结池中有序tape对的语义歧义

目标是界定同一x_C、同一有序com对有两个不同有序tape对的概率，且应覆盖上述所有私有模板、正逆Source查询、不同IV与角色重叠。

RC1不为这个事件给概率。一个全局叶生日碰撞可能只导致相同误差的无害重复；也可能作为更大结构的一部分。要删除旧PairCollision项，需要对真正影响canonical的语义歧义单独证明，而不是把每个父节点简单当独立2λ位随机函数样本。

### 6.2 没有旧Source半边的迟到父节点

RC1排除了旧Source半边遗漏。剩余父节点在本H₁切口的两个真实孩子输入都未被Source触达。但是它们可能早已在Full中由别的IV/角色模板私有定义。

第02稿式(11)只对适当过滤族下两个未揭露输出及固定目标seed集合成立。本稿扩大的K包含私有结果，一般不是F_src可测；一旦条件化于这些K或Full值，所需的双块均匀性可能已经改变。因此“两个地址Source未见”加“两个目标是K桶”，尚不足以直接代入u²/(M−q_0)²。

需要一个同时跟踪Source可预测目标和有限私有模板依赖的联合论证，或改用避免这种依赖的新事件定义。把条件分布放在Full时又直接称输出新鲜，会回到此前的错误。

### 6.3 冻结池之外的新leaf对最终有效开示的影响

RC1证明该leaf的相关com和tape输入在Source切口全部未触达。它没有证明此leaf日后匹配目标且通过有效协议检查的联合概率是“匹配项乘VHash项”。

原因有二：一是H₂检查值及开示可在χ后自适应选择；二是K的成员性本身依赖有限私有读取。应对“最终有效伪造的链与该新leaf的影响”计费，不能把任意无效查询的提取失败一律要求很小。

旧Source-only的LateAlternative并合界仍能保守覆盖一部分迟到匹配，但维持a₁Nq_0/(M−q_0)会留下旧宽损失。要证明等强，需把不影响公共u/v的迟到seed直接吸收，或对有害选择给更紧的联合界。RC1只把旧tape/半parent的遗漏变成明确的已覆盖类别。

### 6.4 查询计费与归约合成

即使前三个接口都有新界，还需与哈希链、QS/ZHash、原始H_Δ查询、CMA模拟和OWF假设在同一预算下合成。新增模板的138/174调用上界和候选CPU不得从最终归约成本删除。QROM与NIST类别1没有被加入当前验收门槛。

## 7. 当前可采用的结论

已有可证候选是“以Source为有限根、按C/T/P三种模板做有限完备化”：它解决跨IV地址解释的有限枚举、旧tape缺com登记及旧半parent未补全三件具体问题，费用明确为式(14)/(15)，并提供第01稿所需的冻结K和canonical接口。

尚未得到的是三个剩余事件的足够紧联合界：canonical语义歧义、新双块父节点及新leaf对有效伪造的有害影响。保留这些接口为未证，才能继续区分“有进展的证明候选”与“完整128位等强结论”。
