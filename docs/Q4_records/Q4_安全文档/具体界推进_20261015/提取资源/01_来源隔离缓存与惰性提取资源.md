# 原030在线提取：来源隔离、地址缓存与惰性求值

2026-10-15，`C030-RFAEST128-EQUIV-TIGHT1`。本稿提出原030六组的分析算法改进；协议源码、旧正式01–03和原始数据均保持原字节。状态为 **候选数学引理，待独立交叉审查**。适用模型是正式01的单参数、单公钥、经典ROM与普通双向理想密码；Rain公钥挑战与辅助理想密码独立。

本稿给出两项可分开采用的改进：

1. 提取器私有读取与攻击者/模拟器/验证器触达的记录分表。同一条来源承诺行的带地址只依树高，固定六组各仅两种树高，补齐次数由 `r N a₁` 收紧到 `min(r N a₁, 2r q_anchor)`。
2. H₁前保存不可变的历史版本及带描述符，在首次被H₂引用时实际求值。差分仍由H₁前的描述符和同一理想密码完全决定；实际求值快照数 `e≤min(a₁,a₂)`，于是补齐次数进一步取 `min(r N e, 2r q_anchor)`。VHash误差仍按全部 `a₁` 个挑战前候选计费。

来源记录上的Pair/Late概率可以在一个单独的过滤族下用 `q₀` 计费；归约算法B的真实oracle资源仍支付全部来源和私有调用。此改进保留旧证明的宽生日项，未解决整体128位等强目标。

## 1. 输入、记号与确切次数因子

继承正式01–03：`λ=128, M=2^λ, L=ℓ+2λ+b, b=48, r=ceil(L/λ)`。第t树高为kₜ，叶数Nₜ，总叶数N，树数τ，`D=Σkₜ`。本稿的r是每条有意义随机带所需AES块数，Rain-3为6，Rain-4为7；它不是Rain轮数、256位存储块数或grinding零位数。

叶承诺与随机带的真实定义是

\[
x^{com}=iv\boxplus(0,0,0,(k_t+1)\tau+t),\qquad
m_s=\operatorname{prefix}_L\Vert_{c=0}^{r-1}E_s\bigl(iv\boxplus(c,0,0,2^{31}+t)\bigr).
\]

`⊞`是四个小端32位lane分别模加。依据：`prgs.hpp:198–205`；`vector_com.inc:238,1071–1082`；`small_vole.inc:108–166`；正式00b §§4、8。最后AES块仅前6字节有意义；提取器查询整块并截断。

令 `H={kₜ:0≤t<τ}`，`d_H=|H|`。固定六组各有 `d_H=2`。

来源进程指攻击者A、pk-only签名模拟器的公开重构、最终Verify，以及它们的正常RO调用；不含提取器私有查询。取先验调用预算

\[
A_V=(r+3)(N-\tau)-2D+\tau,\quad
q_0=a_{IC}+(Q_{sig}+1)A_V,\quad
q_{anchor}=a_{IC}+Q_{sig}A_V. \tag{R1}
\]

`a_IC`同时计正向与逆向调用，`+τ`保留零key洞承诺死计算。模拟器每个未缓存签名公开重构一次；缓存命中实际减少调用，但先验式仍按请求数Q_sig上界。最后Verify结束后不再运行A，也不触发新的提取钩子，故其新行无需列入anchor预算；采用更保守的 `q_anchor=q₀` 同样成立。任何改变这个调度的实现应采用后一数值。

`q₀`是调用数上界，也上界来源首次曝光的不同IC行数。`P_full`是B实际向外部IC取得的不同映射数；两者含义不同。RO的输入/输出总位数、短前缀补长、重复调用和预留采样全部另计运行时间。

## 2. 先排除会破坏改进的做法

下列反驳检查决定了本稿的设计。

**私有行自举。**若所有私有补齐行立即进入候选种子索引，一条来源行补出新的 `(K,x,y)` 后，又能以新的IV把该行解释为另一片承诺，再补出更多带行。一个来源anchor不再只有有限两种带；沿地址平移反复推进会绕过 `2r q_anchor` 的计数。有限群最终回绕不意味着该闭包是所需多项式时间算法。本稿将私有行排除在来源匹配索引之外。

**错误“物理表已定义，所以此后无随机事件”。**一个仅由Ext读过的行，首次被A/Sim/Verify触达时，仍是新的来源曝光。若此时把它当成旧来源行，可能漏掉H₁后发生的叶匹配。完整物理表中的值已经确定，与该值在来源条件分布中尚未揭露可以同时成立。

**以私有成功控制公开流程。**Ext提取出合法Rain原像后立即终止A，或依其成败改变签名模拟、编程点、采样次数，会使来源轨迹泄漏私有信息。本稿记录第一个成功密钥并继续既定有限来源执行，最后输出；Pair/Late/AU发生也只记录，不控制来源。H_s公开检测器同样可以仅记录，避免两种停机规则混用。

**只读现有带块。**H₁前已有承诺行而缺少随机带行的实例完全合法。直接把这些叶当未知并套原LateCom界会漏掉：A随后只查询带，承诺早已存在，全程没有迟到承诺匹配。本稿保留实际补齐，只减少重复与无用快照上的工作。

**用当前表代替历史表。**H₁后A新查出的种子可能依赖chall1；若在H₂才选用当前匹配种子集合，VHash差分已失去挑战前固定性。惰性版本必须检索保存水位之前的记录，冻结选择规则，不接纳新行。

**自适应选中次数替代a₁。**A能先看很多H₁挑战，再只提交一个有利的H₂。因此仅求值e份快照节省的是资源，VHash坏事件预算仍有a₁，不能以e代换。

## 3. 两张IC表及无反馈实现

`Full`保存B真实收到的全部普通IC映射，以 `(K,x)` 和 `(K,y)` 双向索引；调用正逆任一方向都规范化为同一行 `(K,x,y)`。每次外部查询均付费；命中Full缓存时无需再次向外部IC调用。

`Source`是Full的子集，保存来源进程已经触达的规范行，每行有首次来源曝光序号 `source_time`。`SourceByPair[(x,y)]`仅索引这些行，并按source_time追加。Ext只读产生的新行只进入Full，不进入Source。之后任何来源调用触及它，先完成promote，再向来源进程返回，source_time取这次新曝光时刻。

```text
PhysicalIC(direction, K, half):
  if matching row is in Full: return cached row
  answer := ordinary external ideal-cipher query(direction,K,half)
  normalize (K,x,y); insert both Full indices; charge one actual query
  return row

SourceIC(direction, K, half):
  row := PhysicalIC(direction,K,half)
  if row has no source_time:
    source_clock += 1
    assign immutable source_time; append row to SourceByPair[(x,y)]
  return requested answer to A/Sim/Verify

PrivateIC(direction, K, half):
  return PhysicalIC(direction,K,half)      // no promotion or Source callback
```

Sim和Verify只使用自身输入、来源已返回的值、独立随机币与来源RO接口。它们不扫描Full、不读取Ext结果、不根据Full缓存是否命中改变可见流程。该限制也覆盖签名缓存键、grinding上限和编程冲突规则。缓存命中/延迟的真实运行时间计入B资源，但当前游戏不向A开放时间侧信道。

RO仍为正式01中的单一前缀一致XOF表。首次触达包括零长度响应；合规普通H₁/H₂的冻结/提取钩子在新挑战采样或透露之前运行。若实现先预留随机挑战，钩子的数据依赖仍应严格排除该新值；下文伪代码直接把采样放在钩子之后。程序化签名行保留来源标记，依正式02 §2.3与新消息条件隔离。

## 4. 来源边缘分布与Pair/Late费用

**引理R2（来源边缘）。**在§3的无反馈实现中，删除全部PrivateIC调用、私有缓存和Ext计算，来源进程的联合轨迹分布保持不变。

证明：实验开始时抽取每个K的独立均匀置换E_K。PrivateIC只读取该已选置换，不修改它，也不向来源进程输出。对相同的来源随机币、RO采样及同一组E_K，两种执行中每次来源调用的地址、答案和下一步控制流逐步相同。Full缓存只改变B何时读取和多少次读取，不改变来源答案。即使来源以后查询一个提前读过的位置，答案仍是同一E_K的值。对E_K和随机币取平均即得结论。证明不要求私有行少于来源行，也不要求私有读取独立。

概率分析用过滤族 `F_src`：全部来源调用/回答、来源随机币及所需RO预留值，但不含PrivateIC回答、Ext派生量、缓存命中标志或私有成功标志。所有待分析叶目标由H₁输入和此前来源RO记录决定，故在登记时对F_src可测。已保存source_time使候选选择也仅依F_src。

删除私有读取的等分布来源实验中，每次新来源行，正向查询的y在同key未曝光输出上均匀；逆向查询的x在未曝光输入上均匀。分母为 `M−m_K^src`。在真实执行中该行可能早已存在于Full；这里仍以来源边缘求条件分布，未对完整Full历史作相同断言。

定义 `Pair_src`：来源表存在不同K给相同 `(x,y)`。定义 `Late_src`：H₁时从当时RO链得到的某一叶目标，之后有一个当时未在来源表中的匹配行首次来源曝光。后一事件可以覆盖**全部新前像**，即便该目标原来已有另一把来源key；只覆盖原未知目标的较窄版本也足以配合Pair_src支持旧提取器。

至多 `a₁N` 个带标签目标；晚加入的目标不回算旧曝光。每次新来源行前，正向固定x、逆向固定y之后，各自至多a₁N个候选半边。若q₀<M，

\[
\Pr[Pair_{src}]\le\min\{1,{q_0(q_0-1)\over2(M-q_0)}\},\qquad
\Pr[Late_{src}]\le\min\{1,{a_1Nq_0\over M-q_0}\}. \tag{R3}
\]

q₀≥M时取平凡界1。实际不同目标/新来源行较少时可细化逐次求和；先验式用完整调用上界。该证明明确计入逆向查询、模拟器的普通IC行、dummy行及最终Verify；私有行被promote时再次检查Late，绝不因Full已有而跳过。

目标数组无需B在H₁现场逐一枚举：其内容是“该H₁输入及保存RO版本的确定函数”，可以作为分析中的可预测集合，并在需要时根据保留日志恢复。早期哈希链缺失时仍由正式02的LateHash/Coll覆盖；未见子前像时不虚构未来叶目标。

**覆盖旧正式01。**用Source行替代其候选表。在 `¬Pair_src∧¬Late_src` 下，最终打开叶的真实seed已在对应H₁的来源快照中且唯一。若首次匹配曝光在H₁后，属于Late_src；若快照唯一key不同，最终曝光形成Pair_src。即使该行物理上早被Ext读取，同样按来源时序处理。因此正式01的每列式、free/fixed分类与Rain提取证明照常适用。这里未降低真实B的IC预算，仅收紧了正确的坏事件概率预算。

## 5. 地址缓存引理与eager算法

**引理R4（地址消元）。**对任何固定参数、任何IV及任一叶承诺匹配行 `ρ=(s,x,y)`，其树高为k时，全部随机带输入恰为

\[
x\boxplus(c,0,0,\delta_k),\quad
\delta_k=2^{31}-(k+1)\tau\pmod {2^{32}},\quad0\le c<r. \tag{R4}
\]

证明：在高lane中代入 `x=iv⊞(0,0,0,(k+1)τ+t)`，与δ_k相加得到 `iv_high+2^31+t`；低lane由iv_low变为iv_low+c，中间两lane保持。lane模加的结合/消去对回绕亦成立。树号t与IV只通过x出现；同一个来源行在不同快照、树号、IV中再被采用且树高相同，带地址完全相同。

维护 `TapeCache[(row_id,k)]`。row_id标识同一规范来源行；PrivateIC/Full缓存再消除不同TapeCache项间的真实地址重叠。

```text
GetTape(row_id,k):
  if TapeCache[(row_id,k)] exists: return immutable cached tape
  (s,x,y) := source row row_id
  tape := prefix_L(concat over c=0..r-1:
                    PrivateIC(forward,s,x ⊞ (c,0,0,delta[k])).y)
  store TapeCache[(row_id,k)] = tape
  return tape
```

Eager版本在首次H₁回应前按正式01反查两层RO、读取Source桶并冻结唯一key/unknown，然后对需要的 `(row_id,k)` 调用GetTape。任何单一来源行至多以d_H种树高使用，故无论a₁多少或IV如何选择，实际新增私有调用T与物理新行均满足

\[
T\le \min(rNa_1,\ d_Hr q_{anchor}),\qquad
P_{full}\le q_0+T. \tag{R5}
\]

若重复读取Full不再发外部查询，上式的T也上界私有块接口请求数，因为TapeCache每个 `(row_id,k)` 仅填一次。它是上界，部分块已经来自Source或其他缓存时实际新查询更少。所有哈希、XOR、字典检索仍有时间成本。

## 6. 惰性求值：H₁前冻结描述符，H₂前实际读取

H₁预留新挑战之前，只保存

`Desc=(immutable X1 bytes, source_clock, RO_clock, fixed parameter id)`。

RO输入和行的首次时间、完整预留输出保持不可变。`Resolve(Desc)`使用水位之前的RO反查结果和水位之前的Source桶；一旦遇缺失/不唯一，严格按该历史状态返回相应bottom。禁止因后来新增的RO前像、Source key、输出补长或程序行而升级快照。

```text
BeforeFirstOrdinaryH1(X1):
  store Desc[X1] := (X1, source_clock, RO_clock, fixed_parameter)
  return                                // caller now samples/reserves fresh chi1

Materialize(Desc):
  if materialized result exists: return it
  resolve root/inner Hc preimages using records at Desc.RO_clock
  for every leaf target:
    bucket := SourceByPair[target] restricted to time <= Desc.source_clock
    freeze the historical bucket/count (unique-key baseline)
  if hash/bucket/coverage failure: cache exact failure; return
  read GetTape(row_id,k) only for selected historical rows
  compute the same immutable tree sums/unknown masks as formal 01
  cache materialized result; return

BeforeFirstOrdinaryH2(X2):
  find the unique earlier ordinary H1 record through its chi1 prefix
  if absent/ambiguous: store bottom_hash; return
  snapshot := Materialize(Desc[that X1])
  execute formal 01 free/fixed classification and exact (u*,V*,W*) formulas
  verify candidate Rain key; if valid and no saved key, save it privately
  return                                // caller now samples/reserves fresh chi2

After A and final Verify terminate within fixed bounds:
  output the saved valid Rain key if one exists
```

如果未知叶≥2，提前返回的检查可在任何带读取前完成。若有恰一未知叶，则保存已知叶的U/V和洞索引已经足以使用正式01式(2)；无需恢复洞带。所有完整快照和H₂结果保持不可变。

**引理R6（挑战前固定性）。**上述惰性算法中，每个Desc的解析结果和带函数，以及每个完整树的 `a_t=⊕_j m_tj⊕c_t`，在该H₁挑战抽样前已由当时选定的Desc和实验中的同一E完全确定。

证明不诉诸未来开示。定义分析用过滤族 `F_allE`：在来源历史之外，另外给分析器全部最初抽取的置换族E；不把这些置换提供给B或A。Desc的候选key选择只用H₁之前的历史水位，GetTape定义只读固定E在固定地址的值，故该数值及差分对H₁前的F_allE可测。当前首次普通H₁响应尚未定义，由独立RO新鲜采样，条件于F_allE及过去RO仍均匀。因此正式02的固定非零差分AU引理可以在该时刻使用。

这是一种关于同一随机对象的分析性条件化，不是让PPT算法提前获得整个置换表。B的实际工作只有有限Desc、后续至多r块普通IC读取及多项式聚合，全部按R7和§8计费。亦可理解为先在分析中给每个固定地址命名其潜在值，直到被选中的H₂才由B读取。普通IC没有隐藏编程权限；若将IC改为会在以后改变既定单元的过程，该论证的前提不再满足。

H₁之后再选择要Materialize的Desc并不反向改变任何Desc的差分。对所有首次H₁先做并合，仍得

\[
\Pr[\text{不同free树的VU碰撞}]\le a_1\binom{\tau}{2}\epsilon_V.
\]

实际求值数e至多 `min(a₁,a₂)`，是因每个普通首次H₂最多引用一份先前H₁，且每份只求值一次；RO短请求首次触达同样计入a₁/a₂。于是

\[
\boxed{T\le\min(rN\min(a_1,a_2),\ d_Hr q_{anchor}),\qquad
P_{full}\le q_0+T.} \tag{R7}
\]

若采用更保守的eager版本，仅将 `min(a₁,a₂)` 换为a₁。Source的Pair/Late采用F_src；AU采用F_allE；QuickSilver在首次H₂实际计算W*后使用尚未回答的chall2。三个局部界按并合合成，未在条件于其余“全程好事件”后重新声称均匀，更未相乘。

## 7. 六组因子及与旧界的关系

| 参数 | r | N | 原每H₁最多新增rN | 新每来源anchor最多新增d_H r | 总预算系数上界 |
|---|---:|---:|---:|---:|---:|
| rain3_fast | 6 | 1248 | 7488 | 12 | `P_full≤q₀+min(7488e,12q_anchor)` |
| rain3_bal | 6 | 2432 | 14592 | 12 | `q₀+min(14592e,12q_anchor)` |
| rain3_short | 6 | 17408 | 104448 | 12 | `q₀+min(104448e,12q_anchor)` |
| rain4_fast | 7 | 2048 | 14336 | 14 | `q₀+min(14336e,14q_anchor)` |
| rain4_bal | 7 | 1920 | 13440 | 14 | `q₀+min(13440e,14q_anchor)` |
| rain4_short | 7 | 17408 | 121856 | 14 | `q₀+min(121856e,14q_anchor)` |

其中 `e≤min(a₁,a₂)`；同列系数乘的是不同资源计数，不可把数字比直接称为实测加速比。单用q_anchor≤q₀，还可写Rain-3 `P_full≤13q₀`、Rain-4 `P_full≤15q₀`，但保留min通常更好。参照rFAEST EM128f/s具有相同地址结构、r=11，局部缓存因子22；这里只比较代数地址和资源，未将Rain的独立辅助IC前提直接搬到参考OWF游戏。

正式02的B3/B4以R3替换后，旧保守归约的提取部分可写

\[
\epsilon_{extract}^{new}=\epsilon_{chain}+
\min\{1,q_0(q_0-1)/(2(M-q_0))\}+
\min\{1,a_1Nq_0/(M-q_0)\}+
a_1\binom\tau2\epsilon_V+a_2\epsilon_Z+(3a_\Delta+1)/M,
\]

分母越界分项取1，最终总上界截到1。此式仍为旧唯一叶前像提取器的保守结果；碰撞容忍的共享地址新引理若另获覆盖证明，可以替换其事件接口，但并非由缓存自动得到。

## 8. B实际时间、空间和OWF预算

R7消除了大量重复IC读取，并不把B与A当成同等时间。一个可直接实现、确定最坏多项式时间的版本使用平衡树字典，而非假定攻击者对哈希表不会造成退化。

为明确账本，令 `H_call` 是来源所有RO调用数（含重复和补长），`B_IO`为全部输入、输出及内部预留的总位数；`w=max(λ,ceil(log₂(P_full+H_call+2)))`；`C_VH(L)`为一次真实VHash位运算成本，`C_Rain`为一次公开Rain关系核验成本，`c_IC`为一次外部IC调用费用。令T_src是运行A、pk-only模拟器与最终Verify的其余源算法时间，包含签名的最多G个grinding原始调用与实际QS重构计算。可用下式上界总资源：

\[
\begin{aligned}
T_B\le T_{src}+P_{full}c_{IC}
 +O(&B_{IO}\log(P_{full}+H_{call}+2)\\
 &+(q_0+H_{call}+eN+T)w\log(P_{full}+H_{call}+2)\\
 &+eNk_{max}L+a_2[(D+\tau)C_{VH}(L)+\lambda L]\\
 &+(a_s+a_2)C_{Rain}). \tag{R8}
\end{aligned}
\]

这是保守可实施费用表：长RO输入按长度读入/检索；每个求值快照仍扫描N个位置并做至多 `N k_max` 次L位XOR；每次H₂付逐列VH与转置；H_s和H₂最多各核验一次新候选。源算法时间定义中已包括的项目无需在实际测量重复相加，R8作为上界容许重复预算。没有把CPU或内存视为免费，也没有把预留的不可见XOF输出省掉。

空间可取

\[
O\bigl(B_{IO}+P_{full}(\lambda+\log q_0)
 +d_Hq_{anchor}L+e(D+2\tau)L+a_2\lambda L
 +a_1\log(P_{full}+H_{call}+2)\bigr). \tag{R9}
\]

RO编程行（至多Q_sig G等）包含在B_IO/RO表内。TapeCache可只保存Full行引用与截断视图；R9按复制L位的更宽实现计费。每个快照聚合后只需保存U/V、unknown数和洞位置，原始叶数组沿用RO输入引用，避免复制a₁份全向量。

两层Hc输入按完整原始输入ID缓存解析；一个列表只解析一次。完整树的U/V还可按 `(inner_input_id,x_com,k,source_version)`缓存。即使c、μ或outer h_com变化，纯叶和可复用，a_t只需异或新c_t。source_version改变时默认重算；只有经过证明的版本有效性检查才能进一步复用。失败缓存也带水位：它只回答原Desc，后来的新Desc使用自己的水位。

因此额外总IC已降到R7，但R8中的 `eN k_max L` 在最坏情况下仍在。攻击者可复用承诺列表、变化IV或来源匹配版本，使多个树和确实不同；仅凭输入字节总量或哈希列表去重尚未证明能消除这个项。最终OWF优势必须写为 `Adv_Rain^{OWF,IC}(T_B,P_full,...)` 或直接写同一个实际B，绝不以a_IC代替P_full。

## 9. 对共享地址碰撞容忍方案的接口

若另一个提取器在H₁冻结每叶来源前像桶K_tj，并读取桶中所有seed的带，R4仍逐行成立：每个来源行在任意多个桶、IV、树号中最多只有d_H种带。故总新增IC仍≤ `d_H r q_anchor`，不另乘最大桶宽u。其枚举/聚合时间可以有u或u²因子，应在该算法的CPU成本另列；旧 `rNe` 上界则只适用于每叶至多一个被选key的基线。多key版本可换为实际桶出现总数乘r与 `d_H r q_anchor` 的min。

本稿尚未给出canonical bottom-parent的覆盖定理。可研究仅对来源anchor做固定一步pair-completion：若某行作为底层父左输出，右地址是低lane加1，孩子承诺地址是高lane加τ；作为右输出则先低lane减1。每来源行两种方向，可做有限相邻查询与孩子承诺查询。但这些产生的私有行若立即作为新parent anchor递归，R5的无自举前提再次失效；若把其私有leaf seed纳入K_tj，也须另给新的Late/覆盖事件，而非直接沿用Source-only R3。

因此当前可直接组合的接口是：K_tj由Source历史确定；若canonical pair涉及受控私有完成行，可作为独立被冻结对象，必须由共享地址证明另行说明所有合法开示的覆盖。LateParent半边已知的情形有一阶命中反例，资源缓存本身没有把该概率变成M^-2。
