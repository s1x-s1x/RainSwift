## 2. canonical 与可见池的前置固定性

H₁ canonical 只从其 Source 水位前已有至少一父格的父 key 中选取，补齐该父节点两格及 child com，再按固定的父 key、Source root id 次序取匹配有序承诺对的首项。该选择只依：

1. H₁ 的不可变 Source 前缀；
2. 当前森林的父节点两列和叶承诺列；
3. H₁ 当时已经解析的 IV 与承诺向量。

tape 内容没有参加 canonical 排序。没有匹配父节点时使用常量零基线，也没有添加一个虚构 seed。H₂ 可以增长有限叶池，H₁ canonical 保持原定义。

由此，揭示当前森林全部非 tape 列后，H₁ canonical seed 和 H₂ 的 K_vis 都是可测对象。若 p 不属于树 t 的 K_vis：

- 所有实际点 (p,T_t,c) 均未被 Source 触达；
- p 不是树 t 任意 canonical seed；
- p 作为别树的 seed、父 key 或先前响应数值出现，均不改变前两条。

这三条恰好提供 §8 最后保留一条完整随机带的条件。若 canonical 改为依 tape 或 H₁ 之后的新根排序，当前证明须重新审查。

K_vis 只追溯 C/T/P 的 Source 根。私有行后来被 Source 触达时，按实际新的 source_time 入根；旧快照不回填。完整化生成的行自行递归入根会改变算法与资源条件，受审版本没有采用这种规则。

## 3. 全桶语义族与 AU 费用

固定完整 E 及 H₁ 响应前的普通 RO 历史后，全桶、canonical、基线和全部语义误差/共同 u 候选均固定。新的未编程普通 H₁ 回答仍独立均匀。即使 H₂ 的可计算池随 χ₁ 后的 Source 扩大，它找到的也只是这个预先存在的全集的元素。

该论证保留两项必要修补：

- 对同 com 的底层对显式加入 D=A_t⊕M_even⊕M_odd。即使全桶为空也加入，故算法计算出的 D 始终属于语义全集。空桶补一个元素，仍受 u² 上界覆盖。
- BadU 对整个 F⁺ 内所有不同值收费，含同一树内部的候选。实际算法任选一个 KnownU 匹配值时，该值可能来自真正多洞树本身；只计算旧跨树 BadF 留有遗漏。

因此逐 H₁ 的可用统一规模是：

\[
|E_t^{all}|\le N_tu,\qquad
|F_t^+|\le1+(N_t/2)u^2,
\]

\[
\epsilon_{\rm AU}^{new}\le
a_1\epsilon_V\left[
\sum_t\binom{N_tu}{2}
+\binom{\sum_t(1+N_tu^2/2)}{2}
\right],\qquad
\epsilon_V=2^{-176}+R(2R+1)2^{-192}.                 \tag{A1}
\]

式(A1)界定与共同全域桶好事件的交集；其补集由同一份 δ_cap 支付。全域桶、父对、LateParent、LateLeaf 同时引用该事件时，总合成只加一次 δ_cap。

AU 固定完整 E 的过滤族，与下一节只保留 Source 历史的 IC 过滤族是不同的边际论证。它们分别给事件界后可并合，无须互相独立。固定完整 E 之后再声称 IC 某格仍有新鲜随机性，会超出这里通过的证明。

## 4. TwinUnknown 剩余置换界逐项核对

令 M=2^λ，λ=128，1≤u<M。固定六组之一，L=(r−1)λ+b，b=48，Rain-3 的 r=6，Rain-4 的 r=7。q₀ 是来源流程全部普通正/逆 IC 调用的先验上限，包含模拟器公开重构及最终 Verify。

### 4.1 点态删除 PrivateIC 适用于目标事件

TwinUnknown 使用 Source 前缀、H₁ canonical 的固定定义和同一个完整 E。私有读取的值、命中、失败分类、cap-overflow 及提取成功均只进入私有缓存，不控制来源调用、回答、RO 编程、随机币或停止。固定 E 与来源随机币后，逐步删除私有普通读取，来源轨迹与 TwinUnknown 的真假都保持。

这个删除只用于概率边际实验。真实归约 B 的 IC、CPU 和存储账单仍保留全部私有工作。若来源流程另有仅依 Source 的公开停止规则，它可以在两个耦合执行中同步执行；依 Ext 私有成败的提前停止不属于本证明。

### 4.2 当前森林地址分离成立，跨 IV 用实际单元判定

当前森林地址偏移分别为：

\[
x_{C,t}=iv\boxplus(0,0,0,(k_t+1)\tau+t),
\]
\[
x_{0,t}=iv\boxplus(0,0,0,k_t\tau+t),\qquad
x_{1,t}=x_{0,t}\boxplus(1,0,0,0),
\]
\[
T_{t,c}=iv\boxplus(c,0,0,2^{31}+t),\quad0\le c<r.
\]

固定 IV 的四 lane 模加是双射；原六组的结构 tweak 小于 2³¹。所有当前父/承诺列与当前 tape 地址分离，不同树的 tape 地址也分离。模加发生回绕不破坏这一判断，因为比较的是同一个平移前的偏移。

这不是跨 IV 的全局地址分离。若历史其他解释已经触达当前实际 (p,T_t,c)，K_vis 第一项直接把 p 纳入池。因而以 p∉K_vis 为条件时没有漏掉这种历史触达。

### 4.3 未知 seed 的选择发生在其 tape 之前

在固定某个首次普通 H₂ 的来源前缀与查询输入之后，分析器揭示当前森林全部 key 的 3τ 个父/承诺列。该揭示可为指数大小，完全属于分析器，不是 B 的运算。

此时全桶、当前列帽、K_vis、canonical seed、有资格的四元组名单都固定。对某一有资格四元组，按“a 在池外则选 a，否则选 b′”选 p。这个规则尚未读取未知 tape。条件 a≠b′ 保证本树另一候选不等于 p。

随后只揭 canonical、K_vis、本树另一候选及右侧候选所需的 tape。树 t 中这些 key 均不是 p；别树即使用 key p，其 tape 也落在其他 r 个地址。因此所选 p 的树 t 全部 r 个 tape 点仍未曝光。

### 4.4 剩余分母与截断位数准确

对于同一置换 E_p，最后一步之前已曝光的不同输入点数 d 满足：

\[
d\le d_0:=q_0+3\tau+r(\tau-1).                           \tag{A2}
\]

q₀ 计全部正/逆来源行；免费非 tape 列每 key 至多 3τ；其余 τ−1 树对同一个 key 最多 r(τ−1) 个 tape 地址。重复引用、重复 key、相同 seed 与输出数值别名只减少不同输入点数。

给定此前揭示，等式 U_t,i(a,b′)=U_s,j(c,d′) 对最后 m_t(p) 指定了完整 L 位目标。它约束前 r−1 个完整 λ 位输出以及最后块的前 b 位。最后块至多有 M/2^b=2^80 个完整补全；用掉的输出、目标重复或其他同 key 排列冲突只会减少补全数。

故在 d₀+r−1<M 时：

\[
\rho_{\rm tape}:=\min\left\{1,
 \frac{M/2^b}{\prod_{j=0}^{r-1}(M-d_0-j)}\right\}          \tag{A3}
\]

是单四元组的上界。若 d₀+r−1≥M，直接使用 1。此处需要逐因子的安全范围，单独检查乘积为正不足以替代它。

该事件约束的是 L 位向量，非 rλ 位向量，也非 λ+b 位 VHash 值。受审版本已把80个未用填充位放进分子，未把两个独立性未证的概率相乘。

### 4.5 自适应并合与共同帽事件

当前 com 列帽在前述非 tape 揭示之后可测。对每个给定条件，候选有标签四元组数至多：

\[
C_{\rm pair}(u)=u^4\sum_{t<s}(N_t/2)(N_s/2).              \tag{A4}
\]

每个四元组可独立构造自己的“最后揭 p”顺序，再按概率并合；不同四元组之间的依赖无须排除。global-good 可能涉及其他 tape 单元，证明只用其包含于当前列帽的关系，不将其加入未知 tape 的条件信息。

各 H₂ 切口也使用各自的边际 genie；上一次免费揭示的整列没有作为下一次 Source 的额外信息。至多 a₂ 个切口得到：

\[
\Pr[\operatorname{TwinUnknown}\cap G_{\rm cap}]
\le a_2u^4\sum_{t<s}(N_t/2)(N_s/2)\rho_{\rm tape}.         \tag{A5}
\]

A 自适应选 IV、com、H₂ 时刻和最终开示的能力已包含在来源历史条件化与候选并合中。候选未按最终成功开示单独后选。

## 5. unknown 分支的包含关系

无 cap-overflow 且 KnownU 搜索完整地没有命中时，所有 H(A_t)≠ũ。因此 B_t=ũ⊕H(A_t) 非零，单树高列方程使所有通过洞处于同一底层对；非 BadE 又使每洞至多一个 q。每树至多两个洞。

若至多一棵树有两个洞，整个森林至多两种兼容洞组合；固定 grinding 零位后仍至多两个原始 λ 位 Δ。这个语义集合在 H₂ 回答前已由 E、χ₁、X₂ 固定，B 无须把它实际枚举出来。

若至少两棵双洞树存在，非 BadU 使两树 U 相等。对其中任意一棵：

- 两 seed 相同会使 U=D，KnownU 里已有这一匹配，和 unknown 矛盾；
- 两 seed 都在 K_vis 会使 MITM 找到一个匹配，也与 unknown 矛盾。

因此各有两个不同 seed，且至少一个在对应 K_vis 之外。取较小树号作式(A5)的左侧，即落入 TwinUnknown。右侧事件允许更多情形，故其四元组并合确实是剩余分支的超集。

这里不要求“任何无效 H₂ 的提取失败概率很小”。结论只用于后续有效伪造所走的分支和相应挑战目标集合。

## 6. W-only 提取与真实 Rain 最高次系数

KnownU 的实际匹配值 f 属于 F⁺。非 BadU 使 f 等于每一真正多洞树的唯一共同 u。每棵单洞树则可以唯一的通过 (β,e) 定义 v*=q⊕βf；多洞树用固定首点定义后，仿射引理保证同一 v* 覆盖全部通过点。

只要所有 S_t 非空，就存在在 χ₂ 前固定的语义 V*，同时覆盖全部后续合格开示：

\[
Q=V^*\oplus f\Delta^\top,\qquad W=d\oplus f[0:\ell].      \tag{A6}
\]

B 已经实际计算 f 和 W。V* 只服务于证明，算法没有调用指数搜索来输出 W。若有空 S_t，该记录没有兼容开示，无须为它构造见证。

源码只读核对支持该接口：

- owf_proof.inc:731 的 rain_combine 是固定 GF(2) 线性标签组合；
- :760–772 将 witness 首128位及后续轮输出组成 x_r、y_r；
- quicksilver.hpp:545–549 真实调用 add_constraint(x*y+1)；
- :568–599 的 degree-2 mask 与 proof 项至多一次。

因此形式变量 X 下每个约束为：

\[
f_i(X)=a_{i,0}+a_{i,1}X+e_i(W)X^2,\qquad
e_i(W)=x_i(W)y_i(W)+1.                                  \tag{A7}
\]

低次系数允许依赖语义 V*；最高系数仅依赖已算出的 W 和公开关系。若全部 e_i(W)=0，各 x_i 非零且 y_i 为其逆元，沿冻结线性层和末轮 ct⊕K 得到真实 Rain 原像。所以一次真实 Rain 核验失败蕴含 e(W)≠0。

普通新 χ₂ 对已固定非零 e 的 ZHash 消失界适用。排除该消失事件后，任一固定普通 HΔ 输入的 QS 等式至多两个 Δ 根。先前 G_pair、BadE、BadU 等事件可分别收费；这里没有先条件化于整个未来好事件而保留挑战均匀性。

## 7. HΔ 接口及 a₂ 的计数范围

受审版本 §9 对每个普通新 HΔ 响应前，按对应 H₂ 的首次缓存分支定义目标集合：known 用二次根；unknown 的兼容集合至多二时用该集合；尚未覆盖的异常分支用空集合，另由各坏事件覆盖最终有效伪造。目标集合在所有历史上都最多二，因而不需要将 known 与 unknown 的两个上界机械相加。

该接口还保留以下原规则：

- 第一次任意长度（含零长度）触达即预留完整协议输出，XOF 补长不另采样；
- H₂ 的重复输入复用第一次分支与 Source 水位；
- 哈希链逆序/碰撞由自己的坏事件收费；
- 签名编程行的新消息隔离单独成立；
- 最终 Verify 首次才出现的 HΔ 输入，其 Δ 已由提交签名固定，沿原末次一点评价；
- HΔ 已有记录但所需 H₂/H₁ 之后才补出的路径由原链事件处理。

据原正式02的分解，TwinUnknown 与 ZHash 对攻击者普通首次 H₂ 用 a₂ 计费是兼容的；最后 Verify 不自动增加一轮新的可利用 H₂ 提取时机。若总归约改动上述调度，须同步核对是否要修改次数上界。

本审查通过的是 §9 所需前置固定性与每分支至多二点性质。完整 challenge 项、签名模拟及链条总系数仍由总合成采用其已审版本统一列示。

## 8. MITM 的完备性与确定最坏时间

对一个底层对，设左、右目标承诺桶分别为 A、B，均已按 seed 去重且大小≤u。目标方程等价于：

\[
H(m_t(a))\oplus H(m_t(b'))=
\tilde u\oplus H(A_t\oplus M_{even}\oplus M_{odd}).         \tag{A8}
\]

将左侧的 H(m_t(a)) 存入平衡搜索树，每个 hash 值保存固定序首个 seed；按固定序扫描右桶并查 XOR 补值。若左侧多个 seed 的 hash 相同，保留任一规定代表都保持“存在匹配”的完备性，实际构造的 f 也仍在 KnownU 内。

一个底层对最多需要 2u 次 VHash、O(u log(u+1)) 次确定字典操作。每个键是 λ+b 位；相同 χ₁ 下已经缓存的 canonical hash 可作三项 XOR，避免重复哈希完整偏移串。全森林处理至多 N/2 个底层对，其中 N=Σ_tN_t，不是最大单树叶数。

每 H₂ 的搜索上界：

\[
O\!\left(
 (Nu+\tau)C_{\rm VH}(L)
 +Nu(\lambda+b)\log(u+1)
 +L+C_{\rm Rain}
\right).                                                \tag{A9}
\]

来源索引查询、canonical 的历史查找和基线聚合另计于下一节。使用普通散列表只能直接得到期望复杂度；受审版本明确采用平衡树，因此式(A9)可作为确定最坏界。

发现同一个目标 com 桶有 u+1 个不同 seed 即私下 cap-overflow，跳过本次提取；来源流程照常回答 χ₂。重复根指向相同 seed 不触发溢出。这个事件蕴含真实全域桶帽失败，所以可以由同一个 δ_cap 覆盖。检测前扫描、索引和已经执行的普通 IC 读取仍照实际计费。

## 9. 一个可执行实现的完整资源上界

本节给出保守、确定、可实现的全局资源界，供主账本替换旧 Source-only 缓存系数。它不把 B 的运行成本等同于 A 的运行成本。

### 9.1 有限模板与全部 IC

每个 Source 根只执行有限 C/T/P 模板一次；私有行不递归成根。令：

\[
D_{\rm leaf}=d_H(r+5),\quad
K=D_{\rm leaf}q_{\rm anchor},\quad
c_{\rm role}=d_Hr^2+5d_Hr+6.                              \tag{A10}
\]

K 上界包含高度标记的叶描述符数，父描述符数≤2q_anchor。原六组 d_H=2，故：

| 参数 | r | D_leaf | c_role |
|---|---:|---:|---:|
| Rain-3 | 6 | 22 | 138 |
| Rain-4 | 7 | 24 | 174 |

\[
P_{\rm full}\le\bar P:=q_0+c_{\rm role}q_{\rm anchor}.      \tag{A11}
\]

如果最后 Verify 后不再触发提取，可按既定调度取：

\[
q_0=a_{IC}+(Q_{\rm sig}+1)A_V,\qquad
q_{\rm anchor}=a_{IC}+Q_{\rm sig}A_V.
\]

选择 q_anchor=q₀ 也是保守有效的版本。a_IC 同時計正/逆来源调用；A_V 使用原六组真实公开重构预算。模板生成的 tape、com 和父格全部计入式(A11)。

概率式(A3)以及下一节严格限定 Source 支持的 Canon 推论采用删除私有后的 q₀。03稿更一般的 Full 支持定理继续使用其自己的 Full 预算；真实 OWF 归约资源始终采用式(A11)。这是不同目标事件的分别应用。旧12/14系数没有覆盖当前 C/T/P，主资源账本应使用138/174或更精确的已证实际预算。

### 9.2 历史索引与流式查找的实现

以下数据结构足以实现受审算法：

1. Full 的双向普通映射表；Source 首次曝光序号只随真正来源触达增长。
2. 每个根的有限角色描述符；同一 (seed,x_C,k) 的叶项去重，保留最早可见的 Source 根时间。
3. 父描述符按 (x_C,com_even,com_odd) 索引，用持久化平衡树保存各 Source 水位的固定最小父 key/根次序。H₁ 保存版本根，不因后续新增父 key 更新历史 canonical。
4. 叶桶按 (x_C,k,com) 维护不同 seed 数量及 seed 次序。H₂ 先查目标桶计数，溢出则私下退出；未溢出的桶按序枚举至多 u 个 seed。
5. H₁ 只保留快照引用和历史水位；首次被 H₂ 使用时才求值 canonical 和聚合基线。实际求值快照数 e≤min(a₁,a₂)。
6. MITM 按底层对流式处理。完整 tape 存于有限描述符/Full 缓存；VH 临时字典每个 pair 结束可释放，重复 hash 允许重算，其次数已由 Nu 覆盖。无需保存所有 H₁×全部 seed 的交叉 hash 缓存。
7. 每个 H₂ 只存第一次分类和至多一份匹配 f、W；成功仅进入私有缓存。

第6项给出明确的空间选择。如果实现选择跨 pair、跨 χ₁ 长期保留全部 VH 结果，应另加其真实存储；当前上界采用流式版本，不承诺免费永久缓存。

### 9.3 位复杂度账本

令 h=⌈log₂(2+\bar P+K+q₀+Q_RO+a₁+a₂+eN)⌉，用于索引高度和引用长度。Q_RO 是全部来源/模拟/验证的首次完整 RO 输入总数，B_RO 是处理过的输入、请求/预留输出及补长数据总位数。设 T_src、S_src 记攻击者、模拟器、Verify 的原有计算/状态；T_RO、S_RO 另记普通 RO/XOF 表、反查和不可变历史索引的真实资源。

用平衡树加原始字符串存储，可保守取：

\[
T_{\rm RO},S_{\rm RO}
=O((B_{\rm RO}+Q_{\rm RO}(\lambda+h))h).                  \tag{A12}
\]

该项包含格式不合规输入、重复输入的读取、零长度的预留及后续长尾；不是只数协议长度的合格调用。

令：

\[
F=q_0+(c_{\rm role}+D_{\rm leaf}+2)q_{\rm anchor}
  +(e+a_2)N+a_1+a_2.
\]

一份足够宽的总时间上界是：

\[
\begin{aligned}
T_B\le T_{\rm src}+T_{\rm RO}+O\bigl(&
\bar P+F(\lambda+h)h+eNk_{\max}L\\
&+a_2[(Nu+\tau)C_{\rm VH}(L)
   +Nu(\lambda+b+h)\log(u+1)+L]\\
&+(a_s+a_2)C_{\rm Rain}\bigr).                           \tag{A13}
\end{aligned}
\]

其中：

- \bar P 保留实际外部普通 IC 调用；Full 缓存和描述符操作也在 F 内；
- eNk_maxL 保留 H₁ 基线、各列 XOR 聚合，惰性只减少求值份数，没有删除这一工作；
- a₂N 索引请求及至多 a₂Nu 个候选读取保留在索引/MITM项；
- a_s+a₂ 保留 H_s 首次原像检查和 H₂ 候选真实 Rain 核验；
- 模拟器 grinding 截断、公开重构和最终 Verify 的实际成本仍属于 T_src 与 RO/IC账单。

一份相容的峰值空间上界是：

\[
\begin{aligned}
S_B\le S_{\rm src}+S_{\rm RO}+O\bigl(&
\bar P(\lambda+h)+K(L+\lambda+h)\\
&+(K+2q_{\rm anchor}+q_0)(\lambda+h)h\\
&+eN(L+\lambda+h)+a_1h+a_2(L+h)\\
&+u(2\lambda+b+h)+L\bigr).                              \tag{A14}
\end{aligned}
\]

第一行为 Full 和有限 tape/角色缓存；第二行为允许路径复制的历史索引保守费用；第三行为实际求值的基线与 H₁/H₂ 记录；最后一行为单个 pair 的字典、seed/引用和临时完整向量。

式(A13)/(A14)是可实现的保守界，不是性能实测。u 的全域数学值即使很大，实际循环也只枚举有限来源池；每个桶实际读取数量≤min(u,K)。因此算法的无条件 PPT 性不依赖对指数全桶作任何操作。采用原01的显式参数族 N=poly(λ)、r=O(1)及多项式来源预算时，直接用 min(u,K) 界定循环就得到多项式最坏时间；有限128实例的预算评估仍按选定 u 和实际参数计算。

### 9.4 对总界02资源简式的核对

本轮同时读取[02_碰撞容忍见证提取与完整总界.md](../02_%E7%A2%B0%E6%92%9E%E5%AE%B9%E5%BF%8D%E8%A7%81%E8%AF%81%E6%8F%90%E5%8F%96%E4%B8%8E%E5%AE%8C%E6%95%B4%E6%80%BB%E7%95%8C.md)的资源节，读到的 SHA256 为 2C563ADECC5C6D25E31A807C4A73899FAA5838CEEC306DD92634EF3194CABB80。该版本的时间式已经包括索引、eNk_maxL、每 H₂ 的 VH、MITM 和 Rain；c_role q_anchor 也支配 D_leaf q_anchor 及父描述符操作的常数。

其线性空间式可以由以下更省空间的历史实现支持：每个 (x_C,com_even,com_odd) 桶保存当前最小父 key，并且只在最小项变化时追加 (source_time,parent) 历史记录；H₁ 按冻结水位在该桶的有序时间表内二分。每个父描述符至多产生一次更新，全局更新总数≤2q_anchor。对一个后来才首次出现的桶，若首次时间晚于 H₁ 水位，就返回历史空桶。这样保留 canonical 历史无需一般路径复制树的额外 log S 存储。

RO 反查也可保留记录的首次时间与第二个冲突时间，按旧水位判定“唯一、缺失、已有歧义”，避免为每个水位复制完整表。实际长输入/输出和所有预留仍存入 B_IO 账。

另需明确 VH 字典按 pair 释放；可以缓存已物化 tape 和各 H₁ 的 canonical hash，而不长期保存所有 H₂×候选 seed 的 VH 结果。采用该实现时，总界02列出的 O(u(128+b+w)+L) 额外搜索空间成立；保留跨切口大缓存的实现另加其实际容量。

总界02的 a₂(ell+w) 与这里 a₂(L+h) 在原六组上仅差常数，因为 L/ell<2；其余描述符与索引元数据也被已有常数因子覆盖。以上是明确实现下对简式的认可，不依靠遗漏历史信息来节省空间。若采用本节(A13)/(A14)较宽的路径复制版本，无需上述线性历史优化。

## 10. 新增收紧：Source 支持的 Canon 推论

**结论：PASS_LOCAL_CONDITIONAL。** 对受审05的严格 Source-P canonical，主合成所需的底层歧义事件可以只用 q₀ 计概率。原03的 Full 定理保持原范围和原结论；本节构造一个更窄事件后，把同一定理应用于删除私有读取的来源过程。

### 10.1 路径级包含关系不要求 canonical 对 Source 可计算

对一个有匹配 canonical 父节点的底层 context x，记 canonical 父 key 为 p。按受审规则，p 的 x₀ 或 x₁ 至少一个父格在 H₁ 水位前已被 Source 触达。

后续真实合格开示中，任何完全可见的底层兄弟对均由其父节点 q 通过普通公开重构展开。最终 Verify 的这条父格调用属于 Source；即使返回值来自 Full 私有缓存，SourceIC 仍作真实的 Source promote。若该格此前已由 Source 触达，其已有支持同样足够。

在哈希链好事件上，该 context 的两份有序 com 对相同。若 p=q，两个孩子是同一置换在同一父格的确定输出，当前树的两条 tape 也相同。因此真正的有序 tape 歧义蕴含 p≠q，并且 p、q 都具有 Source 父格支持。

令 PairSrc 是“全程存在同 context 的两名不同 Source-supported 父 key，其潜在有序双承诺相同”。则所需的、有 canonical 的坏结构事件逐路径包含于 PairSrc。

canonical 是利用私有 com 计算后挑出的哪个父 key，并不影响这个包含：PairSrc 已经对所有 Source-supported 父 key 作存在量化。此处没有要求 canonical 的实际选择结果仅由已返回 Source 值算出。

没有 canonical 的底层对另由 LateParent 及缺失对规则覆盖；它不由两名父节点碰撞界包办。

### 10.2 删除私有读取后应用注册支持定理

PairSrc 只依赖 Source 的实际注册支持轨迹和同一个 E 的函数值。Source 无反馈耦合使删除所有 PrivateIC 后，PairSrc 的真假保持。

在这个约简普通 IC 算法中，它自己的 Full 表恰好是原算法的 Source 映射。签名模拟、RO 编程以及公开 H_s 检测只依来源信息和独立随机币，没有来自 Ext 私有状态的额外 E 信息。因此原03的注册支持定理适用，查询上限取 q₀。

具体地，对整数 0≤q₀≤M−3、1≤u<M：

\[
\Pr[\operatorname{PairSrc}\cap G_{\rm cap}]
\le
\min\left\{1,
\frac{q_0(q_0-1)u^2}
     {(M-q_0-1)(M-q_0-2)}\right\}.                       \tag{A15}
\]

去掉 G_cap 时再加共同的 δ_cap；越界时本分项取1。式(A15)直接来自原03 §4.3 的事件包含及逐注册计费，其来源不是对一般 Full 事件的上界擅自换字母。

当前已知 canonical 与最终实际 q 可能曾被 PrivateIC 更早查询。删除私有读取后的算法中，其 Source 首次支持仍是合法的首次可见调用；原03对约简过程的“新父格”条件因而照常成立。保留原 Full 历史再要求这两个点物理未定义，则是不同条件，本推论没有这么做。

### 10.3 caller、终止和最后 Verify 的范围

受审 v3 的 caller 约定恰好支持此推论：

- H₁/H₂ 提取钩子只在 A 最终输出前执行；最后 Verify 不新增提取钩子，也不为其新 Source 根运行 C/T/P。
- 最后 Verify 的所有普通公开重构调用仍计入 Source，故概率 q₀ 含最终 A_V。
- Full 命中不省略 Source promote。q₀ 可以上界全部来源请求，即使真正首次映射更少。
- 私有提取成功、桶溢出和失败分类不提前终止来源。若公开 H_s HitKey 停止，则该执行已经给出归约成功；在未成功而到达最终 Verify 的分支，前述支持包含完整成立。
- Verify 后若归约继续执行任何新的 Source 工作，必须将其加入 q₀；当前固定调度没有这种额外来源工作。
- caller 终止后可以读取或输出已经缓存的秘密结果；若另做新的私有 IC 查询，它们仍进入真实 Full 资源账，且没有新增 Source 支持可供本概率式漏计。

因此主合成可以使用 epsCanon(q₀) 的式(A15)，同时仍以 Pbar=q₀+c_role·q_anchor（c_role=138或174） 计真实归约 IC 和 CPU/存储。这两条预算承担不同职责。
