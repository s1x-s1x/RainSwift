## 2. 三项工作已经完成的内容

**共享AES输入。** 新证明区分有害的结构歧义与无害的单叶碰撞。只比较有Source父格支持的有序双承诺；借助有限C/T/P补查覆盖H1前只读一边的父节点。对真正迟到父节点，单独计双块命中。H1以前用完整理想密码定义全桶语义候选族，实际算法在H2以前只搜索有限已知池。找到共同u时，只需实际算出Rain见证W；其余V在证明中预先固定。找不到u时，除已明确计费的跨树完整随机带等式外，兼容挑战至多两个。最后部分AES块只用48位，剩余80位已进入概率分子。

[完整ST总稿](02_%E7%A2%B0%E6%92%9E%E5%AE%B9%E5%BF%8D%E8%A7%81%E8%AF%81%E6%8F%90%E5%8F%96%E4%B8%8E%E5%AE%8C%E6%95%B4%E6%80%BB%E7%95%8C.md)给出完整归约：

~~~text
Adv_030^EUF-CMA(A) ≤ Adv_Rain(B) + ε_ST，最后截到1。

ε_ST = εSim + εChain + δu
     + q0(q0−1)u²/[(M−q0−1)(M−q0−2)]
     + a1 N q0 u²/[2(M−q0−1)(M−q0−2)]
     + a1 εV C_U(u)
     + a2 C_X(u) ρ_tape
     + a2 εZ + (2aΔ+1)/M。

M=2^128；C_U包括同树和跨树不同u的碰撞；
ρ_tape约为2^−L，使用完整的剩余置换分母；
δu为共用全域桶帽失败，只加一次。
~~~

各项定义、分母失效时取1、原始grinding、XOF首次预留及零长度查询、编程行隔离，均在总稿和固定版本审查中保留。旧保守定理C也[单独留存](01_%E5%B7%B2%E9%97%AD%E5%90%88%E7%9A%84%E4%BF%9D%E5%AE%88%E6%80%BB%E7%95%8C.md)，两条归约的OWF优势和成本各自配套。

**实际提取资源。** 为每个来源根执行一次有限角色补查，Rain-3/4分别最多增加138/174次IC调用；Source概率可用q0，真实B成本仍用Pbar=q0+c_role·q_anchor。H2的候选匹配使用线性哈希字典，搜索费用O(Nu log(u+1))，没有实际枚举指数全桶。CPU仍包含基线聚合、VHash、Rain检查、字典和全部输入输出；内存加上A、模拟器、Verify原有状态S_src。提取钩子只在A最终输出前执行，最终Verify公开读取仍全部计费。

审查发现并修正的具体问题有：同树不同u必须加入AU损失、空桶但同承诺时的对角候选、最终Verify期间提取钩子的调用者歧义、总内存中显式计入S_src。半边已知父节点最后一步仅有一阶命中概率、三洞非仿射等反例继续保留。没有用“迟到匹配概率×VHash概率”的未经证明乘法。

## 4. 为什么Q4具体等强仍为OPEN

[资源与128口径说明](%E6%8F%90%E5%8F%96%E8%B5%84%E6%BA%90/06_%E8%B5%84%E6%BA%90%E4%BB%98%E8%B4%B9%E4%B8%8E128%E5%8F%A3%E5%BE%84.md)把剩余接口写成可检查的充分条件：

~~~text
H_Rain(T_B(v,u), S_B(v,u), Pbar(v)) + ε_ST(v,u) ≤ p128(v)。
~~~

H_Rain是明确采用的计算困难性假设，评价点必须是归约B的真实资源；p128是rFAEST所称128水平在共同工作量、预算和成功率口径下的标尺。用户允许计算假设，不需要另证Rain无条件安全下界，也不需要为了接受rFAEST的公开128标尺而重新证明整套EM。

当前完成了Γ=(T_B,S_B,Pbar)的可实现资源账和ε_ST的精确代入，尚未形成同单位下可数值验收的H_Rain(Γ)与p128映射。时间/空间表达式还含数据结构的O常数。仅贴“Rain128”标签、把OWF优势填零、或在放大后的B资源处仍套A原预算，都不会完成这个接口。所采用的假设数值还须与同资源下现成穷举算法可达到的成功率相容。

这不是要求任意预算下优势恒≤2^−128。128位工作因子、一次猜测概率和多次查询成功概率需要按既定含义换算。普通计算假设可以使用，但量词、模型、成本与适用范围应一并写明。

本轮已经排除“迟到叶概率桥尚无证明”这一旧接续障碍；后续不应再次从它开始。最有判别力的下一步是固定上述统一资源/优势口径，在六组上检查余量。如果当前界留下的余量与真实成本不相容，先判断是归约损失还是可利用攻击；只有证据确认原构造降强，再按用户决定讨论修改。

## 7. 固定五问

1. **最强支持是什么？** 真实共享地址下的完整条件ST及双路线内部合成审查；新桥、真实见证算法和所有资源有同一条可核对链。
2. **最强反对/限制是什么？** 归约的Full与CPU放大还存在，具体Rain假设映射未落实；改善上界没有直接认证128工作因子。
3. **离指定强对照还差什么？** 在作者声称128的共同工作量/成功率口径下，将H_Rain在实际B资源处代入并完成六组验收；不额外要求NIST/QROM或EM重证明。
4. **剩余空间和组合代价有何依据？** Source概率投影、全桶语义及线性字典已有证明；代价为138/174倍根补查、eNk_maxL聚合、每H2的Nu哈希/字典操作及完整缓存，均已列入。
5. **什么结果改变分类？** 同口径具体验收和完整性能/创新证据满足六判据才考虑主线；若出现真实低成本完整伪造/正确性反例则停止当前构造；仅界松保持有明确问题的探索。
