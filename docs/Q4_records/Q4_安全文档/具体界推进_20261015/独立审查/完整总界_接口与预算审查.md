## 2. 模型与共同预算

一次定理固定原030六组之一、一个Rain公钥、经典前缀一致RO和普通双向128位理想密码。Rain公钥挑战独立于该辅助IC。使用原KeyGen拒零规则及完整秘密空间。分析阈值u、κ、u_x、u_y不改变协议、密钥空间或六组参数。

令M=2^128，R为3或4，b=48，ell=128R，L=ell+256+b，r=ceil(L/128)，D=128−g，N=ΣN_t。故L=(r−1)128+b，r分别为6、7。a_IC计攻击者正逆调用；a_c、a_mu、a_4、a_1、a_2、a_Delta计各域首次完整输入，含格式不合规及首次短/零输出请求。重复调用、读取输入及输出补长另在实际时间/位长中保留。

两稿都使用：

~~~text
A_V = (r+3)(N−tau)−2D+tau
q0 = a_IC+(Q+1)A_V
q_anchor = a_IC+Q A_V

hc = a_c+(Q+1)(tau+1)
hmu = a_mu+Q+1
h4 = a_4+Q+1
h1 = a_1+Q+1
h2 = a_2+Q+1
hDelta = a_Delta+QG+1.
~~~

A_V的末项是每树洞处零key承诺的真实死读取。即使返回值被覆盖，它仍影响IC表，因此保留。Q是签名请求的先验上界；精确缓存复用只减少实际新对象数。G预先固定，是正4倍数且不超过2^32；原始失败行、首成功行、x4同批后续行均计入QG，没有把“得到一次成功grinding”作为一个免费查询。

h域中的最后一次Verify均保留；q_anchor独自排除Verify。其合法性依赖下一节的调用者约定，而非仅凭最终Verify已经结束以后再无工作。

## 3. 已修复的调用者问题及最终覆盖

原句“最终Verify之后不再产生新提取快照”只排除Verify结束以后的工作，没有排除Verify执行期间的新H₁/H₂钩子。若期间也运行提取，a₁、a₂及q_anchor都应扩大；原定预算缺乏明确算法支持。

最终版按如下表运行：

| 来源 | 普通IC计q0 | 可作私有完备化根 | 运行新H₁/H₂提取钩子 |
|---|---|---|---|
| A最终输出前的调用 | 是 | 是 | 仅首次合规普通A输入 |
| 签名模拟的公开重构 | 是 | 是 | 程序行另作链隔离 |
| 最终一次Verify | 是，缓存命中也Source提升 | 否 | 否，仍正常预留/回应 |
| 无反馈Ext私有读取 | 只计Full实际成本 | 不递归成根 | 不改变来源RO流程 |

所有私有成功、失败、cap-overflow只入缓存，不影响Source调用、响应、编程、随机币或停止。H_s输入若通过公开Rain关系检查，允许立即成功停止，因为停止事件对来源可测并直接给出OWF原像；这与私有提取成功延后输出有不同依据。

不为最终Verify建新快照仍覆盖每个最终有效伪造：

1. 最终HDelta是全新点时，A已经固定整份签名及其中Delta；Verify随后生成的新IC/H₁/H₂不改变这一指定值。因此该新响应只需命中一个固定128位值，收费1/M，无需对其新链先提取。
2. 最终HDelta是旧普通A点时，在链坏事件补集，其前缀对应唯一且更早的普通H₂及H₁。这些调用发生在A输出前，已拥有冻结记录。
3. 若Verify的新H₂后来才给旧HDelta补出同一chi₂，属于a_Delta h2/2^448；后到H₁及摘要链情形属于相应逆序/碰撞项。h1、h2已包含Verify。

### 4.1 CMA没有移用错误的来源预算


正常读取H4旧点，不把IV重用直接列作失败。IC单元耦合先在无Ext的来源过程证明，再安装无反馈Ext；隐藏单元命中预算是q0，Ext的私有查询没有被冒充攻击者猜中。公开H_s停止按R2连接，私有成功未破坏无反馈删除。

~~~text
delta4 = C(h4,kappa+1)/M^kappa
deltax = C(Q,u_x+1)J^(u_x+1)((kappa+1)/M)^u_x
deltay = C(QF,u_y+1)/M^u_y

epsHide = min(1,
 ((u_x+u_y)q0+V)/M
 +[q0 Q E+(kappa+1)C(Q,2)J^2+C(QJ,2)]/M^2

~~~

κ、u_x、u_y为固定正整数；Q=0时模拟误差为0。H₁冲突熵来自同一虚拟耦合中的完整L(tau−1)位修正串，不需先假设真实串均匀。IC与RO同一首次坏事件耦合保留联合边缘；G只出现在真实尾概率与全部grinding账中。

## 5. ST的结构事件、Source Canon及共同桶尾

### 5.1 Source Canon不是把Full定理直接换一个预算

R3/X2的一般注册支持定理针对所有实际Full支持父节点，预算P包括私有查询，该定理保持不变。ST需要的更窄事件来自R5 §10：

- canonical父节点p至少一侧父格在H₁水位前已有Source支持。
- 最终完全可见兄弟对的真实父节点q在Verify公开展开时有Source支持。Full已有缓存只减少外部物理调用，不取消Source提升。
- 同一真实哈希链给出同一上下文及同一有序com对；若p=q，孩子与tape完全确定。因此tape歧义蕴含两名不同Source支持父节点的有序双承诺相同。

故所需事件包含于PairSrc。PairSrc量化所有Source支持父节点，只依Source轨迹与同一个E；不需要canonical选择结果本身对Source可计算。删除无反馈Private后，轨迹及E逐点相同，而约简过程的Full表恰为原Source。把R3应用于这个约简过程才得到：

~~~text
Pr[PairSrc ∩ G_u]
 ≤ min(1,q0(q0−1)u²/[(M−q0−1)(M−q0−2)]).
~~~

其中0≤q0≤M−3，1≤u<M。这正是ST的epsCanon。真实B仍付Pbar=q0+c_role q_anchor，概率预算的缩小没有给归约免除138/174倍的实际IC代价。

若不存在旧canonical，或者最终父节点尚无H₁前Source父格支持，归入LateParent而非强行套双父碰撞。旧半查询父格由P模板补齐，剩余父格按A4的整列分析收费。其目标是整列真实com原像桶，并非一个依私有信息选出的有限K集合。

### 5.2 各结构项确实有与G_u相交的局部界

ST取同一全域事件G_u：所有(x,y)的seed原像桶宽不超过u。U1/R4给出delta_u=min(1,M²/(u+1)!)。受审证明分别直接界定下列交集，故共同尾项只付一次：

| 事件接口 | 在G_u内的费用 | 核对依据 |
|---|---|---|
| 所需canonical有序tape歧义 | epsCanon | R3、X2及R5 §10的Source事件包含 |
| H₁后全新支持父节点匹配 | a₁Nq0u²/[2(M−q0−1)(M−q0−2)] | A4式(18)；当前com列帽的事件包含 |
| BadE与全族BadU | a₁ epsV C_U(u) | A5及R5；固定完整E后的新普通chi₁ |
| TwinUnknown | a₂ C_X(u)rho | A5 §8及R5独立审查的接口 |

这里：

~~~text
C_U(u)=Σ_t C(N_tu,2)+C(Σ_t(1+N_tu²/2),2)
C_X(u)=u^4 Σ_{t<s}(N_t/2)(N_s/2)
d0=q0+3tau+r(tau−1)
rho=(M/2^b)/Π_{j=0}^{r−1}(M−d0−j).
~~~

C_U的第二项包含同一树不同u的碰撞，足以约束B任意选中但已固定的known候选。rho保留最后块80个未使用位；L=(r−1)128+b，分子M/2^b对应完整L位匹配。未将其替成更小的2^−128r量级。

不同局部证明使用不同过滤族是允许的：RO-AU先固定完整E；IC结构界只揭选定的列及正确剩余置换。后者使用G_u包含于当前列帽，不在全局未来好事件条件下重新断言IC均匀。每个切口可以各自建立分析genie并分别界定同一原游戏中的事件；最后仅用并合界，不把这些揭示拼接为一个免费掌握所有列的真实算法。

单篇写出“delta_u+局部项”本身不足以直接证明只付一次尾；这里核对了对应交集形式。所有费用相加，不需要独立性，也没有乘“迟到叶概率×VHash概率”。

### 5.3 完整覆盖与合成式

在模拟游戏中，按集合包含逐步处理：公开H_s或实际私有见证成功给OWF原像；其余有效新消息伪造先经过链隔离。完全可见父对被LateParent或PairSrc覆盖，或者匹配H₁前基线。全桶语义族随后覆盖所有未知新叶。排除BadE/BadU后，known由实际固定W进入QS，unknown经TwinUnknown桥进入至多二点挑战。最后使用共同挑战事件及最终新点1/M。

因此：

~~~text
Adv_030^EUF-CMA(A) ≤ min(1,
 Adv_Rain^(OWF,IC)(B_ST)
 +epsSim+epsChain+delta_u
 +epsCanon+epsParent
 +a_1 epsV C_U(u)+epsTwin
 +a_2 epsZ+(2a_Delta+1)/M).
~~~

这与最终ST一致。q0≤M−3及d0+r−1<M是相应结构分母的适用域；越界的对应概率项取1，分项及总项均可截到1。它没有另外假设单叶承诺全域无碰撞，也没有假设H₁以后永远不会发现新叶。

## 6. 保守定理C与新定理ST属于不同B

C保留原唯一叶提取器，通过来源无反馈删除后使用：

~~~text
epsPair=min(1,q0(q0−1)/(2(M−q0)))
epsLate=min(1,a_1 N q0/(M−q0)).
~~~

适用q0<M，越界各取1。其H₁前固定的完整树差分付a₁C(tau,2)epsV，实际H₂见证付a₂epsZ，挑战使用S3二点并合。于是C中的全部误差项及同一个B_C资源对应，形成另一条完整条件归约。

ST改变了提取算法和语义覆盖，因而能删去C的全局单叶Pair/全迟到叶损失，替成自己的Canon/Parent/AU/Twin项。但ST也多付有限角色及搜索成本。两个OWF项是不同算法B_C和B_ST在不同资源上的优势；可以分别评价两条完整上界，逐项拼接有利费用则没有同一个已定义B支持。

这一区分也排除了将C的每根12/14 IC乘数与ST的小概率界混搭的做法。

## 7. 实际OWF资源与PPT性

### 7.1 私有调用与来源调用承担不同职责

C的资源来自R1/R2/S2：

~~~text
T_private ≤ min(rNe,2r q_anchor)
P_full ≤ q0+T_private.
~~~

ST的有限C/T/P来自A3/A5及R5：

~~~text
c_role=2r²+10r+6
Pbar=q0+c_role q_anchor.
~~~

r=6、7时c_role=138、174。缓存与每根一次求值都基于具体普通IC调用；不含IC编程权，不把私有行递归升级成新角色根。实际最终Verify来源调用仍加在q0。缓存命中与Source首次提升有不同含义，概率账不能因缓存已知而漏掉首次来源曝光。

### 7.2 历史canonical与MITM存在匹配的实现

主稿最终资源式明确采用可实现的数据结构：

- 每个上下文及有序com对保存最小(parent key,root id)；仅当最小项改变时追加带Source时间的历史记录。每个父描述符最多引入一次更新，总数不超过2q_anchor。H₁按冻结水位二分读取旧最小项，后续Source增长不重选旧canonical。
- 叶描述符按(seed,x_C,k)及桶值去重，记录最早Source支持时间。H₂查当前桶，仅枚举至多u个不同seed；发现第u+1个则私下溢出。实际循环还受有限描述符数约束。
- 每份真正被引用H₁仍付eN k_max L的基线聚合；惰性没有删除聚合代价。
- VH字典逐pair创建并释放，完整tape可缓存。无需长期保存全部H₂×候选seed的hash表，流式实现与给定空间项匹配。
- 相同VH值保留固定代表仍保留存在匹配的完备性；B最终只缓存第一次H₂分类与至多一个实际见证。若选择另一种大缓存实现，应另记其真实存储。

完整E、全桶S_t及共同V*只用于证明可测性和事件包含。B从有限Source根实际计算W并核验Rain，不枚举全部密钥域。即使分析阈值u很大，实际枚举不超过有限池大小；用原参数族N=poly(lambda)、r=O(1)及多项式来源预算即可得到最坏多项式算法。PPT性不依赖先假设G_u成立。

### 7.3 时间与空间的最终式完整保留了必要工作

ST取S=Pbar+H_call+2、w=max(128,ceil(log2 S))；各成本单位分开。已核对以下时间项都有算法对应：

~~~text
T_B ≤ T_src+Pbar c_IC
 +O(B_IO log S
   +(q0+c_role q_anchor+H_call+eN+a_2 N)w log S
   +eN k_max L
   +a_2[(Nu+tau)C_VH(L)
         +Nu(128+b+w)log(u+1)+L+C_Rain]
   +a_s C_Rain).
~~~

B_IO计完整输入读取、实际/内部预留输出及补长位数；T_src计攻击者、真实模拟grinding、公开重构与最终Verify的其他工作。实际VHash、Rain、IC并未假定同价。重复作为保守上界可以保留，但不应在将来实测中当作重复省下的收益。

ledger_build发现的最后空间修正也已落实：原有A/Sim/Verify状态须加S_src。最终ST写为：

~~~text
S_B ≤ S_src+O(B_IO
 +Pbar(128+w)
 +2(r+5)q_anchor(L+w)
 +eN(L+w)
 +a_2(ell+w)+a_1 w
 +u(128+b+w)+L).
~~~

固定R=3、4时L与ell仅差固定倍数，故每份H₂缓存完整f/W可由a₂(ell+w)支配。历史最小项追加记录支撑线性空间版本；若使用一般路径复制树，可改用R5中更宽的带对数空间界。这里采用了已写明的线性历史实现，没有从状态账中省去必要旧版本。

C采用其自己R1的完整时间及空间式，未借用ST有限角色成本。两条归约的最终OWF成功优势都必须在各自实际IC、CPU、内存及辅助oracle模型下评价。
