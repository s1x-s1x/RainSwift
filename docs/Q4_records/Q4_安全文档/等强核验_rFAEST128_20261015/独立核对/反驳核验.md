# 原030与rFAEST-128等强：内部独立反驳核验

日期：2026-10-15。审查者：equality_adversarial_review。性质：内部AI审查，非外部同行评审。

**结论：已核对的局部代数与通用挑战攻击支持“处于同一128位设计档”的判断；当前证据尚未闭合“原030的完整具体EUF-CMA安全水平达到rFAEST所声称水平”。本轮没有发现足以证明原030相对该基线实际降强的完整低成本伪造。Q4按用户新验收条件维持OPEN。**

本报告比较原030六个冻结实例与作者固定上游的rFAEST-EM-128f/s。基线选择不是C1R1，也不是另造的NIST类别1门槛。rFAEST作者本身把完整QROM留作未来工作，故不把QROM设成本轮额外门槛；这也不等于双方量子安全已经相等。

本轮只读取现有文献、源码、报告与输出，并作下述代数审核。没有构建、跑分、参数扫描或新的数值实验；仅新建本报告。已排除文件名含“粘贴的”的文件。

## 2. 原语关系确有变化，秘密长度不是等强证明

EM基线的实际关系为

```text
y = AES_p(k) XOR k
```

其中p公开，k秘密；不是把k当作AES密钥的普通密钥搜索问题。证据：

- U/faest_keys.inc:306–318将公钥输入载入fixed_key，将秘密载入em_key，再以零IV/计数/调整值调用固定密钥CTR。
- U/avx2/aes_impl.hpp:133–154先用公开置换计算，再异或秘密输入；在该零输入实例中恰为上式。
- U/faest_keys.inc:104–110及266–273拒绝秘密首两位同为1；参数开关见U/parameters.hpp:46–48。因此允许候选秘密集合大小为(3/4)·2^128。
- OWF验收是找到任意满足公钥关系及秘密域约束的见证。即使p公开，直接计算AES_p^{-1}(y)也没有消除末尾的未知k异或。

原030的关系为`Rain_K(P)=C`且各轮逆元输入非零；归约可输出任意合法K'，不必是实际采样的K（01:21，Rain分析主报告:21–32）。实际拒零联合分布距均匀(P,K)至多R/2^128（Rain分析主报告:59–78）。

因此可以比较候选秘密熵，却不能把“全空间比3/4空间多log2(4/3)位”直接登记成OWF安全增益：任意原像游戏还受像分布、多原像数量、结构攻击及求值成本影响。不存在“同为128位，所以替换OWF自动等强”的推论。

Rain已核文献中针对3轮的2026估计为2^146.07域运算，作者换算2^139.07等价加密、2^134.78字节内存，未胜过穷举；4轮暂无本轮取得文献中的具体成功攻击成本表（Rain分析主报告:84–100）。这些是具体攻击上界与文献覆盖状态，不是所有攻击的下界。审查并未发现该材料构成原030单点Rain的实际破坏。

可接受的条件论证需要明确提出并说明Rain实际关系的128位困难性假设，而不是要求无条件证明具体原语安全。即使接受该假设，协议组合损失仍须另行支付。

## 3. g+Σk=128解决了什么

令D=Σk_t，允许挑战集合为S={0,1}^D×{0}^g。对HΔ回复前固定的一个δ*∈S，每个新的原始128位HΔ响应满足

```text
Pr[H_Δ(x) = δ*] = 2^(-128)
```

如果只计已经通过g零位筛选的响应，条件概率为2^{-D}；每得到一个这样的响应平均先花2^g次原始查询，两者相乘恢复2^128的通用工作尺度。不能只把D=116视为116位，也不能已经计过原始查询之后再奖励一个2^g因子。

源码验证不仅检查g零位，还比较完整128位Δ与HΔ输出：U/faest.inc:219–221、294–307。原030受审B8明确要求aΔ计失败、批次额外和预计算等全部原始查询（02:155–165）。

这项结论只覆盖固定挑战目标。它没有替代：

- 挑战前固定合法VOLE关系的提取论证；
- 无效见证在ZHash后仍非零的论证；
- 有限次多项式残差的根数；
- CMA签名隐藏性与编程误差；
- OWF及归约资源。

所以g+D=128是必要的具体检查之一，并非完整128位强度的充分条件。

### 3.1 可控制根的通用伪造路线

以下是经典ROM中的代数攻击算法与工作量说明，没有运行128位攻击。

先自行生成完整已知的诚实GGM森林、u、V，选择一个不满足公钥关系的见证W*，公布相应d=W*⊕u前缀；VHash部分按真实算法计算。由于所有随机种子已知，攻击者可对任意允许Δ生成合法copath。H1、H2均普通查询，不作预言编程。

对原030，H2之后的验证多项式为（01:173–186）

```text
b'(X) = c₀ + (c₁ + a)X + E X²
```

在E≠0时任选不同δ0、δ1∈S，设置

```text
a = c₁ + E(δ₀ + δ₁)
b = c₀ + E δ₀ δ₁
```

于是b'(X)=b恰在这两点成立。用声明b和proof=a组成真实HΔ输入；若输出落入{δ0,δ1}，输出相应开示，验证器重算的b与所查询b相同，整条普通哈希链匹配。每次新HΔ查询的成功概率为2/2^128，期望原始HΔ次数2^127。

上游v2_em的实际QS次数为3（U/constants.hpp:218，U/parameters.hpp:48），proof含两个自由系数；U/quicksilver.hpp:583–601明确把它们分别乘Δ和Δ²。若三次残差的最高系数E3≠0，类似选择三个不同允许根，通过这两个proof字段和声明b把验证残差设成E3∏(X−δi)。每个新的HΔ输入成功率3/2^128，期望2^128/3。若某次残差最高项退化，应按实际次数处理，不预设每份无效见证都达到3次。

实际签名只储存32位ctr；验证器没有检查更早ctr是否已经满足零位。耗尽一个ctr空间时改变所选根及相应proof，便有新HΔ前缀；这些改动都在H2之后。还需计森林、见证、有限域多项式和前缀重建成本，因此以上数字仅为主循环的原始RO查询成本，非同价AES/门数成本；2次与3次之比也不是0.585位的严格安全下界差。失败E=0的情形另归入ZHash事件；攻击者可以重建该前缀。

这给出两种构造的常规QS根数级通用攻击上界：2次与3次只差常数。密码参数通常仍将这类算法称作128位设计档。这个算法没有显示原030相对EM基线的降强；也不能把上述通用攻击上界反过来用作“没有更快攻击”的下界。

纸面Appendix G只写二次多项式（T:2473–2480），而固定实际v2_em用3次。应明确补这个实现映射，不能直接照搬纸面2Q/2^128作为实际EM的次数界。

## 4. 已从实际源码核实的局部AU比较

以下引理都要求相关差分/残差在相应随机挑战抽样之前固定，且使用普通首次RO响应。不得跳过完整提取/CMA编程隔离，将它们直接用于挑战后才选的值。

### 4.1 VHash

令w为见证位数、d为QS最高次数，h=w+(d−1)128，

```text
n = ceil(h/128)
εV = 2^(-(128+b)) + (n−1)(2n−1) / 2^192
```

源码核验：

- U/constants.hpp:306–312给出h及附加128+b位VHash掩码。
- U/vole_check.hpp:70–77按128位向上补齐，初始化n个128位系数及2n个64位系数；98–120处理数据及末尾零填充。
- 122–125先求两个多项式值；128–131用四个独立128位矩阵元素形成两行。
- 138–149加入掩码并截取128+b位。load_challenge的四矩阵元素、128位键、64位键分占独立响应片段（37–48）。

固定非零data差分在两种分块下都对应非零多项式。两个独立键的同时归零概率至多(n−1)(2n−1)/2^192；至少一个非零时，每个矩阵行独立均匀，两行截取后撞上固定mask的概率2^{−(128+b)}。data=0但mask非零时碰撞概率为0。64→128位嵌入只需保持非零，不需误称域乘法同态。

| 族 | w | d | h | n | b | 多项式小项分子 |
|---|---:|---:|---:|---:|---:|---:|
| 原030 Rain3全部 |384|2|512|4|48|21|
| 原030 Rain4全部 |512|2|640|5|48|36|
| EM128f |960|3|1216|10|40|171|
| EM128s |960|3|1216|10|48|171|

EM见证960由U/constants.hpp:125–137、190–218直接代入10轮、16字节块得到。末64位padding不可遗漏：1216并非128的整数倍。

在相同首次H1次数下，若沿用原030局部的跨free树并合系数C(τ,2)，快/均衡的τ增加仍被b从40到48带来的256倍主项改善覆盖；两短档τ均11，原030的小项更小。这是局部引理的严格比较，不是上游完整协议提取事件总数已经相同的证明。

### 4.2 ZHash与QS根数

令c为约束数量。对H2前固定的非零残差向量，有

```text
εZ = 2^(-128) + (c−1)² / 2^192
```

U/quicksilver.hpp:358–375采样两份组合系数、128位多项式键与64位多项式键，各约束进入同一组哈希（521–538）。U/universal_hash.hpp:98–115的第二种哈希在GF(2^128)中迭代，但键只有64位；它在一个含2^64个互异域元素的集合上求值，非零次数≤c−1的多项式在这个集合内仍至多有c−1个根。第一键独立，二者同时归零概率满足上式小项；否则独立组合系数给2^-128。

| 族 | c | εZ小项分子 | 非零最终残差最大根数 |
|---|---:|---:|---:|
| 原030 Rain3 |3|4|2|
| 原030 Rain4 |4|9|2|
| EM128f/s |241|57600|3|

EM c=3·1·16·10/2+1=241；+1来自缩空间约束，源码为U/constants.hpp:89–111。Rain残差与关系等价性见01:162–188，原030原式见02:142–165。

因此在固定非零残差、同一首次挑战查询预算下，Rain本轮可证的ZHash小项和QS次数均不比所选EM基线更差。这不证明Rain关系本身更难，也不消除提取、迟到、自适应和模拟损失。

## 5. 隐藏叶多目标与共享输入：防止虚假降强结论

实际同树同层共享AES输入。上游和原030沿用同一承诺核心，此事实不能独立归罪于替换Rain。论文则使用位置i入域，故作者F函数具体界与实际实现之间存在映射缺口（01:25–32；协议组件报告:34–47）。

### 5.1 N_t目标不等于N_t个有用秘密目标

在一份有效签名的第t棵树里，除了一个洞叶，其余叶由copath公开展开。恢复任意一个洞叶的**真实**seed足以重建该树u_t，再由c_t得到全局u并恢复d掩盖的见证。然而：

- 同树N_t个承诺中，绝大多数对应的seed本已公开。匹配它们不产生新的见证信息。
- 给定某个(tree,depth)地址，copath只留下该路径上的一个隐藏节点；不同树的tweak、不同签名的IV还要分别计费。
- 找到与洞承诺相同的另一seed不自动等于洞tape相同。所得候选W要通过公开Rain关系验证；“碰到一个128位承诺”不能立即记为密钥恢复。
- 对跨签名地址重合、隐藏seed重复、可见/隐藏seed碰撞等，仍要按真实调用和签名查询预算建立概率界。当前旧C5采取保守并合。

所以2^128/N_t不是已建立的完整密钥恢复成本。也不能仅凭上述观察宣称多签名场景总是严格2^128。旧P0-3报告:119与替换附录:113把“每查询一个隐藏目标”标成实现依赖的估计，边界应保留。

### 5.2 生日碰撞4-XOR有反例，但未穿透全协议

同树C(a)=C(b)时，在不同位置交换(a,b)与(b,a)使tape四异或恒为0；组件生日成本约2^64。这使纸面位置绑定的4-XOR分析不能原封不动用于当前共享地址实现。

但协议组件报告:71–121已进一步核验合法copath情形：两个不同洞的开示仍可解释为同一个仿射VOLE。其代数理由是共享输入所造成的相同兄弟误差可能只产生公共V偏移。这样的相同误差不是一次非零VHash差分碰撞，也不立即破坏后续QS。

报告明确未证明底层pair唯一性的具体强度、挑战后误差集合界或最终QS/FS伪造；所以既不能说2^64已破签名，也不能说该反例已被完整安全定理消除。需要界定真正破坏单一仿射VOLE/提取时序的事件，避免把所有无害叶碰撞一律付费。

### 5.3 纸面4-XOR长度敏感性只是条件算术

T:730–743印出

```text
64 (Q_I + Q_P) Nmax² (2 / 2^128)^(floor(L/128)−2)
```

并附Q_I Nmax+Q_P≤2^127的使用前提。若假定论文位置地址等前提都满足，则Rain3/4的L=688/816使指数分别为3/4；EM的L=1384/1392使指数为8。随机带缩短确实令这个纸面上界变大，不能只列有利的VHash项。

在同一纸面前提下，Q_I+Q_P≤2^127、Nmax≤2^11，因此最保守代入给Rain3≤2^-226、Rain4≤2^-353，仍远低于单个128位挑战项。这个算术解释“缩短随机带”在该理想位置模型中没有单凭这一项掉到128位以下。

**这不是当前实际源码的有效4-XOR证书。** 共享地址交换反例已经表明应另建适用的事件/证明；把上述很小数字写入原030最终账本会重犯模型映射错误。PRG那一项还存在独立反例。

## 6. PRG反例与宽账本的准确作用域

P0-3_Lemma3.6_反例严格核验.md:22–55给出的合法区分器只做一次Get取得公开IV，再猜M把种子密钥，精确优势

```text
(M / 2^128) (1 − 2^(-128))^M
```

M=2^100时约2^-28，大于作者印出的PRG上界（该报告:57–79）。公开IV让查询者可直接选中被测AES输入，原界中的一个2^-128输入猜测因子没有根据。

这是普通组件种子搜索区分器。没有同时给出完整签名伪造，也没有推出原030比实际EM基线更弱；两者相同AES-CTR承诺/树核心都受这条印刷界失效影响。反例足以拒绝“直接代入作者Lemma3.6就已确认128位”的论证。

原030C7中pair/late/hide采用更保守且经过内部审查的界（03:233–254；05:38–50）。它们在示范预算下很宽，两个短档CMA48例甚至饱和（05:103–127），因此当前证据不足以用此定理取得所需具体强度。但全局pair事件允许攻击者独立地在同一AES输入下制造普通跨密钥生日碰撞，事件本身发生不要求有一份有效伪造；将宽界的误差指数解释为签名实际安全位数是错误的。

同样，把作者失效/不同模型下的“紧数字”与我们有效但宽的界直接比较，也不能证明rFAEST真实更强。合理比较须采用匹配的游戏、查询/时间计费及适用的界。

## 7. 最小决定性缺口与验收意见

当前有三种不同的可交付结论：

| 结论层次 | 本轮判断 |
|---|---|
| 同一128位设计档、同类经典RO/IC安全目标 | 支持；需明列Rain原语假设与实际EM关系 |
| 固定差分VHash、固定残差ZHash、原始挑战及QS次数等局部比较 | 上述范围内支持原030不差于EM基线；随机带长度纸面项更弱但仍有巨大条件余量 |
| 完整具体EUF-CMA安全达到rFAEST声称水平 | 尚未闭合，Q4维持OPEN |
| 已有完整低成本伪造证明原030实际降强 | 本轮未取得这种证据；通用约2^127挑战攻击属于双方设计档共有的常数次根现象 |

最小决定性缺口不是强行追加QROM，而是以下两条桥接：

1. **协议桥接。** 对实际共享AES地址、合法copath与所有自适应查询，给出足够紧的有效伪造提取/模拟界，消除或重构目前全局P²/2^128、a1NP/2^128及宽hide项的无关损失，并支付真实提取器新增rNa1调用。不能只把旧4-XOR界改名后塞回去。
2. **原语及尺度桥接。** 把实际单点Rain关系的困难性作为明确可辩护的128位密码分析假设，按相同成功率、攻击成本及签名使用预算与公开AES-EM关系对照；含辅助IC的归约时间也要记账。无需假装拥有具体Rain的无条件普遍攻击下界，但必须说明条件何在。

只要前一条还没有有效具体界，后者仅作“接受Rain128假设”也不足以把现有C7自动压成128位等强证书。反过来，宽界尚未收紧也不足以要求立刻弃用或修改原030。按用户“先核是否相当、不相当再说”，本轮先保留原030、记录OPEN和这些可核查进展是恰当处理。
