# 原030与rFAEST-EM-128的组件和参数独立核对

日期：2026-10-15。分工：ledger_build。对象：原030冻结六参数，对照本地固定上游 rFAEST @ 7a59c5c18b199bae427bd71d3b9fb5ea3f3b6d97 的 v2::faest_em_128_f / v2::faest_em_128_s。本轮按用户最新“与rFAEST声称的具体安全水平相当”目标开展；完整NIST类别1不作本报告的额外验收门槛。

本报告仅新增于独立核对目录。输入源码、既有Q4稿及C1R1均保持原字节。没有构建、跑分、参数扫描或新密码攻击实验。文件名含“粘贴的”的材料排除于检索和引用。

## 1. 直接结论

**源码映射与八组参数算术核对通过；六组整体具体等强仍待综合论证。**

原030的GGM森林、AES叶承诺、AES随机带、VOLE重构、VHash、QuickSilver实现主体及Fiat–Shamir实现主体均继承固定上游。此前指出的“同树同层及同树叶子共享AES明文”、small_tweak未使用，以及论文按位置编码与实现按树/深度编码的差别，属于双方共有的实现事实。它们不是Rain替换新增的劣势。

按快/均衡对照上游f、短对照上游s，原030六组的总叶数N、最大单树叶数N_max和诚实AES调用数均更少；额外VHash位数相同或多8位；约束多项式最高次数从3降到2。这些支持继续保留同档候选。它们未构成整体优势函数的逐项支配定理：树数、挑战分布、随机带长度、OWF及密钥生成分布同时改变，须在同一实验和资源口径中比较。

完整源码哈希、参数值、公式及有限算术记录见[机器可读证据](%E7%BB%84%E4%BB%B6%E4%B8%8E%E5%8F%82%E6%95%B0_%E8%AF%81%E6%8D%AE.json)。

## 3. 森林、grinding与VOLE参数

λ均为128位。本文以g表示源码zero_bits_in_delta_v，避免与见证w重名。B以字节计，b=8B；论文Table 1的B以位计。

来源：[上游parameters.hpp:284](https://github.com/samsungsds-research-papers/rFAEST/blob/7a59c5c18b199bae427bd71d3b9fb5ea3f3b6d97/parameters.hpp#L284)、[原030 parameters.hpp:317](../../../../../src/parameters.hpp#L317)、[上游constants.hpp:241](https://github.com/samsungsds-research-papers/rFAEST/blob/7a59c5c18b199bae427bd71d3b9fb5ea3f3b6d97/constants.hpp#L241)和[原030 constants.hpp:282](../../../../../src/constants.hpp#L296)。

设D=128−g、k=floor(D/τ)、h=D mod τ，则低树有τ−h棵、高k+1树有h棵，N=(τ−h)2^k+h2^(k+1)。下表是源码常量的整数重算，未运行C++编译器。

所有实例均选AES-CTR作为tree/VOLE PRG、aes_ctr作为leaf_hash、ggm_forest作为BAVC。原030 Rain-4快与均衡的τ同为18，是源码及冻结值。

D+g=128说明活跃挑战位与grinding位的布局。每次H₂³原始输出仍为128位，再要求高g位为0；按已通过grinding的挑战计数与按全部RO查询计数是两个口径。例如一个已经固定的非零次数d多项式，对每个新均匀128位挑战最多有d个根；若条件化到通过grinding的子空间，分母相应变成2^D。完整分析应计入取得这种条件分布的查询工作，D+g恒等式本身不是完整抗伪造证明。

论文若用N=2^k指单树大小，应与本表N_max或具体N_t对应；本表N是全森林总数，二者没有统一替换资格。

上游的公开AES密钥可见[faest_keys.inc:38](https://github.com/samsungsds-research-papers/rFAEST/blob/7a59c5c18b199bae427bd71d3b9fb5ea3f3b6d97/faest_keys.inc#L38)，末尾异或秘密见第250行。因而“把AES换成Rain”应准确理解为更换OWF关系，AES-EM的单向性前提与Rain已知明文的密钥寻找前提分别验收。

上游约束和见证公式见[constants.hpp:90](https://github.com/samsungsds-research-papers/rFAEST/blob/7a59c5c18b199bae427bd71d3b9fb5ea3f3b6d97/constants.hpp#L90)：10轮、每轮16字节，norm分支产生3×16×10/2=240个约束；见证为128+8×(16×10×3/4−16)=960位。第108行再为缩空间加一项。真实缩空间约束由[owf_proof.inc:718](https://github.com/samsungsds-research-papers/rFAEST/blob/7a59c5c18b199bae427bd71d3b9fb5ea3f3b6d97/owf_proof.inc#L718)实现为k₀k₁=0。上游接受3/4·2^128个秘密，即约2^127.585；这不是固定削掉一个秘密比特。

Rain常量见[constants.hpp:256](../../../../../src/constants.hpp#L260)。实际见证由[faest_keys.inc:122](../../../../../src/faest_keys.inc#L126)写成(K,y₀,…,y_{R−2})的多项式基编码；最后一轮输出从ct⊕K导出。[rain_constraints:754](../../../../../src/owf_proof.inc#L757)每轮调用add_inverse_constraints；[quicksilver.hpp:545](../../../../../src/quicksilver.hpp#L545)实际加入xy+1=0。

取消缩空间没有减少枚举秘密的名义空间，但该事实不自动继承依赖3/4域大小的lossy-key证明。若沿原Q4的直接Rain-OWF条件归约，需清楚声明实际密钥生成分布与辅助IC模型。Rain的“全密钥空间”表示未开启上述人为两位筛选；真实KeyGen仍拒绝产生零逆元输入的(pt,K)对，和所有256位打包串均接受是不同说法。

约束更少、次数更低，有利于诚实计算及相应固定错误检测系数；Rain原语抵抗结构化攻击的强度须另外判断，不能从约束数量直接推出。

## 6. 论文宣称、实现及“至少不弱”的边界

所核[作者版](https://eprint.iacr.org/2025/1077)物理p9 Table 1列出rFAEST-EM-s/f的4014/4980字节、τ=11/16、g=10/8、b=48/40，与本轮上游源码算术一致；正文以128-bit security level比较。p8 Theorem 4.3保留OWF、PRF、PRG、ZK及VSC组件优势，属于条件具体界。p11 §4.5明确完整QROM留待后续工作。

论文与实现至少有三类需要维持的映射边界：

1. 按树内位置编码的F与源码按树/深度编码的F不同，双方共享这一差异。源码中的N_max可比叶承诺数不等于N_max个攻击有用的未知秘密；从中直接写2^128/N_max密钥恢复成本缺少完整攻击。
2. 论文附录G物理p20附近按二次QuickSilver写根数损失，固定上游v2_em实际norm分支最高次数为3；Rain分支为2。比较时应代入真实最高次数，不把纸面常数2静默套到上游源码。
3. 混合树高、H₃树根展开、H₄派生以及参数相关输入长度，均应进入实现级定理；论文表达和源码相似不足以自动套用全部界。

数值上，六组具有明确的有利方向：B≥对照、N≤对照、N_max≤对照、d_QS≤对照，且误差检测处理的行数及约束数较少。但是“参数至少不弱”不是仅检查这些不等式：

- 路径替换数Σ_t(k_t+2)=D+2τ：上游f为152，s为140；Rain六组依次为165、155、138、158、156、138。部分项增加，即使完整PRG项还乘上随带长度下降的系数，也应合并后比较。
- 论文Lemma 3.6的4-XOR纸面界含floor(ℓ/λ)−2，较短随机带会使该项的纸面上界变松；所以“见证更短使所有安全项更优”并不成立。这里仅说明该公式的参数依赖，未将未完成映射的论文界宣称为当前实现定理。
- 更大的完整秘密空间不直接解决H₃模拟、实际OWF单向性或其他证明中缩空间裕量的问题。
- 诚实算法oracle调用减少并不等价于攻击成本下界；归约额外调用和 adversary 的正/逆向查询仍要计入。

| 验收问题 | 本核对结论 |
|---|---|
| 相同组件来源与调用分支 | PASS |
| 六组λ、τ、g、树分布、B、见证、次数、约束及哈希字节映射 | PASS |
| 因共享输入缺口就判原030比上游更弱 | 缺少这种差异归因的依据 |
| 因共享组件就删除共有风险或直接宣称等强 | 缺少这种推导的依据 |
| 六组作为rFAEST-128同档候选继续评估 | 有源码与参数依据 |
| 六组已证明整体具体优势不高于对应rFAEST实例 | OPEN，待OWF差异及同尺度完整比较 |
| 本核对是否产生低于目标成本的完整签名伪造 | 未产生；本轮没有开展攻击实验 |

建议综合报告采用“共有机制共同披露，新增差异单独验收”的比较方式。若要给出最终等强判定，应明确攻击者模型、成功率和资源预算，比较实际OWF前提及实现级完整协议；历史保守上界的误差指数不替代攻击位数。
