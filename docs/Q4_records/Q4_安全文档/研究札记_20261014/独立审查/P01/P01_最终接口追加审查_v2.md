## 2. XOF前缀与域计数已经对齐

01第15行将SHAKE建模为一张按完整输入串索引的无限随机位串表。首次触达时，H_c/H_μ/H_s预留2λ位，H₄/H_Δ预留λ位，H₁预留L₁=704位，H₂预留L₂=448位。短输出及零长度请求也建立记录；只向A返回所请求部分，余下标准前缀留在内部反查索引中。补长复用原值，额外尾部独立延长。

这样处理同时解决两处问题：一是提取器在任何chall1/chall2前缀泄露之前固定快照；二是摘要反查、碰撞检测和逆时序分析都针对已经存在的完整标准输出。某个短查询尚未向A透露完整输出，不会被归约误当成一个从未定义的挑战。

02第11行明确a_j覆盖相应末字节域的全部首次完整输入，包含格式异常、短前缀与零长度查询。格式异常输入仍可能产生与合法输入相同的标准输出，所以B2的碰撞预算应覆盖它们。提取钩子只处理合规H₁/H₂；使用更大的域计数上界来收取其工作和坏事件是保守的。01第198行原有“仅合规H₁次数”定义经本轮指出后同步修订，现与02一致。

两层H_c仍是同一张表，未被偷换成两个独立预言；其合法输入长度的区分沿用00b的六组核对。额外输入/输出长度、预留及读取工作计入时间，协议查询数并非整个运行成本。

## 3. 签名编程行与普通提取行隔离

03的program_fresh对任何先前触达过的完整输入都产生冲突，包含只请求过短输出或零长度的旧记录。它不覆盖旧答案。所有签名H₁/H₂和H_Δ成功、失败、同批后续行均带来源标记；01的提取钩子只处理A的普通首次合规挑战输入。

对于最终新消息伪造，若其H_Δ行属于签名模拟器，复用的chall2在排除Coll₂后强迫相同H₂输入；其chall1在排除Coll₁后强迫相同H₁输入；其μ在排除Coll_μ后强迫消息相同。这与新消息条件矛盾。同一个推理覆盖失败grinding行与x4额外行，不只覆盖返回签名中的成功行。

因此B6、B7、B8所用的AU挑战和多项式根挑战均位于普通首次响应路径上。分析没有将可编程签名模拟器黑箱地当成一个普通EUF-KO对手，也没有把预先选择的签名Δ误当成新的均匀完整域挑战。

B2中涉及签名χ₁、χ₂输出的碰撞项，在它们被均匀抽样时与过去同域表比较：签名调用原子完成，调用内部不会夹入新的A查询，公共重构只增加其他域的聚合查询。其输入或后续计算可依赖已选挑战，但旧同域目标先于这次抽样固定。这里用的是首次坏事件并合，不是在排除未来所有冲突之后再次宣称挑战均匀。

## 4. Sim之后加入Ext的顺序成立

03第122行及G0—G5先比较没有Ext的真实签名游戏与pk-only Sim；完成该分布比较后，才在G4中加入01的Ext普通IC读取。这个顺序很关键：Ext可以直接检查归约内部表，因此真实隐藏key的不可猜测性不应以“Ext看不见隐藏记录”为前提。

在G4预先固定全部理想置换，Ext只提前读取其中确定位置；这些读取既不改变置换，也不对A增加回答。Sim的公开重构仍使用同一置换，且Sim不因为Ext预读某个IC位置而额外中止。因此加上Ext后的A与Sim公开视图保持同分布。新增私有记录会扩大PairCollision/LateHit等分析事件，B0将这些读取重新计入P，正好处理该影响。

两类预算因此应继续分别使用：

- 实际归约B：P=a_IC+rN a₁+(Q_sig+1)A_V。
- 未运行Ext的隐藏路径耦合：P_H=a_IC+Q_sig(A_S+τ)+A_V，T=1+P_H+Q_sig S₀。

它们各自服务不同游戏。C5中的T未包括真实游戏的Ext；B3/B4中的P包含G5中Ext产生的所有普通IC行。将两个数互换会遗漏调用或错误使用隐藏标签的条件熵，最终文稿已经区分。

## 5. 普通IC计费与B0—B9延续

Sim每个未缓存签名只执行一次公开重构及QS检查。其IC调用是普通正向读取，没有人为设定IC回答。公开Verify的临时零key洞承诺随后虽被覆盖，仍在A_V中的+τ计费。

以r_blk表示每叶带块数，有：

- A_V=(r_blk+3)(N−τ)−2D+τ。
- J₀=2D+(r_blk+2)τ。
- A_S=(r_blk+3)N−τ。
- A_V+J₀=A_S+τ。

所以C4中每签名的额外τ正好覆盖模拟重构的dummy调用；这些调用没有因其输出被丢弃而消失。P_H还计A的正/逆访问及最终Verify。固定零key纳入已知key集合的处理与这个计数一致。

B3/B4以完整IC行(K,x,y)为对象：正向查询固定K,x而随机化剩余y；逆向查询固定K,y而随机化剩余x。Sim与Ext加入后的普通读取仍满足该条件。最终Verify所需的迟到叶承诺也计入P。由01对最终打开叶的唯一旧承诺行覆盖，迟到父节点、输出作为新key及跨IV复用均已落入PairCollision/LateHit；无需扩大为指数输出闭包。

因此v1对VOLE校正关系、free/fixed分类、挑战前差分、ZHash最高次系数以及成功伪造覆盖的意见延续。P达到M时B3/B4取平凡界，T达到M时C5取平凡界，文稿没有继续使用非正分母。

## 6. 单个Rain归约的成功路径与模型

01第21行、03第7行统一定义Adv^{OWF,IC}_{Rain}(B)。挑战来自冻结KeyGen；辅助理想密码置换族独立于挑战，B获普通正/逆访问。本地A-facing RO由B模拟及编程。B没有获得sk、陷门或IC编程权限。这个目标游戏与同成本的无oracle Rain单向性假设分开陈述，严格PPT及查询成本均相对已明示的辅助IC模型定义。

检测器仅检查A的H_s查询；真实签名器内部秘密前缀调用不会平凡触发HitKey。命中任意合法Rain原像即可成功，不要求等于原KeyGen密钥。在未命中HitKey的执行前缀，真实秘密H_s输入尚未被A触达，隐式派生缓存成立。

03第29行和01第212行经本轮指出后明确：只在每个完整H_s输入首次触达、任何前缀返回之前计算一次Rain关系；重复与补长复用已判结果。a_s计首次输入，所以a_s+a₂次公开关系核验的成本现在成立。仅在措辞中写“每次查询都计算”，同时用首次输入计数收费，会遗漏重复查询的成本；最终稿已修正。

同一B可以在HitKey时输出合法原像，也可以在任意已提取W*通过公开关系核验时提前输出。为证明可在后台继续的耦合游戏和实际提前停止B建立对应即可：提前输出本身已经是成功，不会丢失最终成功下界。于是：

Pr[Forge_real] ≤ Pr[HitKey ∨ Forge_sim]+ε_program+ε_tail+ε_hide；

Pr[HitKey ∨ Forge_sim] ≤ Adv^{OWF,IC}_{Rain}(B)+ε_extract。

这里仅收取一次OWF优势。它既没有假定每个伪造都查询H_s，也没有用先知sk的算法建立实际B。
