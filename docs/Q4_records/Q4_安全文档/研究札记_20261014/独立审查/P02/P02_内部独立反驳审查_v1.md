## 4. 反驳发现及实际闭合

### 4.1 提取器加入时刻是实质修复

曾考虑在真实 signer 游戏先加入读取全部内部 IC 行的 Ext，再把其触达隐藏种子的概率当成猜键概率。该顺序有反例：真实 Sign 已生成 `E_s(X_com)` 行，Ext 从私有表读出 s 后再请求 `E_s(X_tape)`，命中概率为 1。

03 §5、§7 的实际修订先只对 A 与签名 oracle 做 Real→Sim 耦合，完成 pk-only 游戏后再加入 Ext。此后普通 IC 读取是非干预操作，提取损失接 02 B9。修订后的隐藏标签分析没有给 Ext 真实 signer 的私有隐藏表。

### 4.2 dummy 零 key 既要覆盖，也要计数

真实重构对每棵树的洞以零种子计算叶承诺，之后用 opening 覆盖。这仍是 IC 调用。03 在时间 0 登记零 key；v2 起修正每次模拟的调用总数为：

`A_V + J0 = A_S + tau`，

`P_H = a_IC + Q_sig (A_S + tau) + A_V`，

`T = 1 + P_H + Q_sig (1+D+tau)`。

其中 `A_S=(r_blk+3)N−tau`，`J0=2D+(r_blk+2)tau`；末尾单独的 A_V 只覆盖最终验签。原 `Q_sig A_S` 少计每次公共重构的 tau 个 dummy。正式 v4 及作者研究稿均已同步。

独立缩小反例取 M=8，归一 `E_0(X_com)=0`。真实承诺满足 `Pr[com=E_0(X_com)]=15/64`，独立抽取承诺时为 `1/8`，区分差 `7/64`。它驳回忽略零 key 的零损失论证；当前包含零 key 的 C5 已覆盖该事件。

### 4.3 符号、检测域和截断实现

正式稿现区分根种子 s_root 与 tape 块数 r_blk，后者对应 01/02 的 r；检测事件命名 HitKey，与 D 位数分开。G1 明确仅对 A 的 H_s 查询检查，避免诚实 signer 的秘密派生令游戏立即停止。 末轮接口复核还确认：每个完整 H_s 输入只做首次检测，重复和 XOF 补长复用该判定，故公开 Rain 检查次数仍为 a_s+a₂；01 的 a₁ 也已统一为完整末字节域的首次输入数。

R3 用 `(max(1,Q_sig)-1).bit_length()` 精确计算 `ceil(log2 max(1,Q_sig))`，再以整数整除向上取到 4 的倍数，最后封顶 `2^32`。这与 C3 相同。保留的 R2 浮点 cutoff 没有被当作该公式的证据。

## 5. 对关键证明的独立反驳检查

**隐藏路径耦合。**固定 Delta，虚拟游戏的隐藏标签不参与公开量的计算，故标签可迟抽；公开兄弟子树仍走普通 IC。检查隐藏标签互撞、标签与普通 key 的先后两向相撞，以及同隐藏 key 的指定不同输入产生重复输出。包括 key0 后，好事件下每个隐藏 key 无普通表行，且指定输入/输出各自互异，能延拓为随机置换。普通逆查询也显式给 key。公开兄弟 seed 被正常查询本身没有标坏。前两类各以 `T²/(M−T)` 保守计费，同 key 无放回切换至多 `T²/(2(M−T))`；C5 的系数 4 有余量。P_H 与实际 B 的 P 分开，后者才包含 Ext 调用。

**联合掩码与预选 Delta。**每棵树的洞 tape 与公开子树异或后得到 u_t，映射到 `(u,c)` 可逆。再按 d→u_W、a→u_QS、ut→u_VH 的顺序逆解，所有掩码总维度恰为 L。QS 的 Z1 只用见证行，因此三角性成立。有效 W 使全部约束残差为零，完整 b 与公开验证相同；这一步保证预选 Delta 后构造 H_Delta 输入仍能与真实 signer 的 b 连接。

**编程新鲜性与 grinding。**H1 使用新 IV、H2 使用新 chi1、H_Delta 使用新 chi2 的前缀界。当前所有 G 个计数器共用同一 chi2，已有 h_Delta 含过去原始行，所以无需重复乘当前 G。真实首成功几何位置、失败输出、成功子空间均匀 Delta 以及 x4 后续输出与模拟分布逐项一致。32 位耗尽及提前 cutoff 均由 `Q_sig(1−2^-g)^G` 覆盖；没有把固定 ctr=0 或单条成功行当作真实 grinding。

**缓存及同一归约。**相同 `(mu,rho)` 对应相同实际 H_s 输入，在只增不改的 oracle 表下整个执行逐字节相同；不同缓存键的碰撞保留。秘密前缀查询一旦给出任意有效密钥就能公开识别并停止，先耦合 `HitKey or Forge`，再由检测成功或提取成功输出同一个 OWF 挑战的原像。若仅讨论 Forge⇒HitKey 会遗漏另一条成功路径；当前版本已避免此跳跃。

**编程行组合。**无 mu/H1/H2 输出碰撞时，新消息伪造若使用 signer 的 H1 行便回到已签消息；若使用 signer 的 H2 或任意成功/失败/x4 H_Delta 行，则沿唯一挑战链亦回到该消息。故最终链的自适应 AU/根数分析只使用普通响应。本审查复核该接口；P0-1 本体仍由其独立审查负责。

## 7. 通过条件的含义与移交

上述实验检验可执行性、有限代数和小参数精确分布。128 位协议的 C1/C2/C5 与 C7 依赖正文的游戏证明，实验次数没有转化为密码安全位数。

本轮文件写入仅在独立审查目录；没有运行 P0-4 数值账本，没有修改冻结源码、参数或作者文件。旧稿保持错误案例地位。未发现需要再次阻断 P0-2 的未闭合事项。根代理可将本裁决和 P0-1 独立审查合并为阶段 04；只有该总关卡通过后，才据 C7 进入阶段 05。

阶段 05 须分别列明归约误差、带辅助 IC 的 Rain OWF 条件及实际预算；宽界饱和和具体攻击成本是不同结论。这里的 PASS 代表已给出并经内部反驳审查的条件证明，不代表已取得外部同行评审或既定具体安全位数。
