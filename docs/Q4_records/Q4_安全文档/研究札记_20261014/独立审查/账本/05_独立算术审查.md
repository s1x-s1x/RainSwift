## 3. 容易错算的口径

1. **计费 N 是总叶数。** 六组 N 依次为 1248、2432、17408、2048、1920、17408，N_max 另保留为单树上界；B4 和 rNa₁ 均用前者。b=48 位、λ=128 位，H₁/H₂ 分别为 704/448 位。
2. **P 与 P_H 用途不同。** P 含 `rNa₁+(Q_sig+1)A_V`；P_H 每签名计 `A_S+τ`，T 再计 `1+Q_sig S₀`。独立核对 `A_V+J₀=A_S+τ`，每次重构的 τ 个零 key dummy 都已入账。
3. **攻击者查询口径完整。** a_IC 为正向与逆向调用之和；a_Δ 包括全部原始 grinding 查询，含失败、预计算和 x4 后续行。签名 oracle 自身原始 grinding 的 `Q_sig G` 加入 h_Δ，不把它只按成功签名计一次。不同 RO/IC 次数相加仅作计数总表，未折算为等成本时间。
4. **Q_sig=0 先行处理。** hide、program、tail 为 0，包括 T≥M 的无签名场景。B3/B4 的 P≥M 和有签名 C5 的 T≥M 则按定理取平凡 1，避免负分母。P/T 尚小于 M 时，概率项仍可能先达到局部 1。
5. **G 全程整数。** C3 用 `ceil(log₂ max(1,Q_sig))`、4 倍数向上取整和 2³² 封顶。账本的尾项是有证明的 `Q_sig·2^{-floor(G/2^g)}` 上界，不是声称精确等于 C2。四组当前预算均未触及 counter 封顶；三个有签名预算的尾上界恰为 2^-128。
6. **舍入展示不作严格判断。** εZ 略大于 2^-128；a₂=2²⁰ 时 ZHash 项略大于 2^-108。展示 `108.0000000000` 与精确 floor=107 同时出现是正常舍入现象。审查用整数分数验证 `2^k ≤ 1/ε < 2^{k+1}`，没有用展示对数判断目标。
7. **存储只列核心载荷预算。** 独立复算快照、仿射矩阵、IC 三元组、RO 协议前缀、grinding 表和缓存字段；完整存储上界仍为 null，等待输入/XOF 延长长度与数据结构表示。它们也不是当前计算脚本的实测内存。
