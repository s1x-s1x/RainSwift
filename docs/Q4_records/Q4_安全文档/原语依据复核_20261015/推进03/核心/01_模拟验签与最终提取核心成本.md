## 2. 统一机器、原子例程与完整计费

与本轮管理稿统一：字长w≥64，所有实际使用的地址、位长、计数及其加1均小于2^w。比较一组m时，先用最大允许m选定同一个w、地址模型和公开arena模板；给定公开m后，在运行前按该m的固定容量分配，沿其全部秘密轨迹保持容量相同。不同m的费用可呈仿射变化；不得随成功轨迹换字长或容量。若q=2^128，需要足以表示q+1的w。

RAM向量按以下七项计数：

~~~text
(LOAD, STORE, ADD/SUB, BIT, CMP, BRANCH, MOVE).
~~~

另列随机位RNG、边界传输IO位数、IC正/逆请求数及RO请求清单。每项乘共同机器模型中明示的非负权重；使用有限具体时间比较时，所有实际使用的动作权重应为正。任何一侧都不把一次GF128乘法当作一条免费指令。本文没有给这些权重伪造CPU周期。边界传输统一包含原语挑战P∥C入站256位；原030归约、独立Rain枚举和参考比较均沿用这个约定。挑战落入本地内存的复制/转换另付RAM费用。

定义一项完全显式的宽松向量：

~~~text
F(n) = 64(n+1) · (1,1,1,1,1,1,1),      n≥0.
Wrap(k) = F(32(k+1)).
~~~

F(n)覆盖一次n位复制、清零、移位、逐位异或、公共位掩码异或、串接取前缀或全长等号检查。采用输入/输出游标，不需要把任意长除法当单位操作。每位至多访问3个输入和1个输出，至多8次读、4次写、20次加减/寻址、24次位操作、16次比较、20次跳转、20次寄存器移动；头尾各项合计至多32，因而64(n+1)逐项支配。定长随机访问可先以游标构造位置，矩阵转置按行列循环维护指针。Wrap(k)为k个外层步骤每步至多32个标量设置、索引及跳转的额外余量；它不是未定成本符号。

### 2.1 GF(2^n)乘法，n=64或128

模多项式分别为x^64+x^4+x^3+x+1及x^128+x^7+x^2+x+1。用n位缓冲区执行：

~~~text
v=A; z=0
for j=0..n−1:
    beta=bit(B,j); z ^= beta·v
    alpha=bit(v,n−1); v = low_n(v<<1)
    v ^= alpha·low_n(modulus)
return z
~~~

每轮3个n位流操作，提取两位和控制至多F(8)，初始化、输入/输出及末字填充预留8F(n)。因此：

~~~text
M_n = (3n+8)F(n) + nF(8).
~~~

它已经包含乘法、模约减、掩码、读写和循环；平方保守地使用同一M_n。工作区至多4 ceil(n/w)+32字；输入和固定模数另存。无秘密指数求逆黑盒。

### 2.2 d×n的GF(2)矩阵作用

按列存储；从零累积d位输出，扫描n个输入位，逐列作掩码异或：

~~~text
L_(d,n) = (n+3)F(d) + F(n) + nF(8).
~~~

其中矩阵每列读取包含在对应F(d)内。矩阵表占ceil(dn/w)字，临时工作区至多ceil(d/w)+ceil(n/w)+32字。下文L64=L_(64,64)，L128=L_(128,128)。所有PSI、SQ15/SQ31和Rain线性层均使用该明确费用。

### 2.3 表加载与PSI逆矩阵

固定一组R所需公开表位数取：

~~~text
T_R = 64 + 2·64² + 2·128² + 2R·128 + 2(R−1)·128²
    = 8256 + 33024R.
~~~

逐项来自BETA、SQ15/SQ31、PSI/POW、塔域/多项式基轮常数及两组线性矩阵。另加载两个模数至多192位。加载费F(T_R+192)，表空间ceil((T_R+192)/w)字；这些公开常量不作为免费秘密建议。

源码未提供PSI逆表时，在固定128×256增广矩阵[PSI|I]上作GF2高斯消元。128个主元，各最多扫描128行、交换3个256位行缓冲、向128行异或；再转置读出逆矩阵。安全的有限上界为：

~~~text
InvPSI = (128²+3·128)F(256) + F(6·128²+4·128).
~~~

增广矩阵32768位、逆表16384位，另2行缓冲和控制。PSI在既有映射材料中已核为可逆；这里计的是执行消元的费用。若使用预存逆表，应同时记其生成/装载及存储费用，不直接删掉。

可统一预付：

~~~text
V_init = F(T_R+192) + InvPSI + 2L128 + F(64w²+4096).
~~~

两次L128得到公开P_p、C_p；最后一项覆盖有限预算头、公开常数地址/容量构造及固定缓冲设置，按移位加法实现有界整数字乘法。实际Verify会重新解码pk时仍照计，下面的保守和允许这一小量重复收费。

## 4. VOLE与VH的本地核心

### 4.1 森林与q重构

保留原vector_com及small_vole的IC调度，使用显式128位数组。取k_max=max_t log2(N_t)。本地非预言费用可用：

~~~text
V_rec =
 [8A_V +32rN +8N+8D+4tau+256r] F(128)
 +(tau−1)F(L)
 +F(512 k_max² (N+D+tau+1)).
~~~

常数来源：

- 每次IC请求的key/四lane输入构造、结果写回、至多常数次临时复制由8F(128)支配；AES轮函数本身属于IC请求坐标，不在此重复假装真实AES计算。
- 8-key分组的xor_reduce最多11次128位XOR及7次复制；convert、累积与列更新后每组每块小于32次128位流操作。实际组数至多N/8，这里宽松使用N组，所以32rN足够。
- 叶seed/承诺位置复制及置换用8N；开示seed/洞承诺整理用8D+4tau；128列的初始化、校正和高g列清零由256r支配；c_t的L位读取另计。
- reorder、树展开、子树寻找、叶置换及Gray分组循环，逐层最深k_max；把每个节点/叶/开示位置至多8k_max次外层访问、每次至多64k_max个标量指令合并为最后的512k_max²项。子树重排的预分配容量与实际循环次数区分，未把大数组初始化视为免费：写入的有效槽位已在上述复制项计，未读的保留槽位无需清零。

这是有意保守的完整上界，不是本机C++指令条数；空间见第9节。

### 4.2 线性VH的明确算法

前128n位拆成n个128位块，也拆成2n个64位块；用Horner分别在GF128/GF64求值。输出两项：

~~~text
z0 = M00·H128 + M01·embed(H64)
z1 = M10·H128 + M11·embed(H64)
VH(x)=prefix_h(z0∥z1) XOR x[128n:128n+h].
~~~

与universal_hash.hpp的二次幂分组求值相等。最后h位掩码仍读入；未把VH当随机oracle。普通Horner省去无关的预计算表，但所有实际乘加照付：

~~~text
V_H =
 (n+3)M_128 +(2n−1)M_64
 +(n+3)F(128) +2nF(64)
 +F(256)+F(h)+Wrap(3n+10).
~~~

n+3来自n−1个128位Horner乘法及4个映射乘法；2n−1为64位Horner乘法。128位项包含首次块、embed及两个映射加法；64位项包括首次块及更新。串接/掩码、系数读写、控制均已有明确向量。工作区少于128字。

完整vole_check_receiver的费用由：

~~~text
D V_H +128F(h)
~~~

支配。D个活动列再异或Delta位乘ut；高g列逐个复制其22B掩码。后者虽然恒零，128列总H2输入依然完整保存。不会把输出按D列截短。

## 5. QS与Rain约束验签

把quicksilver_gfsecpar的verifier对象解释为GF128的一个MAC及固定Delta指针。纯本地等价算法如下：

1. 128项rain_combine计算Σ_j C[j]·mac[base+j]，共有2R−1次。
2. 从pk的P_t、C_t作两次PSI得到P_p、C_p；装载chi2的两个组合系数、128位键与64位键。
3. 计算Delta²。逐轮构造x_r、y_r的MAC，得到e_r=x_r y_r+Delta²。
4. 对e_r同时作128位键Horner和嵌入64位键Horner，两者都在GF128内。第二项不是GF64乘法。
5. mask=Σ_(j=0)^127 X^j mac[ell+j]。以GF128的公开X=2按Horner计算；加a·Delta和两个组合哈希，输出b。

源combine_mac_masks先在256位多项式里移位，最终约减；按GF128逐项约减与总和后约减相同，故第5步保持b逐位一致。它消除未定256位大操作，但也实际收费127个M_128，未把它称为免费移位。

一次128项组合取：

~~~text
V_combine=128M_128+129F(128)+Wrap(129).
~~~

完整QS核心含公开key转换可取：

~~~text
V_QS =
 (2R−1)V_combine +(4R+130)M_128
 +(5R+132)F(128) +2L128+F(1024)+Wrap(20R+160).
~~~

额外4R+130个乘法来源：Delta²一次、R+1个常量乘Delta、R个x·y、2(R−1)个Horner更新、127个掩码Horner、a·Delta一次、哈希组合两次。总GF128乘法数因此是260R+2；这是本文审计实现的计数，不是AVX2实际指令数。

加法项含x/y构造、每轮加Delta²、两种Horner首项和更新、mask首项/更新及最终三个加法。F(1024)覆盖固定挑战/PK/Delta/a的局部解析，Wrap覆盖外层轮次、索引和返回；模运算、域乘读写已由M_128展开。

## 7. 最终提取核心与管理字段接口

~~~text
q_anchor=a_IC+Q A_V;
q0=a_IC+(Q+1)A_V;
Kbar=min(Nu,2q_anchor);
Q_priv=3q_anchor+rKbar.
~~~

先按旧H1/H2的Source/RO水位恢复森林和C/T/P角色，补com并过滤，先检查桶帽才取tape。后来Full值只供读取同一E的值。Canonical仍只取H1旧支持，K_vis保留H2旧支持；未按最终插入顺序重选。

下表交管理稿统一实现；payload业务读写也须计，表键不作概率hash平均复杂度假设：

| 映射 | 完整key位数 | payload上界 |
|---|---:|---:|
| 实际IC input→角色 |128|4w|
| (tree,com)→目标位置/桶 |w+128|8w，位置引用另计 |
| (tree,parent)→描述符 |w+128|512+8w |
| (tree,seed)→候选 |w+128|128+8w，tape/VH另计 |
| (tree,comL,comR)→canonical |w+256|384+4w |
| 临时VH值→最小seed及tape引用 |176|128+w |

角色数tau(r+3)；Source扫描至多q_anchor；候选产生至多2q_anchor；保留tape至多Kbar。KnownU每个pair建立左字典、按固定seed顺序查右字典，各自总调用至多Nu/2。以trie的固定字节词典序遍历维持既有候选顺序；同VH保留最小seed。字典节点遍历、字段最小值比较、位置表和链扫描由管理稿计费。

核心无需构造V列。每个保留tape计算一次VH，每个A_t计算一次；最多Kbar+tau次。位串部分取：

~~~text
V_post_noW =
 (Kbar+tau)V_H
 +(N+tau+Kbar+4)F(L)
 +(2N+Nu/2+tau+Kbar)F(h)
 +(N/2)F(128)+F(ell)
 +Q_priv [F(384)+Wrap(4)]
 +Wrap(tau(r+3)+q_anchor+Kbar+N+Nu+tau).
~~~

L项依次覆盖NL累积A、tau份初始化、Kbar份tape落盘、最终至多4L异或重建；h项覆盖H(D)、目标补值、等com时D候选是否匹配ut的比较、右桶查找补值、A_t比较及VH缓存；每pair再付完整com比较。W=d XOR f[0:ell]的ell位成本单列。Q_priv项覆盖私有IC参数装配及回答复制，**另加IC调用/Full查表/来源隔离管理**。私有读取不产生新Source根。

这里只有一次最终历史提取，概率项里的a1/a2/aDelta保持原来全部并合次数。桶溢出、unknown和CheckW失败均有明确失败出口。

### 7.1 CheckW及输出

已有见证W=(K_p,y1,…,y_(R−1))时，令y_R=C_p XOR K_p，按源码线性层构造x_i，检查全部x_i y_i=1：

~~~text
V_CheckW =
 R M_128 +(R−1)L128
 +(3R+1)F(128)+F(ell)+Wrap(4R+8).
V_out= L128+F(128)+Wrap(4).
V_post=V_post_noW+V_CheckW+V_out.
~~~

(3R+1)F(128)为2R+1次向量异或与R次等于1检查；成功输出只做一次PSI_INV。初始化P_p/C_p和逆表已在V_init收费。一次输出K为128 IO位，失败标志亦有固定字大小输出，合成时可统一使用128+w位输出帽。

CheckW直接验证R条非零逆元关系；它与“只有K”的完整Rain检查分别收费。其余W字段错误时即使K碰巧有效，也按已审ST2归入非零约束分支，不偷偷做免费forward。

## 8. H_s候选的完整Rain与枚举接口

rain_owf.hpp给出每次tinv：14次M64、19次S64、2次公开L64及3次外层XOR64。本稿S64=M64，故：

~~~text
V_inv =33M_64+2L64+3F(64)+Wrap(48).
V_key,R =
 R V_inv +(R−1)L128
 +(2R+1)F(128) +(R+1)F(128)
 +F(384)+Wrap(8R+8).
~~~

包含R轮加key/常数、每轮完整128位零输入检测、非零标志累积、最终密文比较、K/P/C读入和控制。拒零失败仍按R轮帽，绝不只计297/396个CLMUL作为整机成本。SALT至多min(m,a_s)次新K核验；ST2至多a_s次；重复/无效K缓存由管理稿付费。

给独立Rain原语的可证伪枚举接口：先加载同样常量，抽128位J，按循环序列枚举q≤2^128个互异K，遇有效关系就输出。一个完整保守向量为：

~~~text
V_enum(q) =
 V_init+F(256)+F(128)
 +q[V_key,R+F(128)+F(w)+Wrap(4)]
 +F(128)+Wrap(4);
RNG_enum=128;
IO_enum≤384+w; IC_enum=0; RO_enum=0.
W_enum≤W_pub+32ceil(128/w)+1024 字。
~~~

它覆盖P/C读取、J落盘、模2^128增key、循环计数与输出。W_pub取第9节公开表/PSI工作区的完整上界；额外32ceil(128/w)+1024字覆盖P/C/J/K、Rain状态、GF临时量、游标、q计数和输出槽，按轮复用，不保存q个K。全部Rain计算均在本地，不访问RO或外部IC；未借外部预言免费核验关系。每个生成时K都被长度q的均匀循环段包含的概率为q/2^128，且接受其他原像只提高成功。因此若该**完整向量及空间**落入独立阈值Gamma_R，则任何可用上界p_R都应至少q/2^128；q=2^128排除p_R<1。它是对错误上界的筛选，不是困难性下界。

推进02的分块批量核验同样可把每轮(7n_b+7)M64+(2n_b+17)S64+2L64代入本稿原子；数组、拒零、乘积链、索引、读写和输出仍应叠加。这里不将仅CLMUL节省替代完整枚举向量，也未执行任何q扫描。

## 9. 统一工作区与全归约合成

记a=ceil(128/w)，所有长度ceil仅是数学空间计数，不许可免费任意长算术。一个走到最后的Verify/Sim工作区（字）可取：

~~~text
W_core(m) =
 D(2^k_max−1)a +2Na+256ra
 +2ceil(8s/w)+ceil(8m/w)
 +ceil(8(I_V(m)+O_V)/w)+1024.
~~~

前项分别覆盖源码verifier_subtrees预留、叶seed及承诺、Q与MAC同时保守保留、签名/临时组装、消息和一个可物化全部查询装配缓冲。Sim额外grinding行流式复用，长存程序值进入管理表；无需把G乘入这个临时空间。为便于保守分配，可把I_V/O_V替换I_S/O_S，但那不是本稿所需的最小临时空间。

最终提取另取：

~~~text
W_post =
 Kbar[ceil(L/w)+ceil(h/w)]
 +tau ceil(L/w)
 +N[ceil(128/w)+2]
 +4ceil(L/w)+ceil(ell/w)+1024.
~~~

候选seed/com/父描述符、角色字典、VH临时trie及全部Source/Full/RO历史由管理稿另计；核心数组只保存tape/VH、A_t、目标承诺/位置引用、命中f/W。每个pair临时trie至多u项并复用；未把Nu份长期临时字典留存。

公开常量、PSI消元和逆表保守另加：

~~~text
W_pub =
 ceil((T_R+192)/w)+ceil(32768/w)+ceil(16384/w)
 +2ceil(256/w)+1024.
~~~

用统一arena的地址区间管理工作区；未调用未定成本的malloc。实际写入、清零和释放指针复位由前述F/Wrap或管理稿预分配初始化支付。A的自身空间及签名缓存Q·s、程序/前缀字节、字典arena均另加，故整体并非只有W_core或只有一个批大小。

设签名请求消息长度依次m_i，最终消息长度m_*，并定义m_max=max({m_i:1≤i≤Q}∪{m_*})。将管理稿七维向量记为**该稿的显式有限式**V_manage(v,m)，将A的同一机器实付向量记为V_A，则SALT整条归约的保守完整和为：

~~~text
V_Bsalt,m ≤
 V_A+V_manage(v,m)+V_init
 +sum_(i=1)^Q V_sim(m_i)+V_verify(m_*)
 +V_post+min(m,a_s)V_key,R.

IC_B ≤ q0+3q_anchor+rKbar.

RNG_core ≤ Q(r_S+128);
RNG_B ≤ RNG_A+RNG_manage+RNG_core.

IO_B：原语挑战P∥C入站256位，加管理稿的A输入/输出、RO/IC边界传输，
      加签名交付及最终128+w位输出；内部装配已计RAM向量。
Space_B ≤ Space_A+Space_manage
         +W_pub+W_core(m_max)+W_post.
~~~

上界将所有Q次请求按缓存未命中及所有分支完整执行计费，故覆盖编程失败、grinding尾、cap、最终拒绝及延长ghost。资源帽事前统一保留，运行时不因私有数据结构恰好省时而给A增加查询预算。

所有普通IC已由q0覆盖，私有额外项只加一次；RO请求及字节使用第3/6节列表交管理稿，未把SHAKE整段当作一个免费CPU指令。该归约在ROM内部实现表查询/采样，在IC游戏发出普通E请求；若要比较真实AES/SHAKE门电路或CPU成本，还须两侧采用相同实例化模型与校准，本文不冒充完成那一步。

字长和arena模板先按m≤a_s全域选定，每个公开m的固定容量在其源运行前分配，检查费恰是min(m,a_s)乘已展开V_key,R。因此root的严格整数阈值稿可在同一个w、arena、权重与独立原语证书上形成gamma0+m gamma1；不从验收剩余倒定义Rain优势。
