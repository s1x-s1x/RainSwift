## 1. 机器、费用和固定预算

机器字长w在运行前固定，w≥64。全部地址、记录编号、输入/输出位长度、事件时钟、公开容量计算的中间值及它们所需的+1须小于2^w；w按整个m∈[0,a_s]的先验容量一次选定，不依私有盐、成功分支或实际记录数调整。若64位容纳不下，就使用事前选定的更大w，并使用该w对应的原语成本模型；没有免费多字地址。

使用七维非负计数向量，按坐标比较：

\[
(\mathsf{LD},\mathsf{ST},\mathsf{ADD},\mathsf{BIT},\mathsf{CMP},\mathsf{BR},\mathsf{MOV}).
\]

LD/ST是一字内存读取/写入；ADD是一次一字加减（包括有效地址形成）；BIT是一字与/或/异或/非/移位；CMP是一字相等或大小比较；BR是一次条件或无条件转移；MOV是寄存器或字常量搬运。寄存器间移动不隐藏在零费用赋值里。每种指令可有独立正权重；向量不等于CPU周期。普通IC调用、真实随机位和边界位传输另设独立坐标。

不使用免费乘法、除法、CLZ、哈希表、malloc或排序。容量公式所需一字整数乘法/除法用w轮移位加减长算法，每轮至多4个下述β块；逐项计算本文容量需要少于256次这种整数例程，连同初始化常数、取整、min及边界校验，由2048(w+1)β覆盖。允许域以所有中间值可表示为前提；越界在分配/写入之前按既定预算失败，不能在继续运行时截断地址。

设

\[
\boldsymbol\beta=(8,8,16,8,8,16,16).
\tag{MACHINE}
\]

β是后文有限微程序的坐标上界，不是一条新的单位成本指令。给每坐标选取成本后再作内积。所有内存连续切片使用公开容量、只增指针和边界比较；没有操作系统分配器的未知成本。管理宏可以全部内联成固定跳转，常驻游标/暂存/返回槽保留512字，不用递归或无界调用栈。

沿用SALT/ST2：

\[
\begin{gathered}
a=a_s,\quad 0\le m\le a,\quad h=176,\quad\ell=128R,\quad L=\ell+304,\quad r=R+3,\\
q=a_{IC}+Q A_V,\quad q_0=a_{IC}+(Q+1)A_V,\\
K_* =\min(Nu,2q),\quad p=3q+rK_*,\quad F=q_0+p,\\
A_*=(r+3)\tau,\quad S_* =\min(2q,Nu+1).
\end{gathered}
\tag{P1}
\]

F同时上界所有普通/私有IC接口请求和实际新物理行。S_*允许在桶帽检查失败前保留一个造成溢出的seed；成功进入tape阶段的保留数仍≤K_*。不以Gu成立作为空间前提。u为原算法的整数桶帽。

全部源RO调用/编程尝试数使用

\[
H=H_A+Q(\tau+5+G)+(\tau+6)
\tag{P2}
\]

的先验上界；包括重复、零输出、长前缀、编程失败、grinding及最后Verify。I、O分别是这些调用输入/请求或编程输出的总位长先验界；M_msg是Q个Sign消息与最终消息总位长界。L_in、L_out、L_msg是各自单次最大位长。I/O可直接代入推进02资源稿R2及核心稿的长度式；只给调用次数不足以约束这些量。σ为完整签名字节数；κ=ceil(128/w)、ζ=ceil(384/w)。以下所有符号均是公开上限，不是事后成功轨迹值。

## 2. 有限基础例程及常数的来由

### 2.1 位读写、字搬运、分配

连续位串按固定字节顺序存储。BitReader保存(word_ptr,bit_offset)；读一位执行地址读取、移位与1掩码，游标加一，到w时进下一字。BitWriter用读改写置位并同样推进。字节内顺序按原协议，数值词典序使用其事先规定的编码；不因主机端序变更比较次序。

| 例程 | 实际动作 | 七维操作上界 |
|---|---|---:|
| ReadBit / WriteBit与游标推进 | 每位至多2读、1写、4加减、4位操作、2比较、3跳转、4搬运 | β/位 |
| CopyBits或CmpBits(n) | 初始化双方游标；逐位读/写或比较，保留首差异；比较相等时也计全部n位 | (16+2n)β |
| CopyWords(n) | 每字1读1写、两指针推进、计数和循环 | (16+4n)β |
| AllocZero(n) | 先检查剩余容量，更新只增指针，逐字清零；零长度仍付头尾 | (16+2n)β |
| AppendRecord(p) | 通过已固定arena追加p字段，所有指针/状态赋值与序号增加 | (16+4p)β |
| 固定停止槽 | 原因、当前事件、水位、活动候选、末记录、输出状态，共≤24字 | 128β |

ReadBit/WriteBit所列各列逐项≤β。CopyBits每位至多一次读取和一次写入，CmpBits至多两次读取；头尾的游标/长度/分支均在16β内。CopyWords、AllocZero、AppendRecord均只有一个所示长度的单循环。不存在把n字初始化当常数的步骤。

一次真实随机位用独立RNG坐标计，并用WriteBit保存；存储控制按上述位程序另计。边界数据接收/发送逐位复制，费用与bit传输坐标并存。

### 2.2 精确位树：查找、新建与payload

每个节点四字：child[0]、child[1]、parent、payload。空指针为0；根有单独固定槽。FIX字典的键长在该字典中固定为b，路径就是b位键。VAR字典的路径是w位大端长度字||原始位串，长度为w+b；两个不同长度的原串在前w位已经不同，故路径前缀歧义不存在。头部长度位不改变原始串的内容相等关系。VAR的w位长度头由已校验raw_bitlen寄存器按高位先出流式生成，不写入raw键打包缓冲；打包缓冲只保存原始键段，故第5.2节L_key无需再加一份w。逐位生成/读取长度头仍已计入路径K和TRIE。

下面伪码只有第2.1节例程及一字操作；每一指针解引用都算LD/ST与寻址。

```text
TrieAccess(dict, key_segments[1..s], raw_bitlen, mode, p):
  // s<=3；固定族检查长度，变长族读取/生成w位长度前缀
  pack segments into a reusable key buffer; check public size bounds
  cur := dict.root
  for bit b of the FIX/VAR path, in order:
    slot := cur+b
    nxt := LOAD(slot)
    if nxt == 0:
      if mode == LOOKUP: return (0,false)
      nxt := allocate four-word node; check capacity before write
      STORE(nxt+0,0); STORE(nxt+1,0)
      STORE(nxt+2,cur); STORE(nxt+3,0)
      STORE(slot,nxt)
    cur := nxt
  ptr := LOAD(cur+3)
  fresh := false
  if ptr == 0 and mode == FIND_OR_INSERT:
    ptr := AllocZero(p); STORE(cur+3,ptr); fresh := true
  if ptr != 0:
    copy all p payload words to the caller's fixed frame
  return (ptr,fresh)
  // caller changes only declared payload fields
  // at most one complete p-word commit back to ptr per visit
```

每个路径位包括：一位读取、child寻址/读取、空值判断、必要时容量判断与四字段初始化、父边写入、进入下一节点。该完整块逐坐标不超过2β；无新节点分支更小。一次查找头尾、payload指针判断和返回不超过32β。至多三个键段的打包各付CopyBits；固定头尾允许96β。加上payload搬出/一次写回和初始化，得到可直接复用的接口：

\[
\boxed{\mathcal G(J,K,P,W)
 =\boldsymbol\beta\,[128J+4K+2P+8W].}
\tag{TRIE}
\]

J为调用次数；K是所有调用的**路径**位长之和；P是所有新payload的总字数；W是逐调用payload宽度之和。LOOKUP未命中也用该次p计W，故不需成功概率。P含所有临时字典重建的payload初始化。节点初始化已在路径位费中；固定arena预留/启动初始化还会在总式另付，允许保守重复收费。输入输出字节传输不混入K，另计。

例：一个固定256位键、p字payload的字典，J次调用满足

\[
\mathcal G\preceq\boldsymbol\beta[(1152+8p)J+2P].
\tag{TRIE256}
\]

至多Z个新键时，其节点≤1+256Z、payload≤pZ，工作区≤4(1+256Z)+pZ字。它不依键的随机性或分布。两张IC索引应分别计根和新键，不能把它当一张表。

### 2.3 顺序遍历与临时字典重用

为保持seed词典序，以0边先于1边作深度优先遍历。父指针使其不用递归：状态为(prev,cur)，分别判断从父进入、从0子返回、从1子返回，选下一个子或父。每个节点至多进入三次，每次至多4个字段读取、4个地址/指针动作和固定比较/跳转；可用16β/节点覆盖。访问叶payload按CopyWords单列。

V个节点、Z个p字payload的一次有序遍历上界为

\[
\mathcal D(V,Z,p)=\boldsymbol\beta[16+16V+4pZ].
\tag{DFS}
\]

临时VH字典每个pair结束后仅把根四字段清零、节点/payload只增指针退回该公开切片起点。后续重用必须重新初始化所分配四字段和payload，仍由TRIE逐次收费；没有依赖“arena曾经为零”。一个pair的最坏容量u决定峰值，全部pair的创建工作由累计P和K决定。

### 3.2 OnRO：首次触达、预留与程序行

```text
OnRO(caller, mode, X, requested_bits, supplied_program_bits):
  read/check the length headers; receive exactly the allowed input bytes
  append a pending version; advance RO-event clock, preserving prior cut
  row := exact VAR TrieAccess(X)
  if row is new:
    copy immutable input; set first-event and source identity
  if mode == PROGRAM_FRESH and row was already touched:
    record programming conflict; SealAndStop
  classify by exact input length and suffix, using the frozen domain table
  if first qualified ordinary H1/H2:
    store descriptor BEFORE any new output reservation or answer
  if first qualified ordinary 65-byte H_s:
    append Candidate and execute the two-direction SALT handler below
  need := max(requested_bits, exact first-touch protocol reservation)
  if need > row.defined_bits:
    allocate a new exact-size prefix buffer
    copy the old immutable prefix
    append programmed bits or independent random tail as the mode requires
    publish new prefix reference and its defined length
  complete the version and copy the requested answer to the caller
```

域识别只需末字节与固定参数下有限长度表（Hμ、H4、内/外Hc、H1、H2、HΔ、Hs）；使用原有首次预留长度，最大704位。不把所有未知输入一概预留704位来改变历史资格。程序点只允许完整未触达输入，先前零输出记录也会冲突；冲突不覆盖旧值。Hs的SALT钩子在任何答案/新预留之前执行。

输出使用**持久追加缓冲**：每次真的增长分配恰好所需的字数，旧缓冲保留到程序结束，历史只记录row_id和当时有效前缀长度。每次增长的最终位长≤该次请求位长+704，因此全部分配量≤W_O+H ceil(704/w)，其中W_O=ceil(O/w)+H。全序列复制旧前缀位数≤O+704H。它以完整请求长度预算收费，无扩容摊销黑盒；占用比旧翻倍方案更保守，语义相同。

RO版本包含pending/aborted状态；后续补长不得升级旧版本。编程输出由模拟器随机带提供，额外独立RO随机尾由管理程序抽取，两者区分；管理RO新随机位数上界O+704H。

### 3.3 Sign、候选与Checked

```text
OnSign(message):
  append pending SignEvent; register full message bytes in message trie
  draw/store private 128-bit rho; obtain mu through the ordinary RO path
  z := Ctx.FindOrInsert(mu||rho); preserve event/context references
  if z.cache_ready: copy cached signature; finish event; return
  z.cursor := z.head; z.registered := true  // first registration of this object
  while z.cursor != 0:
    save next before callback; ProcessCandidate(cursor); advance cursor
  z.cursor := 0  // old chain has been exhausted
  call the same pk-only core
  on success copy signature/derived value into cache, finish SignEvent
  on original failure preserve event/prefix and SealAndStop

OnFirstQualifiedHs(K,mu,rho,row):
  z := Ctx.FindOrInsert(mu||rho)
  c := append Candidate once; c.next := 0
  if z.head == 0: z.head := c
  else: old(z.tail).next := c
  z.tail := c  // do not extend an already registered context's cursor
  if z is registered: ProcessCandidate(the new record)

ProcessCandidate(c):
  record reached-event
  if Checked.Lookup(c.K) exists: mark processed; return
  if completed_checks == m: SealAndStop(cap) BEFORE any further Rain work
  call complete CheckKey(c.K); increment completed_checks
  if valid: emit this exact K and stop
  Checked.FindOrInsert(c.K); store invalid result; mark processed
```

新Ctx的head、tail、cursor、registered、cache_ready均由payload初始化为0。接口串行；旧Sign若失败全局退出，所以缓存未备而进入OnSign的对象在这里首次登记。首次登记显式从head扫描旧链，完成后cursor为0；随后到达的已登记上下文候选即时处理，不再挂入待扫cursor。同一完整RO输入只建一条Candidate；重复Sign缓存命中不重扫旧链。新到候选立即处理，故登记上下文的cursor只用于首次Sign旧桶。每条候选最多处理一次，共≤a次；完整CheckKey≤m，失败插入≤m。最终消息的新鲜性检查对完整消息trie只作LOOKUP，不插入最终消息；执行顺序沿原最终验证程序。已签集合登记所有Sign请求消息，失败Sign后全局退出。Q+1次调用及Q+1个潜在新键只用作保守空间/费用帽。链顺序用首次源事件，绝不用trie的盐数值顺序。失败后没有继续模拟；失败SignEvent即使尚未缓存也保留。

### 3.4 H4正常复用与普通IC

实际程序沿用ST2所依`具体界推进_20261015/签名模拟/01_按IC单元耦合的原030无私钥模拟.md`第5、8节：抽iv_pre后正常调用H4，`iv_pre||04`已有记录时复用原输出；H4不编程，也不因旧输入中止。只有H1/H2/HΔ的PROGRAM_FRESH旧点冲突产生对应编程失败。旧阶段03的H4旧点abort已被该模拟删除，本文不恢复它。

实际RO访问只需≤H。为了保持已列保守资源式，本稿仍使用H+Q以及I+wH+Q(w+136)的宽帽；额外Q次136位查表只是可省的多收费项，实际程序不执行这一步，也没有相应输出、随机采样、事件时钟增加或分支。此宽帽不会改变SALT的公开轨迹与失败前缀。

```text
IC(caller,direction,K,arg):
  append pending IC-event; look up exact (K,arg) in forward/reverse trie
  on miss: make ONE ordinary external IC call
           append canonical (K,x,y); insert both directional indices
```

Full命中仍作索引、记录和复制。Private永不提升Source；未来普通触达旧Private行先提升再回答。新物理行≤F，索引总调用≤F+2F=3F。外部IC返回值来自同一个独立普通IC，不在本稿编程或本地仿造。

## 4. 最终历史链及提取管理

### 4.1 旧水位与历史链

全局RO版本按事件顺序扫描，至多τ+3轮：H2、H1、外层Hc及各树内层Hc。最终Verify已记录其实际H2行号，行号精确标识完整输入；其他前像按原固定顺序和对应输出前缀寻找。每条版本先核旧Source/RO水位、来源、长度、预留及完成资格，**合格后**才检查/写本轮row stamp。不合格版本不妨碍同一行之后合格的旧版本。每个扫描版本最多比较704位前缀及8个资格字段。

stamp比较/读写、循环、扫描序号、边界与各次结束均收费。所有版本数≤H，故扫描固定事件数为(τ+3)H，前缀位比较量≤704(τ+3)H。选中输入的解析位量上界

\[
J_{hist}=648+(\tau-1)L+704+129h+\ell+8+256\tau+8+128N+8\tau.
\tag{HIST}
\]

解析后仍保持旧冻结规则；没有旧链即按原失败分支停止。未来RO扩展、最终Verify新行或以后Source首次曝光都不获得旧成员资格。

### 4.2 提取字典及调用上界

核心只作森林/向量/VH/QS/Rain算术；以下字典、精确成员性、顺序、桶帽和所有记录控制均在本稿收费。固定(tree,seed)编码为w位树号||原固定seed词典序的128位表示。下面的宽界允许部分相同引用多查一次；代码使用引用时只会更省。

| 字典 | FIX键位数 | payload字数p_f | 调用上界J_f | 新键峰值Z_f |
|---|---:|---:|---:|---:|
| 当前森林角色 |128|4|A_*+q|A_*|
| 目标com桶 |w+128|κ+12|2N+2q+K_*|N|
| parent去重 |w+128|5κ+12|2q|q|
| 保留seed |w+128|2κ+12|2q+N+2K_*|S_*|
| 目标有序com对/canonical |w+256|3κ+12|N+q|N/2|
| 当前pair的VH值→最小seed |h|κ+4|Nu|u（每pair重用）|

实现顺序如下，引用更新由这些payload承担：

1. 插入A_*个实际input角色。读原N个目标承诺，建com桶及每叶bucket引用；读N/2个有序承诺对，建pair桶及每pair引用。相同目标串合并但保留各叶引用。
2. 按不可变Source首次曝光数组的序号顺序扫描，严格截在旧H2水位s2，最多q条旧行；到首个序号>s2即结束扫描。最终Verify或之后产生的Source行不参与旧成员分类，只可能通过Full提供同一IC数值。角色查找确定唯一C/T/P角色。parent按(tree,parent key)去重；首次支持时刻和最早root id保存。它的两个实际孩子/com由核心普通PrivateIC接口补齐，费用进入F。
3. 每条C/T源行最多贡献一个seed、每个parent最多两个，共≤2q个贡献。先查目标com；无关com不存tape。命中的(tree,seed)精确去重，同一个seed在固定tree下有确定com。新seed增加桶计数；超过u即记录溢出并停止，**在tape读取之前**。
4. 仅首次父支持≤s1的parent参与canonical。查目标有序com对，以(parent key,earliest qualifying root id)字典序比较更新最小项；每个父候选最多一次128位比较和一字tie比较。保留两个孩子的seed引用。它不阻止后续H1之后、H2之前成员进入K_vis。
5. 在未溢出分支，按保留seed trie的(tree,seed)顺序遍历一次。为≤K_*个seed调用tape/VH核心，并把其记录按遍历次序挂到相应桶的链尾。于是各桶都按原seed词典序排列。遇到同com的重复叶，只复用桶头，仍分别执行该pair的扫描。
6. canonical由每pair保存的引用读出；所有A_t与VH算术交核心。按原顺序先查A_t，再查同com的D，再处理pairs。每pair清空临时VH trie；左桶顺序插入，重复hash保留最小seed；右桶按seed顺序查补值，首次命中交核心生成完整f/W。左右桶总访问分别≤Nu/2。固定选择规则连碰撞情况下的最小seed/tie也保持，不换成Full插入顺序。

第3步的每次新seed都有一个旧Source支持，但完整保留数允许S_*，以覆盖最后造成溢出的记录。第5步实际进入tape的数量用K_*。第2步无命中仍支付角色查找及扫描。临时VH树的排序由精确路径/按顺序桶链实现，不额外调用sort。

给所有这些固定宽管理动作一个可直接核对的事件总帽

\[
E_{ext}=A_*+3N+6q+2K_*+2Nu+16.
\tag{EXT}
\]

A_*覆盖角色构造；3N覆盖叶/pair建表、canonical引用和pair循环；6q覆盖根、parent与至多两个seed贡献及去重；2K_*覆盖tape/VH引用更新与有序桶链接；2Nu覆盖左右插入/查找及命中判断。每事件至多24字payload、两个引用表和固定比较/状态操作，主体≤256β；每事件固定宽字符串的保存/比较合计≤2048位，所用Copy/Cmp块≤8个。L位tape和代数向量不藏在这2048位中，由核心另付。该统一宽界允许重复收费，不用另留一个未知提取管理函数。

## 6. 完整管理七维上界

为使常数可逐事件审查，把非trie的固定控制列出：

| 事件 | 单次固定动作的有限上限（不含已单列的长串循环/密码核心） |
|---|---|
| RO/程序调用 | ≤16项头部/长度校验；≤16个域长度/后缀分支；一次16字pending及完成更新；一次8字描述符；row标志/长度/指针更新≤24字段；预算/退出检查≤16项 |
| H4可省宽帽（实际不执行） | 保留旧一次只读LOOKUP的保守费用余量；实际H4走普通OnRO，复用旧输出，无额外事件或中止分支 |
| Sign开始/结束、消息登记 | 各≤24字段访问/赋值，缓存分支和退出；整个新对象的密码工作另算 |
| Candidate追加/处理、Checked提交 | 各≤24字段/队列/计数动作，一次cap/成功分支；没有扫描隐含桶 |
| IC接口 | 一次8字事件；规范行/Source状态≤24字段；首次提升、两表提交、返回状态；密码调用另算 |
| 历史版本一次扫描 | ≤8资格字段、stamp读/比/写、游标/边界及一次前缀比较调用 |
| 第4节一次提取事件 | ≤24字业务payload、两个引用数组、固定比较/更新；宽串量和例程调用数按EXT |

逐字段动作至多一次寻址、读/写、比较、指针/常量更新；即使把表中所有可同时发生的分支相加，各坐标也小于256β。多个trie访问通过J_m收费，长串循环通过下述B_m收费，所以这不是把可变循环隐藏在一个事件里。

固定事件数用

\[
E_m=H+4Q+2a+m+F+(\tau+3)H+E_{ext}+16.
\tag{EVENTS}
\]

其中4Q覆盖Sign开始/完成、消息登记，另留Q次未执行H4查表的可省多收费余量；Q+1的最终消息/退出余量在+16。a次追加与a次处理分列，m是Checked提交；停止槽及各阶段结束的常数余量保留。每次调用失败均落在同一事件帽内。

所有非trie长串复制/比较/随机位保存的位量可取

\[
\begin{aligned}
B_m={}&2I+4O+1408H+2M_{msg}+768F\\
 &+512a+128m+Q(1024+16\sigma)\\
 &+704(\tau+3)H+J_{hist}+2048E_{ext}+128+w.
\end{aligned}
\tag{BITS}
\]

逐项含义：

- 2I为RO输入接收/不可变副本；4O+1408H覆盖编程/返回、旧前缀搬迁、新尾保存；后两项各≤O+704H。
- 2M_msg为完整消息接收/保存；768F覆盖IC逻辑请求/返回及新规范K/x/y副本，另有TRIE键打包。
- 512a覆盖候选K及Ctx键副本；128m为Checked的K副本；Q(1024+16σ)覆盖盐抽取保存、SignEvent、μ/ρ上下文、缓存派生值及缓存/返回签名，宽于各实际之和。
- 历史前缀/解析与EXT的固定宽记录分别列出；128+w为最后密钥/失败输出及长度状态。

非trie的CopyBits/CmpBits/随机带保存例程总调用数保守取

\[
L_m=8H+8F+4a+2m+12Q+8(\tau+3)+8E_{ext}+32.
\tag{BULK-CALLS}
\]

它覆盖每个RO的收/存/程序/返回/扩展，IC规范化，Sign/候选/缓存，选中链分段和EXT每事件≤8次宽串操作；相同块的重复收费只扩大上界。键打包和payload搬出/写回已在TRIE内，未依赖从这里扣减。

有序遍历只需保留seed字典一次，取V_seed=1+(w+128)S_*、p_seed=2κ+12。临时VH每pair重置已计入EVENTS和TRIE累计初始化。

最终管理操作证书为

\[
\boxed{
\begin{aligned}
\mathbf G_m\preceq\boldsymbol\beta\big[{}
 &8S_m+2048(w+1)\\
 &+128J_m+4K_m+2P_{all,m}+8W_m\\
 &+256E_m+2B_m+16L_m\\
 &+16+16V_{seed}+4p_{seed}S_*\big].
\end{aligned}}
\tag{MANAGE}
\]

这是一条显式有限表达式；其右端没有C_manage,ctl、Gamma管理黑盒或未给常数的大O。β每坐标的单价仍独立；完整核心/对手/外部IC分量尚要相加。

额外独立坐标可保守取：RO新随机位≤O+704H；私有盐随机位为128Q，其来源在这里登记。核心稿的Q(r_S+128)已经包含同一份盐，因此合成时盐只计一次：取RNG_manage=O+704H，并加核心Q(r_S+128)及A的随机币。位存储操作仍按本稿与核心的保守RAM帽收费。逻辑边界位传输总量≤I+O+M_msg+384F+8Qσ+128+4w(H+F+Q+1)，其中头部按4字计，内部接口也保守收费。对外IC调用≤F及其真实输入输出不能因为有Full缓存而免除。A本地随机币/运算、公开核心算术、CheckKey与CheckW保持正费用。

## 7. m的仿射资源帽及零预算情况

固定v和全域容量选定w后，只有Checked与检查提交的管理项依m。记p_c=κ+4，则

\[
\begin{array}{c|c}
\text{项}&\text{每增加1单位m的上界增量}\\\hline
V_m&128\\
P_m,\ P_{all,m},\ W_m&p_c\\
S_m&512+p_c\\
J_m&1\\
K_m&128\\
E_m&1\\
B_m&128\\
L_m&2
\end{array}
\]

因此MANAGE和SPACE给出坐标仿射帽

\[
\mathbf G_m\preceq\mathbf G_0+m\,\boldsymbol\beta\,
[8(512+p_c)+128+512+10p_c+256+256+32],
\tag{AFF-T}
\]

\[
S_m=S_0+m(512+p_c).
\tag{AFF-S}
\]

这里G_0指MANAGE右端在m=0的确定表达式。其他与m无关的Source、历史、上下文及最终提取满额费用都在G_0；原CheckKey完整forward成本由核心另加m次，保持同一个实际归约。未把不同算法较小分项拼接，未把完整forward替换为不同接口的CheckW。

- m=0仍初始化Checked根槽，执行所有相关输入识别/上下文匹配及首次未缓存K的cap分支；仅完整CheckKey次数和其结果插入为0。
- a=0强制m=0；保守Ctx仍按Q个Sign对象计，候选数为0。Q=0时不存在已签上下文，实际SALT检测检查数为0；若仍使用宽仿射帽则只是多收费，原cap误差按SALT规则取0。
- 设定m≤a保证m≥a时的特殊SALT尾为0。所有前缀/failed Sign/重复消息均仍保留，失败输出不是WINDOW列表。
- 所有上界是确定性最坏界，非E[Z]驱动的平均计算预算；没有把Qa/2^128当每条执行的检查次数。

## 8. 与已审SALT的连接及边界

把抽象字典看作从完整键到记录的数学映射。FIX/VAR精确位树无碰撞且只改变表示；每个源事件后，其数学映射、事件/版本顺序、输出前缀与旧SALT程序一致。记录复制保留原字节，完整消息新鲜性用原消息而不是μ。Candidate由源事件顺序链接；缓存仅由相同(μ,ρ)复用；Checked只复用固定(P,C,K)的无效结果。

历史函数仍使用旧H1/H2切口、旧成员与原canonical/KnownU选择规则。PrivateIC不升级Source，未来Full值只可用来回答同一个E的值；旧支持资格不变。提取树的0/1顺序必须选为原固定比较顺序，因此精确保留碰撞情况下的tie行为。

对任何固定随机带与IC，按源事件归纳，所有公开响应、缓存命中、编程/grinding失败、RelevantHit/cap和最终成功相同。位树结构、地址、分配次数和实际用时均为内部状态；**模型没有秘密计时或内存访问观测接口**。初始化和最坏资源帽在源运行前统一预留，内部耗时不缩减A既定步数/查询数/Sign额度。因此更换字典不会破坏SALT的盐置换对称性或停止成功耦合。这里的等价针对源A可见响应、原候选选择规则及最终成功输出，不主张失败后私有IC日志逐字一致。旧提取稿先完成分类再判桶帽；本实现一发现已超帽即失败，省去剩余私有补读。超帽以后旧程序也无成功输出，且这些补读没有返回给已终止的A，因此该早停保持成功函数；完整最坏费用帽仍按全部可能工作保留。

所有失败都保留已建记录；pending请求标记aborted而不伪造答案。保存只指程序内解释所需有限内存；若另需磁盘导出日志，必须增加其序列化/传输费用。本文没有外部日志导出操作。

本文给出一份完整**管理**程序成本。与核心稿相加后，还应核同一归约的随机位/IC/业务复制归属；重复收费可保守保留，删重必须有实际共享接口依据。即使总成本闭合，也须有在该完整资源点适用、独立于签名结论的真实拒零Rain困难性依据，才能进行与作者声称强度的具体比较。本文未赋予实际安全位数。
