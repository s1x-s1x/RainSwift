## 2. 跨IV完整链与原子计数

两层Hc实际输入不含IV。给定一次完整叶承诺列表及两层旧原像后，以新IV形成新的H1，无需再次提交同一批Hc输入。H1的完整输入仍含该IV，后接H2的chi1也来自实际旧回答；H2输入中的128列22B校验串没有被缩成一个32B摘要。

冻结参数内父地址由xC确定，因此原子身份为实际三地址及有序目标对，等价地为(xC,c0,c1)。本源给每个叶位置分配不同的com值，故不同底层有序叶对没有身份碰撞。对一个固定叶对，IV到xC是四个32位lane平移的双射。因而在旧链唯一可解析的运行上：

~~~text
J_actual = D_IV N/2.
~~~

此计数不额外乘树号或位置，也没有把重复IV算成新原子。无H4碰撞且无旧Hc解析歧义的运行有正概率，支持全轨迹确定帽至少为qN/2。对独立均匀H4输出，q−D_IV不超过相等输出对数，Markov所给(q−1)/M上界正确。

最终输出把delta第127位置1；该字节位于signature_bytes−21。faest.inc:219的检查在H4和开示重构之前拒绝，故原A_chain的真实优势恰为0。这里的“完整链”只指旧哈希链、真实长度和顺序，不包含VOLE/QS关系及真实开示正确性。

## 3. 审查发现的计价错误与修正

冻结成本约定第6节规定每次RO查询从零状态完整吸收，计价路径只依赖公开长度。原稿的H1前缀缓存及H2跳过零正文虽是正确的实际SHAKE优化，却不属于这项冻结接口价格。只保留完整IO费用不足以弥补这一差异。

最终稿改用同一冻结程序和原上界50176，静态复核为：

~~~text
置换：H4 1次 + H1至多11次 + H2至多18次 = 至多30次。
padding字节帽：168 + 1848 + 3024 = 5040。
输出字节：16 + 88 + 56 = 160。
非置换包装：48·5040 + 32·160 + 3·4096 = 259328。
全边界：5543·24 = 133032。
新key AES：762 + 3036 = 3798 ≤ 4096。
两循环、编码与控制：8192。
总和：30·50176 + 259328 + 133032 + 4096 + 8192 = 1909928。
~~~

一次准备、完整Hc输入、摘要歧义比较、公开代码/表装载、空间清零和最终短验签保留在2^32内。这里没有运行程序测量成本，也没有更改3036单位或目标阈值。

q=2^116时，T*=3108864q，余量为1198936q，足以支付2^32准备及后文2^48完整随机后缀。因此q116域内结论有同一有限源的完整费用支持。q118时当前上界超过777216q，只能得出这张费用证书没有证明入域；最终稿已经正确保留该区别。

## 4. 完整随机签名后缀

后缀均匀采样完整足长签名，再固定g个grinding高位为0，故分布均匀于2^(8sigma−g)个足长字符串。它没有省略开示、seed、承诺、counter或其他签名字段。

支持集证明可在同一随机对象上使用真实KeyGen的隐藏有效见证形成一份分析用诚实签名，且该见证从未交给对手。已有前缀没有HDelta查询；域标签使诚实counter0输入为新点。其高g位为零的概率为2^-g。vector_com.hpp:62给GGM森林OPEN_ALWAYS_SUCCEEDS=true，vector_com.inc:1033—1060的流程确认该分支开示成功。诚实关系确保完整验证接受。

独立随机完整输出恰好等于上述分析签名的条件概率为2^-(8sigma−g)，相乘得到不小于2^-8sigma的接受概率。这不依赖生成密钥均匀或原像唯一。

以推进03完整V_verify及F、M、L等已展开公式核对，最终稿给的2^48额外上界有充分余量：V_rec与其余本地项分别可被2^44支配；完整IC、完整RO、随机位、IO、代码/表装载及空间初始化全部保留。这个宽帽不是运行速度。

最终稿区分了两个有完整费用支持的例子：

- A_chain^+在q116入域，具有上述任意完整旧哈希链。
- 推进04原A_q加同一后缀在q118入域，其原前缀缺Hc旧原像；该例子只证明非零支持并不限制大查询预算。

二者都没有给出最终有效旧链、LateFinal与实际Fail_B交集的非平凡概率下界。

## 5. 与首现条件矩的组合边界

A_chain全部合规H1都在Source首次IC之前，因此首现桶占用为0、lambda=1。异目标使用交叉矩，同目标使用B(B−1)阶乘矩，分子均被1支配。首现稿A8的Parent<1/64适用于Q=0、无IC前缀且H1与攻击者IC各至多q=2^118的查询轨迹类；它不依赖这个具体源是否已在q118取得冻结成本入域证书。
