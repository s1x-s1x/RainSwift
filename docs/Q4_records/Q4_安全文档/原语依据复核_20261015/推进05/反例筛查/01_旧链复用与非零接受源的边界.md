## 2. 一次完整叶列表，多个完整旧链

固定m0=0^128，普通查询mu=H_mu(pk||m0||08)。按实际叶顺序给所有位置分配全局互异的128位值com_j=enc128(j+1)。它们是公开承诺目标，不宣称已知叶seed或有效开示。

完整提交每树16N_t+1字节Hc输入，取得h_t，再提交32tau+1字节根输入得到hcom。全部原像输入、输出和规范SHAKE价格只支付这一次。对摘要歧义可检测并记标志，但继续全部循环；原子计数在旧链解析无歧义运行上陈述，随机签名后缀在所有运行上执行。

令1≤q≤2^118为公开有限参数。源分两段，不保存q份驻留历史：

~~~text
Acc := 0
for i=0,...,q−1:
    IV_i := H4(enc128(i)||04), request 16B
    chi1_i := H1(mu||hcom||0^((tau−1)L)||IV_i||09), request 88B
    chi2_i := H2(chi1_i||0^(176+128·176+ell)||0A), request 56B
    Acc ^= IV_i ^ prefix128(chi1_i) ^ prefix128(chi2_i)

for i=0,...,q−1:
    Y_i := IC.Forward(enc128(i), 0^128)
    Acc ^= Y_i

sigma := a correct-length zero buffer
sigma[0:16] := Acc
sigma[signature_bytes−21] := 0x80
return (m0,sigma)
~~~

指数为位数，09/0A/04为一字节标签。所有输出完整接收，未参与Acc的字节照付费。c、ut、128列校验串和d均按真实长度输入；选零并不意味着它们满足实际VOLE或QS等式。每条H2的chi1来自紧前H1，mu、hcom、两层Hc原像和H4原像均已在历史中。

没有Sign、H_s查询或Rain秘密，Q=a_s=0。q个IC key互异且都在全部H1切口后触达，所以这些H1之前Source IC表为空。最终足长输出严格有

~~~text
Adv_sig(A_chain)=0.
~~~

这里“完整旧链”仅指真实长度、普通回答及正确先后关系。实际接受仍需要完整开示、重构、HDelta连接与新消息规则。

## 3. 旧链不迫使逐IV重付全部叶承诺

固定参数组中

~~~text
x0=xC ⊞ (0,0,0,−tau),   x1=x0 ⊞ (1,0,0,0).
~~~

所以原子可写alpha=(实际xC,有序com0,com1)，等价于带三地址的身份。树号、位置及H1序号不额外进入原子。

本稿所有底层有序叶对全局互异。对固定叶对，IV到xC是四lane平移双射。令D_IV为q个H4回答中不同IV数，则合规首现原子数为

~~~text
J_actual=D_IV N/2.
~~~

同IV重复只重用旧原子。无H4碰撞运行具有正概率，并有D_IV=q；因此全轨迹有效的确定先验原子帽至少为qN/2。这里未把事后实际J当作先验统一保证。

H4的q个输入互异，回答独立均匀。令C为相等输出对数，则q−D_IV≤C且E[C]=q(q−1)/(2M)。Markov给

~~~text
Pr[D_IV<q/2] ≤ (q−1)/M.
~~~

这是原子数的陈述，不是实际伪造概率。它说明两层旧Hc输入不含IV，故完整列表可跨IV复用。若只把旧a1N/2换成原子帽Jbar，最坏计数仍可等于qN/2；每首现时的实际Source桶占用则给出另外的信息，见第7节。

本节计数形式也可写在q118，但第5节只证明完整链源q116进入冻结预算域。未从计数形式推出新的q118域内障碍。

## 4. 严格沿用冻结规范价

依[推进04标尺第6节](../../%E6%8E%A8%E8%BF%9B04/%E6%A0%87%E5%B0%BA/01_%E5%9B%BA%E5%AE%9A%E6%88%90%E5%8A%9F%E7%8E%87%E4%B8%8E%E5%85%B1%E5%90%8C%E6%88%90%E6%9C%AC%E7%BA%A6%E5%AE%9A.md)与[推进04源成本第6节](../../%E6%8E%A8%E8%BF%9B04/%E8%AF%81%E4%B9%A6%E9%9A%9C%E7%A2%8D/01_ST2%E5%85%A8%E6%A1%B6%E5%B8%BD%E9%A5%B1%E5%92%8C%E4%B8%8E%E5%90%88%E6%B3%95%E6%BA%90%E9%A2%84%E7%AE%97.md)，RO查询每次从零状态吸收全部输入。重复固定前缀与全零正文均照常计费。规范核比特值不替换ROM/IC回答。

### 4.1 全部SHAKE工作

固定规范置换沿用C_f≤24·2048+1024=50176，不以本轮新程序改变oracle价格。

H4输入17B，需要1次完整置换；H1最多1815B，需要11次；H2最多2991B，需要18次。三个调用合计至多30次。其实际padding缓冲分别不超过168、1848、3024B，合计5040B；输出共160B。

沿用每吸收/复制byte48动作、每输出byte32动作、每调用头尾4096的既有帽，三个调用非置换部分共

~~~text
48·5040+32·160+3·4096=259328.
~~~

块循环、游标、输入复制或padding清零、lane寻址/移位/XOR、输出提取及返回均保留。H1没有缓存计价，H2没有按零数据删吸收计价。

### 4.2 全边界、AES与源控制

四次调用各4w位描述头，合计512B。每个i配对的完整输入输出字节至多

~~~text
H4 17+16，H1 1815+88，H2 2991+56，IC 16+16+16，描述头512
合计5543B。
~~~

每byte边界复制≤16 RAM动作，再付8位IO，共5543·24=133032。每次IC key不同，762动作key展开与3036动作加密均支付，3798≤4096。两循环编码、Acc、复制、解析和分派统一给8192；最多8个16步字段块、每步32动作仍在此帽内。

同一个源的全部每i上界因此为

~~~text
C_chain ≤30·50176+259328+133032+4096+8192
        =1909928 <2^21.
~~~

所有坐标来自同一有限程序，没有混接不同算法的最便宜分量。

## 5. 完整准备、空间和已证域内切片

一次准备包括com_j生成、两层完整Hc、h_t歧义比较、mu、固定输入缓冲、代码和表装载、描述头及清零；后置包括完整签名/消息输出与实际短Verify。

可保守使用：

- 空间≤2^21个256位字。N个16B承诺按每byte一字保存不足2^19字；全部代码、输入、状态、签名、摘要和控制在该容量内。
- 固定代码≤2^17字、公开表≤2^13字。有限核与短循环小于这个容量；24位静态地址/控制字段和128位字面量可放进256位指令字。加载IO、清零RAM与复制RAM分别低于2^26。
- 两层Hc、mu和固定上下文的一次输入总量<2^19B，调用数<32；含padding置换数<2^12，因此规范核<2^28。其他复制/吸收/输出、边界和叶生成各可封于2^27。
- 摘要歧义检查≤32²次32B比较，费用<2^20；最终拒绝输出、短H_mu和grinding首位检查<2^24。

上述固定项相加<2^32，所有准备和IO保留。由此

~~~text
W(A_chain) ≤2^32+1909928q,
Space(A_chain)≤2^21 words, RNG(A_chain)=0,
a_IC=q, a1≤q, a2≤q, Q=a_s=0.
~~~

Source自身流式空间不免除归约的完整历史、水位、输入及索引费用。

取q=2^116，则T*=3036·1024·q=3108864q。因3108864−1909928=1198936，固定2^32及下节2^48后缀均有充分余量。因此完整链源在q116确实进入固定候选域。

取q=2^118时，阈值是777216q；本稿1909928q的上界未证明入域。**较大费用上界也没有证明真实程序必超预算。** 精确成本可能另行收紧，但本稿不以尚未证明的收紧登记q118入域，更不修改规范定价。

## 6. 非零接受后缀及其有限意义

将A_chain的后缀换为：选m1=enc128(1)，采样全部8sigma个独立均匀位形成完整签名，把delta的g个grinding高位置0，然后输出(m1,sigma)。称为A_chain^+。全部开示seed、洞承诺、c、ut、d、QS字段、iv_pre和counter都存在于足长字符串；没有只猜摘要而省开示。Q=0满足最终消息从未请求Sign的规则。

对手没有sk，没有Sign或H_s调用。以下只用隐藏见证作支持集证明：对真实KeyGen给出的有效见证，考虑同一随机对象上一份诚实Sign(m1)的counter0签名。前缀没有HDelta查询，所以其counter0回答是新点；grinding高g位为零概率2^-g，GGM开示在此条件下总成功，真实关系保证完整Verify接受。随机输出在所有高g位为零的足长字符串上均匀，恰好等于这份分析签名的条件概率2^{-(8sigma−g)}，因此

~~~text
Adv_sig(A_chain^+) ≥2^-8sigma >0.
~~~

这个耦合未把隐藏见证交给对手，不假设KeyGen秘密边缘均匀或原像唯一。

完整Verify后缀另收2^48的宽松有限帽。依据[推进03核心完整Verify](../../%E6%8E%A8%E8%BF%9B03/%E6%A0%B8%E5%BF%83/01_%E6%A8%A1%E6%8B%9F%E9%AA%8C%E7%AD%BE%E4%B8%8E%E6%9C%80%E7%BB%88%E6%8F%90%E5%8F%96%E6%A0%B8%E5%BF%83%E6%88%90%E6%9C%AC.md)：F(z)七项总价448(z+1)<512(z+1)；代R≤4、r≤7、N<2^15、A_V<2^18、D<2^7、tau<2^5、k_max≤12、L<2^10，V_rec<2^44，其余本地项合计<2^44，含公开初始化可取<2^46。IC价格和边界<2^34；全部RO输入<2^20B，用冻结规范核、包装和边界仍<2^34。8sigma<2^16随机位、全部字段构造和输出也<2^34。额外≤2^24指令/数据字的加载IO<2^33、清零/复制<2^30；总和<2^48。

故q116时

~~~text
W(A_chain^+) ≤2^32+1909928q+2^48 <T*,
Space(A_chain^+)≤2^25 words, RNG(A_chain^+)≤8sigma.
~~~

这个粗帽计入完整最后Verify的最多A_V个IC、tau+6个RO以及新增Source记录；不是性能估计。其接受概率极小，最终有效链通常不对应前置的任意旧链。它没有给LateFinal∩Accept∩Fail_B的有用下界。

另有一个q118入域的非零支持例子，但要保持身份区别：给**推进04原A_q**附加同一个完整随机签名后缀，原冻结费用为2^24+756736q，q=2^118，故

~~~text
2^24+756736q+2^48 <777216q=T*.
~~~

同样的支持集证明给正接受概率。该原前缀没有Hc旧前像，这个例子不拥有本稿完整旧链性质。两者不混写。它们只排除“非零成功算法天然查询预算小”的推理；事件限定应落到实际最终接受轨迹。

## 7. 首现占用是本稿源能被新界识别的原因

原子alpha=(xC,c0,c1)在首个合规H1出现时，o0/o1表示Source已观测桶占用，Z0/Z1为未观测部分。不同key剩余置换独立；同key在固定xC只输出一个值。

c0≠c1时，同key指示互斥，故

~~~text
E[(o0+Z0)(o1+Z1)|H] ≤(o0+lambda)(o1+lambda).
~~~

c0=c1时父两输出必须不同，正确分子是阶乘矩：

~~~text
E[(o+Z)(o+Z−1)|H] ≤o(o−1)+2o lambda+lambda².
~~~

对A_chain全部合规旧H1之前没有IC行，所以o0=o1=0且lambda=1，两式都≤1。IV和Hc列表只经独立RO选定，未额外限制辅助IC。单列Genie与原子并合因此给Pr[union L_alpha]≤q0 Jbar/den，未含旧PM7的高桶mu2。

该条件矩识别了“J很大、首现占用很小”的区别。[有效链首现稿](../%E6%9C%89%E6%95%88%E9%93%BE/01_%E7%9B%AE%E6%A0%87%E5%8E%9F%E5%AD%90%E9%A6%96%E7%8E%B0%E4%B8%8E%E6%9C%89%E6%95%88%E9%93%BE%E7%9A%84%E6%9D%A1%E4%BB%B6%E7%9F%A9%E7%95%8C.md)进一步证明：在Q=0、无IC前缀、q118查询计数的轨迹类，六组Parent<1/64。该数学轨迹类结论本身成立；本稿并未据此证明这个具体完整链源在q118进入冻结价域。

随机首现数量需作可测加权积分；一次观测到小J或小权重总和也不自动成为整个源类的先验上界。
