## 2. 一个费用更紧的普通Rain枚举程序

这里给出正常逐候选枚举在固定256位机器上的另一种标量实现。它只用于审查普通原语假设；原030源码、签名程序和速度基线保持。它没有免费CLMUL、GF乘法、GF平方、求逆或矩阵指令。

### 2.1 GF64乘法与模约减

底域为GF(2)[x]/(x^64+x^4+x^3+x+1)。a、b均保存于一个字的低64位。

先在一个256位字内形成128位无进位积，64步静态展开：

~~~text
p := 0
for j = 0,...,63:                 // 固定展开，无运行时循环
    t := (b >> j) AND 1
    mask := 0 - t                // 模2^256，得到全0或全1
    p := p XOR ((a << j) AND mask)
~~~

每步是5个BIT及1个SUB，共384动作。所有中间积位≤126，不发生256位字截断。输入与输出读写、低64位约束、头尾及暂存分别保留，未作为免费函数参数处理。

定义φ(h)=h⊕(h<<1)⊕(h<<3)⊕(h<<4)，其实现需3次移位和3次XOR。对任意p<2^128，

~~~text
h := p >> 64
t := phi(h)
v := t >> 64
z := (p XOR t XOR phi(v)) AND (2^64-1)
~~~

共1+6+1+6+2+1=17个BIT。证明是x^64≡1+x+x³+x⁴：首次折叠的t至多68位，v至多4位，φ(v)至多8位，第二次折叠后再无64位以上项。这个公式不是整数乘法或带进位约减。

为完整输入、输出、暂存和返回再给至多32动作；即使额外进行固定掩码与几个MOVE，也远小于下面的统一帽：

\[
C_{M64}\le640.
\tag{M64}
\]

### 2.2 GF64平方

在特征2中，平方是把原第j位搬到第2j位。先把低64位放入128位区，依s=32,16,8,4,2,1执行

~~~text
x := (x OR (x << s)) AND D_s
~~~

其中D_s在128位内每2s位保留低s位：

\[
D_s=\sum_{j=0}^{128/(2s)-1}(2^s-1)\,2^{2sj}.
\]

六个D_s为公开128位静态字面量，连同代码加载付费。每步3个BIT，共18；得到的数恰为未约减平方。再执行前节17个BIT的约减。35个核心动作加输入/输出、头尾和暂存后使用

\[
C_{S64}\le64.
\tag{S64}
\]

例如s=32首先保留低32位及第64—95位，随后逐级分开16、8、4、2、1位组。这说明六步确实执行位交错，没有假设一个免费的bit-spread指令。

### 2.3 64位与128位公开线性层

公开矩阵按列保存，一列至多128位，可置于一个256位字。对n=64或128的输入x，静态展开n步：

~~~text
acc := 0
for j = 0,...,n-1:
    bit := (x >> j) AND 1
    mask := 0 - bit
    col := LOAD(C[j])             // 静态地址，仍支付LOAD
    acc := acc XOR (col AND mask)
~~~

每列1 LD、4 BIT、1 SUB，共6动作。输入/输出、头尾和暂存另留32，故可取

\[
C_{L64}\le512,\qquad C_{L128}\le1024.
\tag{LIN}
\]

源文件的每个128位列由两个64位数组成；一次准备时将其打包成一个字，打包和表装载已列入第2.5节。程序运行时没有免费动态地址计算；列地址静态展开，常数字面量随代码装载。

### 2.4 单次tinv及完整候选核验

冻结rain_owf.hpp的inv64链为

~~~text
1,2,3,6,7,14,15,30,31,62,63
~~~

其中到30与62的平方幂分别用SQ15、SQ31公开线性映射实现。逐项计数，inv64内含10个M64、17个S64及2个L64；外层范数与回代再含4个M64、2个S64和3个XOR64。因此tinv总计

\[
14M64+19S64+2L64+3XOR64.
\]

该计数与推进03核心稿第8节相同，本轮只更换普通枚举程序的实际底层实现。给外层范数、回代、保存中间b_i、参数和返回额外256动作，得到

\[
C_{\rm tinv}\le
14\cdot640+19\cdot64+2\cdot512+256=11456.
\tag{INV}
\]

输入0的链仍给0，与总化forward相同；候选核验另外逐轮累积零输入标志，只接受全部非零的候选。

对R≤4，每个候选最多4次tinv和3次L128。另给1024动作覆盖全部轮常数/状态/密钥读写与异或、128位pack/unpack、R次零检查、最后C比较、循环密钥加1与低128位截断、候选计数及成功/失败出口。轮数固定，除枚举外不需要长运行时控制循环。这些外层操作只有O(R)个定宽字段动作；32个固定字段块、每块至多32动作即可覆盖1024。

于是一个完整候选步骤满足

\[
C_{\rm key}
\le4\cdot11456+3\cdot1024+1024
=49920<2^{16}.
\tag{KEY}
\]

该值是这个具体程序的上界。它不说明每个攻击必须执行一次forward，也不把这49920个动作重新命名为新的安全强度单位。

### 2.5 全部代码、常量、IO、随机性与空间

在真实(P,C)上独立均匀抽128位J，依次检查K=(J+i) mod M，i=0,…,n−1，n≤M；遇任意有效原像即输出。得到完整费用

\[
\boxed{
W(E_R(n))\le2^{26}+2^{16}n,\quad
S(E_R(n))<2^{17}\ {\rm words},\quad

\tag{ENUM}

这里W已包含全部RAM、RNG与IO，不再另把随机位或代码IO丢掉。每个RAM坐标分别也被同一个总数支配。RO与IC调用均为0。

每个真实生成K被独立均匀起点的n长循环段包含的概率恰为n/M；其他有效原像只增成功率。因此

\[
\operatorname{Adv}_{G_R^+}(E_R(n))\ge n/M.
\tag{SUCCESS}
\]

n=M时，无论公钥来自哪一个有效原像，完整枚举必成功，优势恰为1。该成功结论没有理想随机函数、唯一原像或均匀秘密边缘假设。

## 5. 有限必要条件及应当停止的具体路线

由式(ENUM)可以给一般资源球一个无需扫描的必要筛选。若普通标量预算W允许相同空间/IO，令

\[
n_W=\min\left\{M,\max\left\{0,
\left\lfloor\frac{W-2^{26}}{2^{16}}\right\rfloor\right\}\right\}.
\]

那么任意有效原语上界h_R(W)都须满足

\[
h_R(W)\ge n_W/M.
\tag{NEC}
\]

特别地，试图给h_R(W)<1/2的充分证书至少要避免W≥2^26+2^15M；试图给h_R(W)<1则至少要避免W≥2^26+2^16M。这些是已知可执行程序强制的必要条件；区间未被排除时并不意味着困难性已证明，其他更强普通算法还可能提高下端。

因此，本轮应停止的具体路线是：

> 保留推进03现有完整普通资源帽，在整个759M源域上直接换一个更强H_unit系数或另填一个p_R<1，期待新Parent界自动结清整个证书。

这一阻碍有两点区别于推进04：它不只是某条未证猜想的包络提前饱和；它由一个给出全部代码/IO/空间费用的实际普通枚举程序反驳该资源球上的所有p_R<1。它也不依赖Q=0时已经停用的旧H_s列表检测地板。

但以下方向仍有逻辑空间：

- 给同一程序证明更紧的**实际**资源帽，或改进本地模拟/提取实现并重新给出整条费用，避免把大量未利用的能力放入普通资源球。
- 对最终有效事件给更直接的安全归约，且真正控制普通求逆算法的全部资源。
- 提出独立、有明确生成与计费规则的受限原语模型，再证明当前归约属于它；这属于新的接口和前提，不能从普通Rain标签自动取得。

前两项可以改变本文固定公式；第三项改变被保护的算法类。本文没有将这些尚待证明的方向当作已取得净收益。

## 6. 来源相关或关系辅助前提的边界

某个辅助记录T由公开挑战X=(P,C)和源程序生成，不因其所用随机币/IC与X独立就自动与X独立。若T=Gen(X;r)，对T的普通求解器D可合成为普通算法D(Gen(X;r))；从普通Rain困难性得到的合法资源接口仍支付Gen与D的全部费用。

如果仅把Gen的耗时说成“证明工作”并免账，就没有从普通困难性得到这一合成。反例接口很直接：允许任意公开Gen免费运行时，它可执行式(ENUM)的全枚举并把K放进T，接收方只复制即可成功。这个反例针对这种泛化接口，不是当前真实SALT轨迹。

另一方面，专门限制到C_L,m[A]的某个来源类不必在逻辑上自动循环；但要回避RB，就必须明确说明为何普通枚举被排除，且给独立的成功率依据或一个资源受控的非放大归约。把此类的上界定义为p_ref减本项目误差，仍只是待证明结论的改名。旧B_final的任意H_s输入即检查机制也不能原样用于当前Q=0的SALT；本文的排除没有作这种错误继承。

现有冻结Rain文献支持保留有条件128档设计评价，但其特定攻击复杂度不是普通资源球下界。本文不从2^139.07等昂贵攻击估计补出RB所排除的p_R<1记录，也不要求普通计算猜想先取得无条件困难性证明。当前最有判别力的是改掉已明确失效的资源球接口，而不是重复寻找一个能填进去的概率数字。

## 7. 核查点、范围与阶段分类

独立审查应优先反驳：

1. 两次GF64模折叠、六级平方交错和塔域/PK编码是否与真实Rain相同。
2. 64位/128位线性层的每列动作、tinv的14/19/2计数、R≤4时49920候选帽及全部一次代码/常量生成装载是否遗漏。
3. IC-only源的完整边界和规范AES费用、q=M/32的允许域以及确定失败出口。
4. 式(BRIDGE)的系数、帽的数值方向、L任意性的范围，以及L128实例的所有资源坐标。
5. 是否把“归约帽容纳全枚举”误写为“原030在759M源预算内已经被攻破”。

枚举的完整上界约为65536M，本文只证明它进入放宽后的原语预算；没有证明它进入源目标759M。源A_q^IC的真实伪造优势恰为0。实际Rain优势和完整签名安全位数仍为null，严格等强UNESTABLISHED，作者同层级评价SUPPORTED_CONDITIONAL，总体目标active。

六判据：固定rFAEST EM128f/s与原030六组；机制是普通预算包含筛选；剩余空间在真正更紧的归约/资源界；关键步骤有有限程序和整数代数；不主张新密码学攻击；完整组合效果是排除一个无效证书接口，而非签名性能或安全位数提升。

五问：最强支持是完整枚举与逐坐标包含；最强反对是它仅针对目前公开保守帽；距强对照还差新的资源相容桥和完整事件界；剩余空间须实付其算法代价；更紧资源、正确反驳本推导或完整有效新桥会改变结论。
