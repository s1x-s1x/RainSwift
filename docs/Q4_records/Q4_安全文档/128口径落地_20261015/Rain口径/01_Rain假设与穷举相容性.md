# Rain 假设、有效原像与穷举相容性

2026-10-15；候选 `C030-RFAEST128-CALIB1`；分类：限额探索；分工：rain_hardness。本文只作源码、原文证据和数学核对，未执行构建、密码实验、跑分或参数扫描。

**本轮将 Rain 困难性项落实为实际拒零建钥分布上的“寻找任意有效原像”假设，并给出了该假设必须满足的通用穷举约束。既有证据支持将单点 Rain-128-3/4 继续作为128位设计目标的原语候选；它没有给出足以消除归约开销的额外安全位。现阶段没有发现针对原030单点 Rain 的低于枚举规模的已建立攻击，也没有从文献得到全部攻击成功率的数值上界。**

用户允许计算困难性假设。本文不要求无条件证明 Rain 下界，也不把严格逐预算、无常数损失的 `T/2^128` 证书增设为用户唯一验收门槛。与作者128位设计声明对齐的攻击谱论证，以及更强的完整优势曲线证书，应分别披露证据身份。

## 1. 真实实例、关系与密钥分布

原030的六组签名参数只使用两种原语：Rain-128-3 与 Rain-128-4。快、均衡、短的森林参数改变签名结构，未生成六种不同的 Rain 原语。源码对应 [parameters.hpp](../../../../../src/parameters.hpp#L317)。

令 `M=2^128`、`R∈{3,4}`，底域为固定的 GF(2^128)。写成多项式基时，关系为

\[
s_0=P,\qquad x_i=s_{i-1}+K+c_i,\qquad y_i=x_i^{-1},
\]
\[
s_i=L_i(y_i)\quad(i<R),\qquad C=y_R+K.\tag{R1}
\]

所有 `x_i` 均须非零。`P,C` 公开，`K` 有128位。见证包含 `K` 与前 `R−1` 个 S 盒输出；它们均可从有效 `K` 确定计算，见 [faest_keys.inc](../../../../../src/faest_keys.inc#L126) 和 [rain_owf.hpp](../../../../../src/rain_owf.hpp#L104)。塔域与多项式基之间为公开可逆表示转换，其费用需要计入实现，秘密熵保持原值。

源码 `rain3/rain4` 未置 `owf_flag_zero_sboxes` 或 `owf_flag_shrunk_keyspace`，见 [parameters.hpp](../../../../../src/parameters.hpp#L30)。因此实际 API 进入 [api.hpp 第44行](https://github.com/s1x-s1x/rain-voleith/blob/3f8b0f4/src/api.hpp#L44) 的循环：均匀重取整个32字节的 `P || K`，计算公钥，有零 S 盒输入时整对重取。`faest_keys.inc:129–131` 执行该拒绝。

用 `inv(0)=0` 扩展 Rain，定义事件 `E_R(P,K)` 为全部 S 盒输入非零。固定任意 `K` 后，异或、扩展逆及可逆线性层都保持从 `P` 到每轮状态的置换性，所以每轮恰有一个 `P` 使该轮输入为零。因而

\[
\delta_R:=\Pr_{P,K\leftarrow U_{128}}[\neg E_R]\le R/M.\tag{R2}
\]

实际建钥分布正是 `(P,K)←U | E_R`，而不是独立均匀的两个变量。每个 `K` 至少有 `M−R` 个可接受 `P`，故仍有完整128位密钥域的支持，不存在把域压缩成 `3·2^126` 的步骤。设 `r_K` 为该密钥的坏 `P` 数量，则

\[
\Pr[K=k\mid E_R]=\frac{M-r_k}{\sum_{k'}(M-r_{k'})},\qquad 0\le r_k\le R.\tag{R3}
\]

与联合均匀候选的总变差为 `δ_R`。同一具体 Rain 扩展游戏与其接受后版本之间，对于任意事件可以使用

\[
\Pr[S\mid E_R]\le\Pr[S]/(1-\delta_R),
\quad |\Pr[S\mid E_R]-\Pr[S]|\le\delta_R.\tag{R4}
\]

该修正是联合随机采样的分布结论，未声明任意人为指定 `P` 的逐点困难性。若困难性假设直接定义在实际接受分布上，就无需再把 `δ_R` 重复加进总界。

## 2. 可审查的困难性假设

令 `Rel_R(P,C,K',Y')` 表示式(R1)及全部非零约束成立。攻击成功条件为输出**任意**满足此关系的 `K'` 与中间值，而非必须输出最初抽中的 `K`。给定有效 `K'` 可以重算中间值，所以“输出有效密钥”与“输出完整见证”的区别是明确的有限计算费用。

定义

\[
\mathcal H_R(T,S,p):=
\sup_B\Pr[\operatorname{Rel}_R(P,C,B(P,C))=1],\tag{R5}
\]

其中：

- `(P,C)` 按实际拒零 KeyGen 生成；`B` 是经典、单公钥关系求逆算法。
- `B` 总工作量至多 `T`，峰值空间至多 `S`，可对与 Rain 挑战独立的普通双向128位理想密码作至多 `p` 次查询。
- 概率覆盖 KeyGen、`B` 的随机币和辅助理想密码。计入挑战前准备、数据结构、输入输出及可复用材料的实际成本；不授予免费巨型建议表。
- 预先固定工作量单位及最坏/期望费用约定。位运算、域运算、Rain 求值、AES 求值、墙钟秒分别列出转换依据，不按同价调用直接相加。

“采用 Rain 困难性假设”可以准确写为：对列明的资源域 `U` 与函数 `h_R`，

\[
\forall(T,S,p)\in U:\quad \mathcal H_R(T,S,p)\le h_R(T,S,p).\tag{H-Rain}
\]

这是可证伪的计算假设，不是假装已经证明的普遍攻击下界。函数应在查看验收结果前解释其依据，且须通过下一节的已知攻击相容性检查。`h_3` 与 `h_4` 分别陈述；增加一轮不自动产生可抵扣归约损失的若干安全位。

常见的线性时间—成功率假设，可以在统一的参考工作量 `W` 下写成

\[
h_R(W,S,p)=\min\{1,\kappa_R(W+1)/M\}.\tag{R6}
\]

这里 `κ_R` 和 `W` 的单位是声明的一部分，须覆盖有效原像数量、优化求值及预处理等影响。`+1` 保留最终未验证猜测。式(R6)提供可审查的参数化形式，**本分工没有给某个未经论证的 `κ_R` 签发 PASS，也没有把 `κ_R=1` 当作满128位密钥域自动推出的结论**。

独立辅助 IC 不应被默认为“真实 Rain 自带某种 AES 结构”。在经典模型中，它可由独立随机币和懒采样表模拟；若要从无辅助 IC 的困难性假设导入，需计入模拟时间和空间，并说明精确采样的费用约定。直接用式(H-Rain)声明独立辅助 IC 版本，则该模型前提已经明示。现有代数攻击论文没有给出这个三变量函数的完整上界。

## 3. 穷举相容性的硬约束

对任意实际生成的公钥，至少存在真实 `K` 这个有效原像。选均匀128位起点 `J`，按模 `M` 的循环顺序测试 `q≤M` 个不同密钥。对每个固定的真实 `K`，都有

\[
\Pr_J[K\in\{J,\ldots,J+q-1\}]=q/M.\tag{R7}
\]

出现任何有效原像就停止。因此，这个经典、常数数量字段存储、无辅助 IC 的算法有成功率至少 `q/M`。该结论逐个密钥成立，**拒零后的密钥轻微偏差不影响它**。前 `M` 次测试保证成功；随机起点测试至原生成密钥的期望位置为 `(M+1)/2`，其他有效原像只会更早停止。

令 `T_test,R(q)`、`S_test,R(q)` 为某个明确枚举实现的完整费用上界，包含拒零判断和关系验证。只要

\[
T_{\rm test,R}(q)\le T,\quad S_{\rm test,R}(q)\le S,
\]

就必有

\[
\mathcal H_R(T,S,p)\ge q/M.\tag{R8}
\]

这里是已知算法给出的**可达到成功率下界**；不需要也不使用128位大规模实跑。若允许最后输出一个未测试候选，还可把它计入候选数，费用另行说明。

有效原像可能不唯一。固定 `(P,C)` 若有 `m` 个有效密钥，均匀独立有放回试探 `q` 次的成功率为

\[
1-(1-m/M)^q.\tag{R9}
\]

这说明“找回原密钥”和“找到一个有效原像”的成功率常数可能不同；满128位输入域并不保证 `m=1`。

为了显示该常数差异，考虑一个**单独标记的理想模型**：随机函数 `F:D→[M]`，`|D|=D`，随机 `K∈D`，挑战 `Y=F(K)`。固定测试 `q` 个不同候选，候选集不依赖未知函数值。植入密钥在集合内的概率为 `q/D`；否则，集合中的函数值独立均匀。因此精确成功率是

\[
p_{\rm RF}(q)=1-(1-q/D)(1-1/M)^q.\tag{R10}
\]

`D=M,q=1` 时为 `2/M−1/M²`，不是 `1/M`。多出来的项来自其他有效原像；该挑战分布对大原像桶有偏重。

对照原语的另一个独立理想模型为均匀置换 `Π`、秘密域 `S⊆[M]`、`|S|=D`、`Y=Π(K)⊕K`。一个固定候选 `K'∈S` 的精确成功率是

\[
p_{\rm EM}(1)=\frac1D+\frac{D-1}{D(M-1)}.\tag{R11}
\]

证明：`K'=K` 时成功；否则其目标 `Y⊕K'` 与已经占用的 `Y⊕K` 不同，故从剩余 `M−1` 个像中命中率为 `1/(M−1)`。当 `D=3M/4` 时，首阶常数约为 `7/(3M)`。多候选事件在置换中相关，禁止以独立 Bernoulli 事件直接相乘。

式(R10)/(R11)仅是明确模型内的通用试探公式，既不是实际 Rain 的原像分布定理，也不是完整 rFAEST 的安全定理。它们说明作者惯用的“128位”工作因子通常容纳常数与成功率约定。真实 Rain 的式(R2)仅比较实际扩展 Rain 与实际拒零分布；没有中间状态的理想随机函数不会自动继承该拒零修正。

## 4. 代入本项目 ST 时会出现什么证书损失

既有 [ST 总稿](../../%E5%85%B7%E4%BD%93%E7%95%8C%E6%8E%A8%E8%BF%9B_20261015/02_%E7%A2%B0%E6%92%9E%E5%AE%B9%E5%BF%8D%E8%A7%81%E8%AF%81%E6%8F%90%E5%8F%96%E4%B8%8E%E5%AE%8C%E6%95%B4%E6%80%BB%E7%95%8C.md) 给出

\[
\operatorname{Adv}_{030}(A)
\le\min\{1,\mathcal H_R(T_B,S_B,\bar P)+\epsilon_{\rm ST}\}.\tag{R12}
\]

必须评价同一个实际归约 `B` 的资源。它的 Full IC 系数为 Rain-3 的138、Rain-4 的174，另有来源执行、聚合、VHash、字典、输入输出、Rain 核验及内存；这些 IC 系数本身不是总时间放大率。

若仅作解释性的共同单位假设：`T_B≤αT_A`，采用 `h_R(T)=κ_R T/M`，且未到截断区间，那么证书变为

\[
\operatorname{Adv}_{030}(A)\le\kappa_R\alpha T_A/M+\epsilon_{\rm ST}.\tag{R13}
\]

对应可认证的时间—成功率比为

\[
W_{\rm cert}=\frac{M}{\kappa_R\alpha+M\epsilon_{\rm ST}/T_A}.\tag{R14}
\]

这展示归约认证的损失，没有建立同费用的签名攻击。若目标被另外规定为严格 `p_ref(T_A)=T_A/M`，则 `κ_Rα>1` 已使这条充分界难以达到该更强目标；但用户接受的 rFAEST 作者声明未必要求此无常数损失的逐预算曲线，须按参考分工核实的实际声明处理。

更一般地，令 `q_Γ` 为预算 `(T_B,S_B,bar P)` 内能实际实施的上述枚举候选数。任何资源统一假设给出目标证书的必要相容条件为

\[
q_\Gamma/M+\epsilon_{\rm ST}\le p_{\rm ref}(v).\tag{R15}
\]

若式(R15)失败，写下一个更小的 `h_R(T_B,S_B,bar P)` 会与已知枚举算法冲突。正确处理是报告该资源统一证明的认证缺口，考虑更紧归约或真实参考声明允许的口径；不把 Rain-3 文献中的 `2^139.07` 攻击估计当作139位普遍困难性来强行抵扣费用。

## 5. 只按 Rain oracle 查询数计费是否能绕过放大

本项目的归约额外明确调用完整 Rain 关系检查的次数，来自每个合格 H2 至多一次及公开 H_s 检测。形式上可以写成

\[
q_R(B)\le q_R({\rm src})+a_2+a_s+q_{\rm final},\tag{R16}
\]

其中 `q_final` 须根据计价接口逐项定义，避免把最终验证、局部约束与完整求值混算。这个调用账与整个 `T_B` 是不同对象。

若另外把 Rain 替换为不可读取内部结构的独立随机函数或理想密码，并在对应模型证明攻击成功仅受 `q_R` 控制，那么胶水代码的 CPU 消耗可能无需逐步折算为 Rain 猜测次数。这是有明确用途的**另一种模型**。

它目前不自动适用于真实原030，原因具体为：

1. 真实 Rain 的常数、线性层和域运算全部公开。攻击者可以本地计算 Rain，或直接求解公开多项式系统，完全不调用人为提供的 Rain oracle。只计显式 API 次数而不计等价本地运算，会把实质计算藏进免费区。
2. 原030的 QuickSilver 检查真实 `x_i y_i=1` 等低度代数约束。完整黑盒理想函数不自带这些固定轮数的见证关系。把它换入原语层之后，ST 中“最高次系数给出真实 Rain 关系”的接口需另建证明。
3. 若既保留公开低度关系、又直接假定本地计算对求逆毫无帮助，便新增了结构性困难性假设。它应独立分析并能被代数攻击反驳；“B的额外工作本意是提取”本身并未证明该假设。

因此，式(R16)可以保留为寻找更紧资源定理的方向。现有证据未给出一个已经验证、足以抹去 `α` 的 query-only 替代。也不推荐把“所有由A产生的B都特别难求逆”作为未经独立依据的专用假设来取得 PASS；该说法可能只是重新包装待证明的签名安全性。
