# rFAEST作者的128位声明：证据、成本口径与验收含义

2026-10-15；候选 `C030-RFAEST128-CALIB1`；分类：**限额探索**；分工 reference_standard。本稿为只读证据核查及数学判断，未运行密码实验、构建、参数扫描或性能测试，未改协议与源码。

**核查结果：rFAEST确实把表1中的两组EM实例称为128位安全级别；其提供的是经典ROM/理想原语下、仍带OWF/PRF等假设项的条件归约和参数选择理由。原文没有同时给出统一机器工作单位、固定成功率门槛和完整逐预算优势曲线。把“每一个预算都严格满足优势≤工作量/2¹²⁸”设成Q4唯一关卡，会比作者实际给出的声明更强。这个发现只纠正验收解释，并不把原030自动判为具体等强PASS。**

研究目标仍是用户确定的“与rFAEST声称的具体安全水平相当”。以下区分作者实际声称、原文支持范围及本项目推论。NIST类别1、完整QROM、重新证明参考EM均未增加为要求；原030六组及历史C1R1保持各自身份。

## 2. rFAEST究竟声称了什么

| 问题 | 原文及定位 | 可以据此认定的范围 |
|---|---|---|
| 是否明确声称128档 | R p9 §4.3：**“at the 128-bit security level”**；文本1031–1041。表1标题为 **“Performance comparison between 128-bit parameter sets”**；1028–1030 | 这是作者的明确设计级别声明。表1两组EM为f：4980字节、s：4014字节，1023/1027行；128不是从签名长度倒推出来的。 |
| 正式安全游戏 | R p8 Thm4.3；978–1002；附录G重述2514–2532 | EUF-CMA，给定一个公钥、攻击者可请求签名。定理参数为签名查询Q_sig、总RO查询Q、理想原语查询Q_P；存在正整数u和归约对手B、C。 |
| 定理使用的模型 | 同一定理称 **“modeled as random oracles”**、**“PPT adversary”**；F_ctr实例化在R p6，688–696行 | 经典ROM；F函数的条件以理想原语表示，CTR实例使用理想密码。OWF项和密钥前缀H₃的PRF项仍是显式假设/优势项。不是实际AES/SHAKE的无条件安全定理。 |
| 证明允许怎样的损失 | R p8定理后的参数讨论，1003–1013行：**“The additional loss due to VSC is then roughly”**，随后为 NQ/2^λ + τ(k+2)Adv_prg(F) | 作者在宣称128档时仍披露N、τ和查询量依赖的损失。其u=λ、B_fast=40位、B_short=48位等选择控制参数依赖；没有声称全部损失恰好等于零。 |
| 是否给出实际机器归约时间 | R p6 Remark，667–676行谈理想原语查询可换为 **“time resources allocated to A”**；p8/附录G则只称PPT B、C | 给出了计算假设的解释方式；未在所核全文中定位到将B/C时间、内存、AES、SHAKE、域运算统一为带固定常数机器工作量的总表。表1的毫秒是诚实Sign/Verify性能，不是攻击工作因子。 |
| 有没有固定的全局成功率门槛 | Thm4.3给优势函数；p9的128档声明没有另附p=1/2、p≈1或T/p的统一定义 | 可读出带查询参数的条件概率界；未发现把128声明绑定到唯一常数成功率和唯一攻击费用标尺的完整约定。不得自行补写成作者定义。 |
| 是否已经证明QROM | R p11 §4.5；1395–1399行：**“The current ROM proof does not lift directly.”** 以及 **“leave QROM security for future work.”** | 当前正式证明是经典范围。引用其128标签既不要求本项目多交一份QROM，也不证明双方量子安全实际相等。 |

R的Thm4.3保留了 `Adv_OWF(KeyGen; B)`、`Q_sig Adv_PRF(H₃; C)`、F函数的PRG/碰撞/多碰撞/4-XOR项，以及VHash、ZHash、QuickSilver项。定理给出的是一个可代入的**条件**优势表达式；作者没有将这些全部数值化为一个覆盖任意使用预算的最终128位证书。

R p6 Lemma3.6还明说其若干组件界为非紧结果（744–745行）。这进一步说明，取某一个误差界负对数并直接称其为算法的真实安全位数，既不符合数学含义，也不忠于作者的表述。

**特别保留的限制：**本项目此前已发现参考论文某些组件印刷界及纸面地址到源码的映射存在问题。本文核查的是作者到底声称什么，不重新认可这些旧界。原文错误公式保留为历史证据，不能作为“双方都代入旧式，故已等强”的共同证书。

## 3. FAEST v2如何使用“128档”这一说法

FAEST v2是R §4.3明确使用的基础，因此可用于理解其128档背景；F的完整QROM成果不自动转移到rFAEST，更不自动转移到原030。

1. **正式证明以查询复杂度作粗粒度量尺。**F p4，109–113行，称 **“the coarse-grained attack complexity measure of query complexity”**，并说所得破坏查询界 **“is close to the bit security target”**。这不是对每个机器和每个预算给精确的T/2¹²⁸上界。
2. **它容纳明确披露的穷举常数。**F p61 §9.1.1，3381–3392行，作者估计公钥求逆费用介于2^(λ−2)与2^(λ−1)次AES-λ评估，仍将λ=128实例列在128档。原因包括秘密域与有效其他原像。F p67 §9.2.4所述约0.5位损失专指3/4秘密域，和前者“同时考虑其他原像”的1–2位讨论范围不同。
3. **成功率和费用在具体攻击讨论中分别出现。**F p62 §9.1.2，3421–3424行，对PRG密钥恢复说约2^λ次AES评估得到 **“a success probability close to 1”**。这是一项攻击讨论的口径，不是R为其整个EUF-CMA定理统一规定了p≈1。
4. **SHAKE调用和AES评估没有被当成免费同价操作。**F p62 §9.1.3，3442–3456行，讨论2^λ/τ与2^λ/3量级的尝试，并结合SHAKE比AES昂贵说明其攻击比较。把这些指数中的常数损失直接当成“作者不符合自己所称128位”并不忠于它的实际分析方式；反过来，也没有理由把任意大的损失都当成获准容忍。
5. **使用规模并非无限。**F p62 §9.1.2对多签名的文字讨论涉及Q_sig<2^64的IV唯一性背景（3425–3434行）。这不是本项目用户选定的寿命，也不是R提供了一条适用于无限签名的统一保证。实际适用的预算与IV碰撞应随论证披露。

F p13把λ∈{128,192,256}和NIST类别对应起来，是来源背景事实。本项目用户已把本轮标准指定为rFAEST所声称的具体水平；该背景不重新增加NIST认证或类别验收。

## 4. 对现有ST与资源付费工作的影响

ST和实际资源账是有效且重要的成果。其结构为

\[
\operatorname{Adv}_{030}(A)\le
\operatorname{Adv}_{\rm Rain}(B_{A,u})+\epsilon_{\rm ST}(A,u).
\]

如果希望从这条归约**证明某条明确选定的具体优势曲线**，则必须在B的实际资源处代入Rain假设，再加全部误差；即上一阶段的

\[
H_{\rm Rain}(\Gamma(v,u))+\epsilon_{\rm ST}(v,u)\le p_{128}(v)
\]

是恰当的充分验收条件。省略提取开销、将OWF项设零或采用与穷举相冲突的Rain假设，都不成立。

但是R并没有提供一个唯一、完整、可从原文原样拷来的p₁₂₈(v)。因此，**这条充分条件不等于“作者128档声明的唯一必要定义”**。它也没有允许我们自行取p₁₂₈(v)=2⁻¹²⁸，或取p₁₂₈(v)=T_A/2¹²⁸并声称这是用户已经指定的逐预算标准。

同理，某些预算点上ST的加法界大于选定目标，说明这一归约未给出那条目标曲线的证书；它既不是完整攻击，也不是原030已被证实低于作者所称档位。若有直接攻击或更紧归约，可另行改变判断。

有限性能实现和全套测速也不是这一步的逻辑前提。若只比较数学模型中的原语调用和显式假设，现在即可继续Q4。若进一步声称精确CPU周期、AES等价工作或硬件成本，则需要为所用换算提供证据；那属于该具体成本结论的证据，非必须先把签名程序重新实现一遍。

## 5. 忠于原目标的可审查接受条件

本稿建议沿用**作者实际给出的证据层次**推进，不增设严格逐预算定理为唯一关卡，同时保持“具体安全水平相当”所需的实质检查。两种成果须分别命名：

| 成果 | 需要的证据 | 可用表述 |
|---|---|---|
| 与参考同类证据支撑的128位设计安全声明 | 真实协议的完整经典条件论证；Rain单点关系的明示128档计算假设及现成攻击核查；对所有改变的结构、域、随机带、挑战和使用规模给出具体参数评估；逐项说明哪些差异影响实际攻击、哪些只是归约损失 | “在列明假设与模型下，支持与rFAEST所声称128档相当的设计安全评估”，并列明尚未给出紧数值证书的范围。 |
| 某个明确成本/成功率范围内的严格具体等强证书 | 在统一单位与成功率口径下，用完整ST或其他正确论证给出有效数值界；标明覆盖的预算、常数、内存和使用规模 | “在这些明确预算与假设下，已经数值证明达到所列标尺”。此项强于只有参数标签，且可能强于参考论文实际完成的数值化程度。 |

第一行不是“没有攻击就通过”，也不是“λ同为128就通过”。至少还须交出以下可核对材料：

- **完整协议与计算假设清楚。**以实际原030关系和KeyGen分布为准，区分Rain计算假设、ROM/IC模型与实现侧信道。单凭原语名为Rain-128不足以定案。
- **变动没有偷换安全代价。**引用已有六组源码映射、VHash/ZHash/QS同条件比较，并把随机带缩短、共享地址和签名模拟的完整ST证据接上。某局部更优不足以推出整个方案同强。
- **真实攻击费用与证明损失分开评估。**覆盖公钥求逆、隐藏种子/PRG多目标、承诺歧义如何形成有效伪造、声健挑战与grinding、多签名/IV及公开密钥绑定等相关路径；未核范围如实列出。不得把“存在可利用组件事件”直接写成同成本完整伪造，也不得把未找到攻击写成普遍下界。
- **具体对照有共同量尺。**对关键路径至少同时给出工作量、成功率、存储或使用预算的角色。不同原语操作量分别保留；只有有依据时才作等价转换。参考论文未给出的容忍常数不能由本稿随意选择。
- **结论与证据匹配。**原030的完整精确曲线若仍缺证，就保留这一限制；对作者同类设计声明的判断则基于完整证据集合，而非要求它必须先通过比参考更强的万能曲线。

本稿只完成来源口径核查。Rain假设、关键攻击路径与六组总评由本轮其他分工及主报告合成；在它们完成之前，**本稿不单独授予Q4 PASS，也不把原030判为降强**。本文没有修改上一阶段的历史判定。
