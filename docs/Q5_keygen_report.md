## 结论

**Q4 证明不需要改动。** 只替换了建钥中 Rain 正向计算的算法实现，所计算的函数不变：同样的随机字节产出逐字节相同的公私钥，随机源用量和零输入拒绝规则也不变。以下几项都已核实：

- 新构建上 Q2 的 T1–T8 测试，B1=0 与 B1=1 各一遍，全部通过。
- 六组签名 KAT（两种 B1 配置）与 Q2 入库文件逐字节相同。
- 经新建钥实现生成的库方式 KAT，与冻结源码的输出逐字节相同。
- 新旧实现差分测试 8,813 万次对比，0 不一致。
- 机器码比对：整个 Rain 库只有建钥函数 `faest_pubkey` 不同，签发、验签以及约束证明、VOLE、承诺的全部函数逐条指令相同。

**实测（同机同窗口、完整 API 调用，四项指标全部重测）：**

1. **建钥现在快于 FAEST v3 和 rFAEST（Rain-4 短档除外，为持平）。** 主窗口中，Rain-3 快档、均衡档为 1.022／0.992 µs，Rain-4 快档、均衡档均为 1.142 µs；同窗 FAEST v3 为 1.183 µs，rFAEST 为 1.173 µs。短档：Rain-3 为 1.092 µs，Rain-4 为 1.242 µs；同窗 rFAEST-128s 为 1.233 µs，FAEST v3-128s 为 1.222 µs。与对照的时间比（三个窗口）：Rain-3 为 0.77–0.87，Rain-4 为 0.88–0.97，Rain-3 短档为 0.88–0.91，Rain-4 短档为 1.00–1.03。Q3 时这些比值为 1.00–1.28。
2. **Rain 建钥本身比 Q3 快 18%–30%**（1.243→1.022、1.253→0.992、1.503→1.142、1.493→1.142、1.553→1.092、1.563→1.242 µs）。
3. **签发、验签、签名与 Q3 一致。** Rain 主窗口的签发、验签比 Q3 为 0.97–1.00，签名字节完全相同。各项与对照的加速倍数基本不变：例如 Rain-3 快档相对 rFAEST-EM-128f，签发快 3.03 倍，验签快 2.49 倍。

参考线（只作参考）：快档、均衡档的全部参考线**都达到了**。其中“均衡档四项都不输 FAEST v3 与 rFAEST”在 Q3 时缺的是建钥，现在 Rain-3、Rain-4 两组均衡档四项都达到。“建钥不慢于对照 1.05 倍”在 F、S 两个窗口全部达到，Rain-4 短档为 1.007／1.016。

## 1. 改了什么

冻结源码、Q2 工作副本都没动。Q5 工作副本 [源码/rain-voleith-q5kg](../src/) 由 Q2 副本复制而来，相对 Q2 副本只有四处不同：

| 文件 | 改动 |
|---|---|
| rain_kg.hpp（新增） | 建钥专用的 Rain 正向计算 `rain::kg::forward<R>`，与 `rain::forward<R>` 是同一函数 |
| faest_keys.inc | `faest_pubkey` 的 Rain 分支改调 `rain::kg::forward`（增 3 行、删 1 行）；签发中重算见证的 `faest_compute_witness` 仍用原实现 |
| q5_kg_test.cpp（新增） | 新旧实现差分测试与组件微基准，只用头文件 |
| meson.build | 新增测试程序目标 |

`rain_kg.hpp` 中三处实现改进如下（写法由服务器组件测试选定，见[追加记录](Q5_component_tests.md)）：

- **线性层与多次平方表**：原实现每次迭代在通用寄存器里构造位掩码。现在各通道预先放好 x、x>>1、…，统一做立即数左移，把待测位移到符号位，再用 vblendvpd 按符号位常数时间选列，全程留在向量寄存器。
- **GF(2^64) 求逆**：加法链沿用原实现的 1,2,3,6,7,14,15,30,31,62,63。2^7、2^15、2^31 次幂改为查线性表，其中 2^15、2^31 两张表就是冻结常数 SQ15、SQ31；2^7 表在编译期生成，并由编译期断言与冻结常数互相核对。
- **模约化**：第二次折叠不足 3 位，用寄存器内 16 项 pshufb 表完成，省去一次 clmul。

常数时间写法保持不变：除既有的“零输入则重取”外，没有依赖秘密的分支，也没有以秘密为下标的访存。

| 组件（服务器链式调用中位数） | 原实现 | 新实现 |
|---|---:|---:|
| 128×128 线性层 | 88.4 ns | 29.6 ns |
| 塔域求逆 | 158 ns | 117 ns |
| 正向计算 R=3 ／ R=4 | 651–664 ／ 896–917 ns | 411–419 ／ 559–564 ns（约 −37%） |

## 5. 稳定性与漂移

- 三个窗口间的最大值与最小值之比：Rain 建钥 1.00–1.03，签发 1.006–1.027，验签 1.000–1.002。EM-AES 对照的建钥为 1.12–1.13，因为它们约有 25% 的样本因拒绝而多调随机源。
- 对照相对 Q3 的漂移：签发、验签在 ±2% 以内。128s 对照的建钥比 Q3 低 5%–9%，建钥本身只有约 1.2 µs，对所在窗口的缓存状态敏感（Q3 报告第 7 节已说明）。所以建钥一律只在同一窗口内比较。

## 6. 范围与限制

- 结论只针对这一台 Zen 2 服务器（AVX2，无 VAES／GFNI）。组件写法是按这台机器选定的，换微架构后最优写法可能不同，但正确性不受影响，因为各种写法算的是同一个函数。
- 建钥中约 0.49 µs 是一次 `getrandom(32)` 系统调用，这是固定下限。Rain-4 每多一轮就多一次求逆，所以 Rain-4 只比对照快 3% 左右，Rain-4 短档持平。
- 未做常数时间检测和侧信道评估：新代码保持了常数时间写法，但没有经过测量。
- Lynxer 只作性能与格式对照。
