# 原030（Rain＋rVOLEitH）的 EUF-CMA 安全性：完整证明描述

2026-10-16；Q4 结案交付；供论文写作使用。本文合成项目中已经过内部独立审查的证明模块，不引入新的数学结论；与源稿有出入时以源稿为准。

## 0. 摘要

**结论。** 原030（Rain 单向函数 + rVOLEitH 证明系统，六个参数组）在经典随机预言模型与理想分组密码模型下有完整的 EUF-CMA 条件安全证明（定理 1）：伪造优势不超过“一个显式归约者求 Rain 原像的优势”加上一组显式统计项。在“Rain-128-3/4 单点原像困难”的计算假设下，这支持与 rFAEST 作者所声称的 128 位档相当的安全评价，论证层级与作者相同。

**证明的主要构件。**

1. 只用公钥的签名模拟：H_s 按随机预言处理并检测密钥前缀；编程新挑战点并精确复现 grinding 的首成功分布；隐藏路径按理想分组密码的单元逐个耦合；掩码 (d, ã, ũ) 由三角双射变成独立均匀串（§5.3）。
2. 共享 AES 地址下的叶层结构：有序双承诺绑定、迟到父节点、全域桶上限（§5.5）。
3. 全桶语义族上的 VOLE 一致性分析：已知分支直接得到见证 W，未知分支至多两个兼容挑战，或触发一次整条随机带的跨树等式（§5.6）。
4. QuickSilver 约束 x·y = 1 的关系编码健全性：满足约束的见证恰好对应一个所有 S 盒输入非零的 Rain 原像（§5.7）。
5. 显式归约者 B_final：只对最终伪造所指的那一条历史链做事后提取；它自己新增的私有理想分组密码调用至多 (2m+3)·q_anchor，连同来源调用在内的全部调用至多 q_0 + (2m+3)·q_anchor（§6）。

### 1.3 两种域表示与同构 ψ

来源：Q1 验收：实例冻结（内部记录，未随仓库公开）。

| 对象 | 定义 |
|---|---|
| VOLE 域 F | GF(2)[X]/(X^128 + X^7 + X^2 + X + 1)；证明系统与 Rainier 官方实例都在这里计算 |
| 底域 B | GF(2)[x]/(f_64)，f_64 = x^64 + x^4 + x^3 + x + 1 |
| 塔域 T | B[y]/(y² + y + β)，β = x^61；密钥线格式（P_T、K_T、C_T 各 16 字节小端） |
| 嵌入 ι : B → F | ι(x) = ρ，ρ 为 f_64 在 F 中 64 个根里的规范根（最小者） |
| 同构 ψ : T → F | ψ(a_0 + a_1·y) = ι(a_0) + ι(a_1)·η，η 为 η² + η = ι(β) 两解中的较小者 |

**引理 0（ψ 是域同构）。** ψ 是保持加法和乘法的双射，ψ(0) = 0，ψ(1) = 1，ψ(a^{−1}) = ψ(a)^{−1}（a ≠ 0）。

*证明。* f_64 在 GF(2) 上不可约（Rabin 检验），F 含唯一的 64 次子域，所以 f_64 在 F 中有 64 个根；取其一 ρ，x ↦ ρ 诱导单的环同态（域嵌入）ι : B → F。y² + y + β 在 B 上不可约（否则 T 不是域；β = x^61 的迹为 1），其像 z² + z + ι(β) 在 F 上有根（F 是 ι(B) 的二次扩张），取一根 η。于是 ψ 是 B[y] → F 唯一的、扩张 ι 并把 y 送到 η 的环同态；它在 y² + y + β 上取零，故下降为 T → F 的环同态。T 是域，核只能为 0，所以 ψ 单；两边都有 2^128 个元素，所以 ψ 是双射。环同构保持 0、1 与乘法逆元。∎

Q1 另以实际计算核对：两个模多项式不可约；ρ 在 64 位子域内且 η² + η = ι(β)；矩阵 Ψ 可逆；ψ(1) = 1，64 组随机乘法都保持；两域求逆各 64 组正确。

**塔域实例。** 冻结实现的建钥在 T 中计算 Rain，其轮常数和线性层是官方实例经 ψ 的共轭：c_{T,i} = ψ^{−1}(c_i)，M_{T,i} = ψ^{−1} ∘ M_i ∘ ψ（作为 GF(2) 线性映射）。由引理 0，T 中的逐轮计算 x_{T,i} = s ⊕ K_T ⊕ c_{T,i}、y_{T,i} = x_{T,i}^{−1}、s ← M_{T,i}·y_{T,i} 经 ψ 恰好变成 F 中的官方计算，所以

```text
Rain^T_{K_T}(P_T) = ψ^{−1}( Rain_{ψ(K_T)}(ψ(P_T)) )，   且各轮 x_i = ψ(x_{T,i})。
```

特别地，塔域与 VOLE 域的 S 盒输入同时为零或同时非零。Q1 核对：参考实现复现 Rainier 官方 KAT（Rain-128-3、Rain-128-4 各 5 组），塔域实例与 ψ^{−1}∘Rain∘ψ 往返一致；自有 KAT 每个实例 11 组，Python 塔域、Python VOLE 域、C 塔域三套实现一致，非拒绝组每轮 x·y = 1。

**记号约定。** 下文用 P_T、K_T、C_T 表示线格式（塔域）值，用 P = ψ(P_T)、K = ψ(K_T)、C = ψ(C_T) 表示 VOLE 域中的值。ψ 与 ψ^{−1} 各是一次 128×128 二元矩阵乘向量（Q1 实测每次转换约 155 ns）。

## 2. 方案定义

本节逐位对应冻结源码（rFAEST 提交 `7a59c5c` 加迭代030的 Rain 补丁）。协议式子由 C++ 逐步复现（207/207）和独立 Python 重算（180/180）核对，Rain-3 与 Rain-4 各自覆盖，见重做00（内部记录，未随仓库公开）与重做00b（内部记录，未随仓库公开）。

### 2.1 Rain 单向函数

Rain（Dobraunig、Kales、Rechberger、Schofnegger、Zaverucha，CCS 2022）是只在单个已知明密文对下使用的带密钥置换。R 轮 Rain 对 128 位明文 P 和密钥 K 定义为

```text
s ← P
for i = 0, …, R−1:
    x_i ← s ⊕ K ⊕ c_i          （c_i 为公开轮常数）
    y_i ← x_i^{-1}              （GF(2^128) 求逆，规范中 0 ↦ 0）
    if i < R−1: s ← M_i · y_i   （M_i 为公开的随机可逆 128×128 二元矩阵）
C ← y_{R−1} ⊕ K
```

记作 C = Rain_K(P)。冻结实例使用 Rainier 官方常数，并已核对：每个 M_i 写成线性化多项式 Σ_j a_j X^{2^j} 后，128 个系数全非零，其逆亦然（Rain-3 两层、Rain-4 三层，19,369 项检查），见Rain128核验 §2（内部记录，未随仓库公开）。上式在 F 中按 Rainier 官方常数计算，即公开密码分析所针对的官方实例；冻结实现的塔域计算与它经 ψ 精确对应（§1.3）。

### 2.2 预言划分

所有哈希都是同一个 SHAKE128 接口，输入末尾带一个域分离字节，必要时再由输入长度区分。

| 记号（证明中） | 源码名 | 末字节 | 输入 | 输出字节 |
|---|---|---|---|---|
| H_μ | — | 0x08 | pk ‖ msg | 32 |
| H_s | H₃ | 0x03 | K_T ‖ μ ‖ ρ | 32，拆为 (r, iv_pre) |
| H_4 | H₄ | 0x04 | iv_pre | 16 |
| H_c（叶层） | H_leaf | 0x01 | com_{t,0} ‖ … ‖ com_{t,N_t−1} | 32，记 h_t |
| H_c（森林层） | H_com | 0x01 | h_0 ‖ … ‖ h_{τ−1} | 32，记 h_com |
| H_1 | H₂¹ | 0x09 | μ ‖ h_com ‖ c_1 ‖ … ‖ c_{τ−1} ‖ iv | 88，记 chall1 |
| H_2 | H₂² | 0x0A | chall1 ‖ ũ ‖ Ṽ_0 ‖ … ‖ Ṽ_127 ‖ d | 56，记 chall2 |
| H_Δ | H₂³ | 0x0B | chall2 ‖ b̃ ‖ ã ‖ ctr（4 字节小端） | 16，记 chall3 |

两类 0x01 输入在六组中长度集合互不相交（叶层 16N_t+1 字节，森林层 32τ+1 字节）。K_T 是塔域编码的私钥字节，ρ 是每次签名新取的 16 字节随机数。

AES-128 记作 E_s(X)，s 为密钥，X 为明文。所有调用都以种子为密钥、以公开 iv 派生的块为明文：

```text
X_iv(c, e) = iv ⊞ (c, 0, 0, e)      （把 iv 看作四个 32 位小端 lane，lane 0 加 c、lane 3 加 e，各自模 2^32）
```

| 调用 | 密钥 | 明文 | 用途 |
|---|---|---|---|
| F_root | r | X_iv(t, 0)，t ∈ [τ] | 第 t 棵树的根 |
| F_tree | 深度 d 的节点 s | X_iv(0, (d+1)τ+t) 与 X_iv(1, (d+1)τ+t) | 左、右孩子 |
| F_com | 叶种子 s_{t,j} | X_iv(0, (k_t+1)τ+t) | 叶承诺 com_{t,j}（128 位） |
| F_tape | 叶种子 s_{t,j} | X_iv(c, 2^31+t)，c ∈ [m] | 随机带的第 c 块，只取前 L 位 |

固定 iv 下，不同角色、不同 (树, 深度) 的明文互不相同。但**同一棵树同一层的所有节点共用一个明文，同一棵树的所有叶承诺共用一个明文**。这与 rFAEST 论文按树内位置编码的 F^ctr 不同（论文中同一位置跨树共用），是证明必须按真实代码处理的“共享地址”结构。

### 2.3 密钥生成

```text
KeyGen():
    repeat: (P_T, K_T) ← {0,1}^128 × {0,1}^128 均匀（塔域线格式）
    until  塔域 Rain 计算中所有 x_{T,i} ≠ 0
    pk ← (P_T, C_T = Rain^T_{K_T}(P_T))；sk ← (P_T, K_T)
```

由 §1.3，(P, K) = (ψ(P_T), ψ(K_T)) 同样均匀，C = ψ(C_T) = Rain_K(P) 是官方实例的输出，拒零条件在两种表示下相同。签名时重算见证 w = ψ(K_T) ‖ ψ(y_{T,0}) ‖ … ‖ ψ(y_{T,R−2}) = K ‖ y_0 ‖ … ‖ y_{R−2}，共 ℓ 位；末轮 y_{R−1} = C ⊕ K 由公钥导出，不进入见证。拒零采样使 (P, K) 的分布与均匀分布的总变差恰为拒绝概率 δ_R ≤ R/2^128（Rain128核验 §3（内部记录，未随仓库公开））。

### 2.5 验签

| 步 | 计算 |
|---|---|
| 1 | 若 Δ 高 g 位不全为零则拒绝 |
| 2 | 由 pk、msg 算 μ；由 iv_pre 算 iv = H_4(iv_pre) |
| 3 | 每棵树由兄弟节点展开出隐藏叶以外的全部叶种子，算其 com 与带；隐藏位置的 com 取签名中的值；q_{t,h} = ⊕_{j ≠ α_t, (j⊕α_t)_h = 1} a_{t,j} ⊕ δ_{t,h}·c_t（c_0 := 0） |
| 4 | 由重算的 com 得 h_com′，chall1′ = H_1(μ ‖ h_com′ ‖ c ‖ iv) |
| 5 | 原始哈希 R_c = 𝒱_{chall1′}(q 的第 c 列)；修正值 Q̃_c = R_c ⊕ Δ_c·ũ；chall2′ = H_2(chall1′ ‖ ũ ‖ Q̃_0 ‖ … ‖ Q̃_127 ‖ d) |
| 6 | 前 ℓ 行 q ← q ⊕ Δ_c·d；按行转置得每行的 GF(2^128) 元素 |
| 7 | 由这些行、Δ、ã 重算 b̃′；chall3′ = H_Δ(chall2′ ‖ b̃′ ‖ ã ‖ ctr) |
| 8 | 接受当且仅当 chall3′ = Δ |

验签没有单独的相等检查：h_com、ũ、d、ã 中任何一项不一致，都只经哈希链传导到最后的 chall3′ = Δ。

### 2.6 三条核心关系

**VOLE 关系。** 对每棵树 t、每个 h ∈ [k_t]，验证方重构的列满足 q_{t,h} = v_{t,h} ⊕ δ_{t,h}·u_0（隐藏叶的带被消去）。拼接各列并结合末 g 列为零，得到前 L 行上的

```text
Q = V ⊕ u·Δ^T
```

前 ℓ 行再加 Δ·d 后变为 Q′ = V ⊕ w·Δ^T，即每行 K_i = M_i + Δ·W_i（i < ℓ），K_i = M_i + Δ·u_i（ℓ ≤ i < L_QS）。

**VOLE 一致性哈希。** 对固定 chall1，𝒱 是 GF(2) 线性映射：

```text
𝒱_χ(x) = VH_χ(x[0 : L_QS]) ⊕ x[L_QS : L]      （输出 176 位）
```

其中 VH 是 GF(2^128) 与 GF(2^64) 两个多项式哈希经 2×2 矩阵合成的通用哈希。后 176 行以单位阵直接加到输出上。由 Q_c = V_c ⊕ Δ_c·u 与 𝒱 的线性，诚实执行时原始哈希为 R_c = 𝒱(Q_c) = Ṽ_c ⊕ Δ_c·ũ，所以**修正值 Q̃_c = R_c ⊕ Δ_c·ũ = Ṽ_c**，验证方重算的 chall2′ 等于签名方的 chall2。

**QuickSilver 约束与 Rain 关系。** 见证在 VOLE 域 F 中为 W = (k, y_0, …, y_{R−2})，令

```text
x_0 = P ⊕ k ⊕ c_0，   x_r = M_{r−1}·y_{r−1} ⊕ k ⊕ c_r（r ≥ 1），   y_{R−1} = C ⊕ k
```

其中 P = ψ(P_T)、C = ψ(C_T)，M_r、c_r 为 Rainier 官方常数。

每轮加入约束 x_r·y_r + 1 = 0（owf_proof.inc:754–772（内部记录，未随仓库公开），quicksilver.hpp:545–550（内部记录，未随仓库公开））。由于 x·y = 1 当且仅当 x ≠ 0 且 y = x^{−1}，满足全部 R 条约束的见证恰好对应一个所有 S 盒输入非零的 Rain 原像 K（§5.7 引理 12）。

## 3. 安全模型

### 3.1 EUF-CMA 游戏

固定六个参数组之一和一个公钥。挑战者运行 KeyGen，把 pk 交给伪造者 A。A 可以自适应地请求签名，至多 Q 次；签名预言按 §2.4 执行，每次新取 ρ（源码另有省略 ρ 的确定性模式，不经对外接口暴露；重做03 的模拟同时覆盖两种接口，本文按对外的随机化模式陈述）。A 最后输出 (msg*, σ*)，若 msg* 从未请求过签名且 Verify(pk, msg*, σ*) 接受，则 A 获胜。记获胜概率为 Adv^{EUF-CMA}_{030}(A)。

结论分别对六个参数组成立。源码哈希输入没有参数集标签，所以本文不声称六个参数组共用同一组预言时的联合安全；也不覆盖多用户设定（§7.5 给出说明）。

### 3.2 理想化模型

- **随机预言。** SHAKE128 建模为单个前缀一致的可扩展输出随机预言：对一个完整输入，第一次以任意长度查询时就固定其整个输出串，后续不同长度的查询读取同一串的前缀。各域由末字节和长度区分（§2.2）。
- **理想分组密码。** AES-128 建模为独立随机置换族 {E_s}，允许正向 (s, X) ↦ Y 与逆向 (s, Y) ↦ X 两种查询。攻击者、签名预言、提取器和最终验签的所有调用都计费。

计数约定（沿用证明源稿）：

| 记号 | 含义 |
|---|---|
| a_IC | A 的正、逆向 IC 调用总数 |
| a_c、a_μ、a_s、a_4、a_1、a_2、a_Δ | A 对相应预言域的**首次完整输入**个数，含格式不合规、短前缀与零长度查询 |
| Q | 签名请求次数的先验上界 |
| q_0 = a_IC + (Q+1)·A_V | 来源 IC 表规模上界（攻击者、全部签名的公开重构与最终验签） |
| q_anchor = a_IC + Q·A_V | 不含最终验签的来源规模 |
| h_1、h_2、h_Δ | 包括模拟器与最终验签在内的 H_1、H_2、H_Δ 总调用上界 |

### 3.3 原语游戏

挑战者按 §2.3 的真实拒零 KeyGen 产生线格式挑战 (P_T, C_T) 交给算法 B。B 输出 K′_T，若 Rain^T_{K′_T}(P_T) = C_T 且各轮 S 盒输入非零则获胜。由 §1.3，这等价于在官方实例上对 (P, C) = (ψ(P_T), ψ(C_T)) 求 K′ = ψ(K′_T)，两种表示之间只差公开的矩阵乘法。B 只需找到任意一个有效原像，不必找回生成时的密钥。

定义两个游戏：

| 游戏 | B 的能力 | 优势记号 |
|---|---|---|
| 普通游戏 G^OWF | 不访问任何预言 | Adv^{OWF}_{Rain,R}(B) |
| 辅助预言游戏 G^{OWF,IC} | 另可访问一个与挑战独立的理想分组密码，只作普通正、逆向查询；随机预言由 B 本地模拟 | Adv^{OWF,IC}_{Rain,R}(B) |

定理 1 直接得到的是后者，§7.1 的困难性假设对前者陈述。二者由下面的引理 L 连接（推论 1′），所以定理右边实际使用的假设就是 §7 讨论的那一个。“辅助理想密码与挑战独立”只说明它不泄露挑战的信息；它作为计算能力的代价，由引理 L 显式计入，而不是视为免费。

**引理 L（理想分组密码的本地模拟）**（推进05/合成/01（内部记录，未随仓库公开）；独审：推进05/有效链/03（内部记录，未随仓库公开）、推进05/原语连接/02（内部记录，未随仓库公开））。设 B 在 G^{OWF,IC} 中至多发出 p 次理想分组密码请求（正向、逆向、重复都计入），其中至多 f̄ ≤ p 次产生新映射；B 从空表开始，只通过查询—回答接口观察理想分组密码。则存在不访问任何预言的算法 C_rank[B]，使

```text
Adv^{OWF,IC}_{Rain,R}(B) ≤ Adv^{OWF}_{Rain,R}(C_rank[B]) + min(1, f̄·2^{−258})。
```

C_rank[B] 运行 B，并用两棵双向计数树为每个 key 惰性采样随机置换：每个新映射取 384 个随机位，以流式取模选出一个未占用端点的秩。按推进 04 的共同机器（256 位字，七类基本动作各计 1）计，额外费用为：每次请求至多 1912 个基本动作；每个新映射至多 16628 个基本动作与 384 个随机位；固定准备少于 2^26 个动作；额外空间至多 2^16 + 2048·f̄ 个 256 位字；代码与常数装载至多 2^24 位。

*证明要点。* 若每次选秩严格均匀，该模拟与理想分组密码的精确惰性采样同分布。写 2^384 = a·s + r（s = M − n 为当前 key 的剩余端点数），384 位均匀数对 s 取模与均匀分布的总变差距离恰为 r(s − r)/(s·2^384) ≤ s/(4·2^384) ≤ 2^{−258}。在共同前缀上对每次新映射做最大耦合，首次分歧之前 B 的全部状态相同；缓存命中无误差；对至多 f̄ 次新映射并合即得。∎

### 3.4 与 rFAEST 模型的对应

rFAEST 定理 4.3 同样在经典随机预言模型与理想原语模型下给出条件归约，困难性项为 Adv^owf_KeyGen(B)。原030的模型与之同类，差别在于：原030的 B 是给出全部资源的有限可执行算法，而 rFAEST 只断言存在多项式时间的 B（§9）。

### 4.3 定理

**定理 1（原030的 EUF-CMA 安全性）。** 固定 §1.2 的任一参数组和 §4.1 的分析参数。在 §3.2 的经典随机预言模型与理想分组密码模型中，对任意满足 §3.2 预算的伪造者 A，存在 §6 给出的显式算法 B_final，使得

```text
Adv^{EUF-CMA}_{030}(A) ≤ min{ 1,  Adv^{OWF,IC}_{Rain,R}(B_final)
                                 + ε_Sim + ε_Chain + δ_u + ε_Canon + ε_Parent
                                 + ε_AU + ε_Twin + a_2·ε_Z + (2a_Δ + 1)/M }。
```

B_final 只得到 Rain 挑战 (P_T, C_T)，不知道私钥，也不能对理想分组密码编程。它新增的私有调用 Q_priv 与全部调用 P_final 满足

```text
Q_priv ≤ 3q_anchor + m·min(N·u, 2q_anchor)，
P_final ≤ q_0 + 3q_anchor + m·min(N·u, 2q_anchor) ≤ q_0 + (2m+3)·q_anchor，
```

运行时间与空间见 §6 的 (F-T)、(F-S)。

**推论 1′（原语项换成普通游戏）。** 对 B = B_final 应用引理 L（p ≤ P_final，f̄ ≤ P_final），得到

```text
Adv^{EUF-CMA}_{030}(A) ≤ min{ 1,  Adv^{OWF}_{Rain,R}(C_final)
                                 + ε_Sim + ε_Chain + δ_u + ε_Canon + ε_Parent
                                 + ε_AU + ε_Twin + a_2·ε_Z + (2a_Δ + 1)/M
                                 + min(1, P_final·2^{−258}) }，
```

其中 C_final = C_rank[B_final] 不访问任何预言，资源为 B_final 的资源（§6）加引理 L 的模拟费用。§10 的全部预算都有 P_final < 2^53，新增项小于 2^{−205}。§7.1 的假设正是对 Adv^{OWF}_{Rain,R}(C_final) 陈述的。

**状态：** 有条件地已证明。条件是经典随机预言模型、理想分组密码模型，以及 §3.3 的 Rain 困难性。证明各模块经过内部 AI 独立反驳审查（§11），没有外部同行评审，也没有机器形式化验证。

**定理的读法。** 右边除 Adv_Rain 外都是统计项。在实际预算下它们很小：例如攻击者对每个预言域和 IC 各查询 2^48 次、请求 2^32 次签名时，六组的统计项合计约为 2^−77（§10）。因此伪造原030的难度被归约为：在相近资源下求 Rain 的任意原像。“相近”的确切含义由 Q_priv 和 (F-T)、(F-S) 给出。这一结构与 rFAEST 定理 4.3 相同，见 §9。

**同一事件的多个上界。** ε_Hide 与 ε_AU 是同一坏事件的若干已证上界取最小值，不涉及不同归约。项目中还有另外两条完整归约：保守定理 C 和碰撞容忍定理 ST，它们各有自己的归约者。三条定理的 Rain 优势项属于各自的算法，不能跨定理逐项取最小（§5.10）。

## 5. 定理 1 的证明

### 5.1 路线

证明分两段。第一段把真实签名预言替换成只用公钥的模拟器，代价是 ε_Sim。第二段在模拟游戏里分析最终的有效伪造：要么归约者 B_final 得到 Rain 原像，要么发生某个已计费的坏事件。

| 步骤 | 内容 | 代价 | 小节 |
|---|---|---|---|
| G0 → G1 | 在 A 的 H_s 查询上安装公开的密钥检测器；胜利谓词扩大为 HitKey ∨ Forge | 0（只扩大成功事件） | 5.3 |
| G1 → G2 | 新 (μ, ρ) 的 H_s 输出改为隐式均匀采样 | 0 | 5.3 |
| G2 → G4 | 在**同一个首次坏事件耦合**中：新的 H_1、H_2、H_Δ 点编程，按真实首成功分布抽取 grinding 结果；隐藏路径改用虚拟标签，按 IC 单元耦合 | ε_Program + ε_Tail + ε_Hide（合计 ε_Sim） | 5.3 |
| G4 → G5 | 三角双射：(d, ã, ũ) 改为独立均匀采样，签名只需公钥 | 0 | 5.3 |
| G5 → G6 | 加入 B_final 的日志与事后提取；私有读取不反馈来源流程 | 0（引理 1） | 5.2 |
| 最终伪造 | 哈希链 → 叶层结构 → VOLE 一致性 → QuickSilver → 挑战 | 其余各项 | 5.4–5.9 |

两段在同一个耦合里取“首次坏事件”。所有概率论证都只在当时的历史上取条件，从不在“将来不出现坏事件”的条件下再声称某个回答仍然均匀。

### 5.2 来源与私有：两张表

B_final 维护两张理想分组密码表。Full 记录 B_final 实际知道的全部映射。Source 是其子集，只含攻击者、签名模拟器的公开重构和最终验签触达过的行；每行带首次曝光序号 source_time。提取器的私有读取只进 Full，此后若来源过程触达同一行，先登记为 Source 再返回。

**引理 1（来源边缘不变）。** 固定理想分组密码族 E、来源随机币和随机预言采样。删除全部私有读取、私有缓存和提取计算后，来源过程每一次调用的地址、回答和后续控制流逐点相同。因此来源过程的联合分布不变。

*证明。* 私有读取只读取已经抽定的置换 E_K，不修改它，也不向来源过程输出。Full 缓存只改变 B_final 何时、读多少次，不改变来源得到的值；来源以后查询一个已被私读的位置，得到的仍是同一个 E_K 的值。对 E 和随机币取平均即得。∎

后面凡是只依赖来源轨迹和 E 的事件，都可以先删去私有读取再分析；而私有读取的次数仍完整计入 B_final 的资源。这是“概率账”和“资源账”分开的依据。

### 5.3 第一段：只用公钥的签名模拟

**G0 → G1：密钥检测器。** 在 A 第一次以任意长度查询某个完整 H_s 输入、得到任何回答之前，B 把输入的前 16 字节当作候选 K_T，用公钥检验它是否为 Rain 原像（含所有 S 盒输入非零）。若是，立即输出该原像并停止（事件 HitKey）。重复输入复用已判结果。这只把胜利谓词从 Forge 扩大为 U = HitKey ∨ Forge，所以 Pr[Forge_{G0}] ≤ Pr[U_{G1}]。检测器可能找到与原私钥不同的合法密钥，不需要唯一性；它也不断言“每个伪造都查询过 H_s”。

**G1 → G2：隐式 H_s。** 在 HitKey 未发生的前缀里，A 从未触达真正的 K_T ‖ μ ‖ ρ ‖ 03。所以每个新 (μ, ρ) 的 H_s 输出可以按两个独立均匀的 128 位值隐式采样，B 无需知道秘密输入；同一 (μ, ρ) 复用缓存。真实实现中同一 (μ, ρ) 给出逐字节相同的签名，所以缓存恰好复现真实分布。签名预言每次新取 ρ，重复消息不触发缓存。μ 由 A 的消息完全决定，**证明不使用 μ 的熵**。不同 (μ, ρ) 的 s_root 或 iv_pre 碰撞仍保留在后面的事件中。

**G2 → G4（一）：编程与 grinding。** 这一步与下面（二）的 IC 单元耦合属于同一个首次坏事件耦合，分开叙述只为清楚；ε_Program 中 H_1 一项用到的 c 串均匀性只在虚拟侧成立，不预先假定真实的 c 均匀。模拟器（重做03 §3（内部记录，未随仓库公开））对每个新签名：取新 iv_pre，**正常读取 H_4**（即使该输入已有记录也返回原值，不中止）；均匀抽取 Δ（高 g 位为零）、开示中的 D 个兄弟种子与 τ 个洞承诺、各 c_t；运行真实的公开重构与 QuickSilver 验证；然后在 H_1、H_2 的新点编程 chi1、chi2，并逐个 ctr 模拟 grinding：

```text
for ctr = 0..G−1:
    Y ← 均匀 128 位
    if Y 高 g 位非零: 编程 H_Δ(prefix ‖ ctr) = Y          （失败行）
```

真实首个成功计数器的分布为 (1−p)^c·p（p = 2^−g），成功输出在活跃子空间内均匀且与计数器独立，此前输出条件于高位非零，同批后续输出无条件均匀。模拟逐项复现这三种联合分布。编程点若已被任何长度查询触达，记编程冲突。

编程冲突的概率：在虚拟侧，本次的 c_1 ‖ … ‖ c_{τ−1} 是长 L(τ−1) 位的独立均匀串，任一旧 H_1 输入都固定了整串，所以 H_1 冲突至多 h_1/2^{L(τ−1)}；H_2 的输入以新 chi1 为前缀，冲突至多 h_2/2^704；H_Δ 以新 chi2 为前缀，至多 h_Δ/2^448（整批 grinding 共用一个 chi2，不再乘 G）。对 Q 个签名求和得 ε_Program。未在 G 次内成功的概率为 ε_Tail。

**G2 → G4（二）：IC 单元耦合**（签名模拟/01（内部记录，未随仓库公开），误差收紧/02（内部记录，未随仓库公开））。每个新签名有 S = 1 + D + τ 个隐藏源（H_s 主种子、洞路径上的 D 个内部节点、τ 个洞叶种子），共 J = 2D + (m+2)τ 个受保护的 IC 单元：其中 E = D + τ 个单元的输出是另一个隐藏标签，F = D + (m+1)τ 个单元的输出是独立的非标签值（公开兄弟种子、洞承诺、洞的 m 个带块）。虚拟游戏给 F 类输出独立均匀值，公开子树照常查询真实理想分组密码；隐藏标签只索引受保护单元，不参与任何公开计算，可以推迟到整条普通轨迹之后再抽。

只有以下四类端点冲突才需要停止：

1. 受保护单元与普通行**输入**相交：L_i = K 且 x_e = x；
2. 受保护单元与普通行**输出**相交：L_i = K 且 Y_e = y；
3. 不同隐藏源取到同一数值标签，且明文相同；
4. 同一数值 key 的两个不同明文被安排到同一输出。

仅仅 key 数值相等而端点不冲突，不构成冲突：两侧可以共用同一个随机置换。没有冲突时，按真实树的依赖顺序逐单元耦合，两侧各自的置换边缘都正确（同 key 已有 k 个旧输出时，新输出落在每个剩余值上的真实质量为 1/M + (k/M)·1/(M−k) = 1/(M−k)），首次冲突之前普通视图逐项相同。

概率计算（固定整条虚拟普通轨迹，隐藏标签独立均匀）：

- **按源合并**（引理 E1）：同一隐藏源的多个单元被同一公开 key 命中，只是一个“L_i = 该 key”事件，概率精确为 1 − Π_i(1 − |D_i|/M) ≤ Σ_i|D_i|/M。

- **攻击者与最终验签的输入**：按输入重数阈值付 u_x(a_IC + A_V)/M + δ_x；最终验签的 A_V 不因“不向对手返回内部值”而删除。
- **标签输出与保护单元之间**：标签输出相交需要两个独立等式，付 q_0QE/M²；同源输出重复付 Q·v_0/M；不同源之间付 C(QJ,2)/M² 与 (κ+1)C(Q,2)J²/M²。

合并得到 H_ref；旧的较宽合并得到 H_T11。两者都是同一事件的上界，取最小值即 ε_Hide。两个反例说明哪些简化不成立：(i) 公开重构的输入项不能整体归零。在四点置换的局部例子中，普通公开重构已有 (K=1, 0 ↦ 2)，而隐藏源恰取 L = 1 并要求同一输入 0 ↦ 3；虚拟采样赋予它正概率，但同一置换不能同时实现这两个映射。(ii) IV = H_4(U) 不是跨签名独立均匀的：两个独立 U 的 H_4 值相等的概率为 2/M − 1/M²，严格大于 1/M。

### 5.4 第二段之一：最终伪造的哈希链

以下在模拟游戏 G6 中分析。令 F 为最终有效的新消息伪造事件，σ* 为伪造签名。

**引理 2（哈希链）**（重做02 §2（内部记录，未随仓库公开））。除概率 ε_Chain 外，以下成立：(i) H_c、H_μ、H_1、H_2 各域内不同完整输入不给出相同协议长度输出；(ii) A 的首次 H_1 查询中 h_com 的缺失前像（根层或叶层，每个 H_1 至多 τ+1 个目标）此后不被新 H_c 输出命中；(iii) H_2 输入中的 chall1、H_Δ 输入中的 chall2 不会在对应 H_1/H_2 回答之前出现。

在引理 2 的补集上，若最终验签使用的完整 H_Δ 输入从未被查询，签名里的 Δ 已固定，验签第一次采样命中它的概率为 1/M（计入 (2a_Δ+1)/M 的 +1）。否则可以从 σ* 唯一追溯到更早的 H_2、H_1 和两层 H_c 输入，且它们与验签重建的输入一致。

**引理 3（编程行隔离）。** 在引理 2 的补集上，新消息伪造的链不经过任何模拟器编程的 H_1/H_2/H_Δ 行。

*证明。* 若最终 H_1 是签名行，其 μ 与某已签消息相同，无 H_μ 碰撞即消息相同；若最终 H_2 是签名行，chall1 相同，H_1 输出唯一迫使 H_1 输入（含 μ）相同；若最终 H_Δ 是签名的成功、失败或同批行，chall2 相同，依次回到已签消息。都与“新消息”矛盾。∎

### 5.5 第二段之二：共享地址下的叶层结构

**地址。** 对当前森林的树 t，

```text
x_{0,t} = X_iv(0, k_tτ + t)，   x_{1,t} = x_{0,t} ⊞ (1,0,0,0)，   x_{C,t} = X_iv(0, (k_t+1)τ + t)，
T_{t,c} = X_iv(c, 2^31 + t)（c ∈ [m]），   C_t(s) = E_s(x_{C,t})，   m_t(s) = E_s(T_{t,0}) ‖ … 的前 L 位。
```

x_{0,t}、x_{1,t} 是底层父节点生成左右两个叶子的明文，x_{C,t} 是叶承诺的明文。固定 IV 下当前森林的这些地址两两不同，不同树的带地址互不相交。**同一棵树的全部叶共用 x_{C,t} 与 T_{t,·}，同一层的全部节点共用父明文**：这正是 §2.2 指出的共享地址。

**规范父节点（canonical）。** 对每个底层兄弟对 (2i, 2i+1)，在 H_1 切口前、至少一侧父格已在 Source 中出现的父 key 里，选择使 (C_t(E_p(x_{0,t})), C_t(E_p(x_{1,t}))) 等于目标有序承诺对 (com_{t,2i}, com_{t,2i+1}) 的第一个（按 (父 key, 最早来源根序号) 排序）。选择只看承诺，不看带。其两个孩子的带记作基线 M_{t,2i}、M_{t,2i+1}；没有匹配父节点时基线取零。后来的来源增长不改变已定的 canonical。

**可见池。** 在 H_2 切口，K_vis,t 由以下 seed 组成：Source 中以 x_{C,t} 或某 T_{t,c} 为输入的行的 key；Source 中以 x_{0,t} 或 x_{1,t} 为输入的父行的两个孩子。只由 Source 根生成，不递归使用私有派生行。

**全域桶事件。** G_u：对所有分组 x 和值 y，|{s : E_s(x) = y}| ≤ u。

**引理 4（全域桶上限）**（理论补充/01（内部记录，未随仓库公开））。Pr[¬G_u] ≤ δ_u = min(1, M²/(u+1)!)。

*证明。* 对固定 (x, y)，不同 key 的 E_K(x) 独立均匀；某 u+1 个 key 同时映到 y 的概率至多 C(M, u+1)/M^{u+1}。对 M² 个 (x, y) 并合，再用 C(M, u+1) ≤ M^{u+1}/(u+1)!。∎

G_u 对全部输入输出同时成立，所以自适应选择的 IV、树、承诺目标都落在同一事件内。所有使用它的局部界都先界“事件 ∩ G_u”，最后只加一次 δ_u。逐查询的条件概率计算只在当前选定的那一列上取条件，只用到 G_u ⊆ “当前列桶帽”的包含关系，不在 G_u 条件下重用剩余置换的均匀性。

**引理 5（有序双承诺绑定）**（提取资源/03（内部记录，未随仓库公开））。令 PairSrc 为：存在 context x 与两个不同父 key p ≠ q，二者在 x 的父格都有 Source 支持，且有序承诺对相同。则

```text
Pr[PairSrc ∩ G_u] ≤ q_0(q_0−1)u²/[(M−q_0−1)(M−q_0−2)]。
```

*证明。* 把每一条实际调用 (s, z, y) 同时登记为 (s, z) 与 (s, z ⊟ (1,0,0,0)) 两个“父 key + context”注册项，总数 ≤ 2q_0。任一碰撞对中，取首次注册较晚的一方 (q, x)，记其注册调用为第 i 次；此前 q 在 x_0、x_1 两格都无记录。对每条更早注册 (p, x)，在分析中免费揭示整列 C_x(·) = E_·(x_C) 和 p 的两个父格；此时 q 的两个父输出仍是其剩余输出集合 R_q（|R_q| ≥ M − q_0 − 1）中均匀的有序不同对。目标对 (A, B) 被命中的概率为 (ab − c)/[|R_q|(|R_q|−1)]，其中 a、b 为两个目标桶与 R_q 的交，c 为二者交集；在当前列桶帽下至多 u²/D，D = (M−q_0−1)(M−q_0−2)。逆向调用要求返回值恰为父地址，另有更细的 2u/D，统一用 u²/D 即可。每次调用前至多 2(i−1) 条旧注册，求和 Σ_{i≤q_0} 2(i−1)·u²/D = q_0(q_0−1)u²/D。∎

PairSrc 只依赖来源轨迹和 E；由引理 1 可先删去私有读取，所以预算取 q_0 而非含私有读取的 P_final。在 ¬PairSrc 上，任何两名有 Source 父格支持、承诺对相同的父节点给出相同的有序带对，所以 canonical 的选择与实际父节点无歧义：这就是 ε_Canon。注意单个叶承诺的碰撞并不在此收费，它们未必有害；一个“半边旧、半边新”的例子（提取资源/03 §6（内部记录，未随仓库公开））表明最后补全一个父节点的条件概率可以是 1/(M−1)，所以收费必须记在首次获得支持的那次调用上。

**引理 6（迟到父节点）**（共享地址/04（内部记录，未随仓库公开））。令 L_{i,t} 为：存在父 key p，在 H_1 切口 i 前 (p, x_{0,t})、(p, x_{1,t}) 都无 Source 记录，切口后 p 被来源调用以任何地址、任何方向触达，且其潜在有序承诺对落在树 t 的目标对集合中。则

```text
Pr[∪_{i,t} L_{i,t} ∩ G_u] ≤ a_1·N·q_0·u²/[2(M−q_0−1)(M−q_0−2)]。
```

*证明。* 固定切口前完整来源历史。在分析中揭示整列 C(s) = E_s(x_{C,t})（每个 key 至多多固定一行）。此后每当来源将要以一个此前未在本切口后触达的合格 key p 发出调用，先在分析中揭示 E_p(x_{0,t})、E_p(x_{1,t})：这对输出在 R_p 上均匀，命中某个目标对的概率至多 u²/D（在当前列桶帽下）。目标对至多 N_t/2 个，新 key 至多 q_0 个。每个 (i, t) 单独建立分析，最后对 a_1 个切口与全部树并合，得 a_1·Σ_t(N_t/2)·q_0·u²/D。∎

切口前任一父格已在 Source 中出现的父节点，已由 canonical 规则的私有补全覆盖；剩下未被覆盖的父节点必然属于引理 6 的资格集合，而验签展开它又必然触达其 key。因此在 ¬PairSrc ∩ ¬(∪L) ∩ G_u 上：

**推论 7（底层对一致）。** 最终伪造的每个完全可见底层兄弟对，其开示得到的有序带对等于 H_1 切口时的 canonical 基线。每棵树中缺少基线的底层对至多一个（否则该树无兼容的单洞开示），该树合法的洞只能落在其中。

### 5.6 第二段之三：VOLE 一致性与全桶语义族

记 H = 𝒱_{chi1}（§2.6 的完整 176 位映射，GF(2) 线性），并定义

```text
A_t = c_t ⊕ (⊕_j M_{t,j})，   V_{t,h} = ⊕_{j: j_h=1} M_{t,j}，   D_{t,i} = A_t ⊕ M_{t,2i} ⊕ M_{t,2i+1}。
```

**引理 8（单树仿射性）**（共享地址/01 §2–3（内部记录，未随仓库公开））。在推论 7 下，洞为 β 的开示只可能在 β⊕1 处偏离基线，于是对某个误差 e 有

```text
q_{t,h} = V_{t,h} ⊕ β_h·A_t ⊕ [h = 0]·e。                           (1)
```

令 Γ_t = ũ ⊕ H(A_t)，Λ_{t,h} = Ṽ_{t,h} ⊕ H(V_{t,h})。候选 (β, e) 通过 VOLE 一致性检查当且仅当 Λ_{t,h} = β_h·Γ_t（h > 0）且 H(e) = Λ_{t,0} ⊕ β_0·Γ_t。若同一树的不同误差在 H 下不碰撞，则：(a) 每个洞至多一个通过的 q；(b) 若通过的洞跨越两个底层对，则 Γ_t = 0，公共 u* = A_t；(c) 若通过的两个洞同属一个底层对 (α, α+1)，误差为 e_0、e_1，则 u* = A_t ⊕ e_0 ⊕ e_1；(d) 只要通过的洞至少两个，就存在唯一的 u_t 使该树全部通过的开示满足 q_{t,h} = v_{t,h} ⊕ β_h·u_t，且 H(u_t) = ũ。

*证明。* 式 (1)：重构列为 ⊕_{j:(j⊕β)_h=1} m_j ⊕ β_h·c_t，换成基线得 V_{t,h} ⊕ β_h·A_t；洞的系数为 0，兄弟与洞只差最低位，所以替换兄弟带的修正只出现在 h = 0。(a) 固定 β 后 H(e) 有唯一目标值，H 在误差集合上单射。(b) 两个洞在某个高位 h > 0 不同，两式相减得 Γ_t = 0，于是全部通过误差有相同哈希值，排除碰撞后相等，取 v*_h = V_h ⊕ [h=0]e*。(c) 两洞高位相同，低列之差即 u*，且 H(e_0) ⊕ H(e_1) = Γ_t 推出 H(u*) = ũ。(d) 两个不同通过洞在某列的 β 位不同，该列 q 的差直接确定 u*。∎

相同误差异或为零的情形（rFAEST 4-xor 游戏要排除的那类，问题 R04）在这里只改变公共的最低列 v*_0，不需要当作坏事件。

**全桶语义族。** 仅在分析中，用完整的 E 定义（全部是 E 与 H_1 切口历史的确定函数，B_final 不枚举 2^128 个 key）：

```text
B_t(z) = {s : C_t(s) = z}，
E_t = ∪_β {m_t(s) ⊕ M_{t,β⊕1} : s ∈ B_t(com_{t,β⊕1})}，
U_{t,i}(a, b′) = D_{t,i} ⊕ m_t(a) ⊕ m_t(b′)，
F_t^+ = {A_t} ∪ {U_{t,i}(a,b′) : a ∈ B_t(com_{t,2i}), b′ ∈ B_t(com_{t,2i+1})} ∪ {D_{t,i} : com_{t,2i} = com_{t,2i+1}}。
```

最后一项保证即使同承诺桶为空，B_final 能算出的零异或候选也在语义族内。在 G_u 下 |E_t| ≤ N_t·u，|F_t^+| ≤ 1 + N_t·u²/2。

**引理 9（全桶 AU）**（共享地址/05 §3（内部记录，未随仓库公开），误差收紧/01（内部记录，未随仓库公开））。令 BadE 为某树 E_t 内两个不同误差 H 值相等，BadU 为 ∪_t F_t^+ 内两个不同元素 H 值相等。则在全部 a_1 个首次普通 H_1 上，

```text
Pr[(BadE ∪ BadU) ∩ G_u] ≤ ε_AU。
```

*证明。* VOLE 一致性哈希对每个在 chi1 抽取前固定的非零差分 z 满足 Pr[𝒱_{chi1}(z) = 0] ≤ ε_V：令 n = R+1，前缀分成 n 个 GF(2^128) 系数与 2n 个 GF(2^64) 系数，两个 Horner 多项式分别至多 n−1 和 2n−1 个根；同时为零的概率至多 (n−1)(2n−1)/2^192；否则经独立的组合系数，截取后的 176 位输出命中固定掩码的概率为 2^−176（重做02 (B5)（内部记录，未随仓库公开））。

第一个选项：固定整张 E 和 H_1 切口历史后，语义族已固定，chi1 仍独立均匀；G_u 下待收费的差分对至多 C_U(u) 个；对 a_1 个切口并合。

第二、三个选项改用当前来源前缀上的桶矩。删除私有读取（引理 1）后，条件于当前来源前缀，各 key 的剩余置换独立且在剩余双射上均匀。一个目标桶 B(x, y) 的大小为“已曝光 seed 数 O + 未曝光部分 Z”，Z 是不同 key 的独立 Bernoulli 之和，E[Z] ≤ λ_* = 1 + q_0/[M(M−q_0)]；其阶乘矩至多 λ_*^k，所以 p 阶矩至多 Poisson(λ_*) 的 p 阶矩。在“当前前缀所有已选桶 O ≤ v”的可测事件上，|B| ≤ v + Z，用二阶、四阶 Hölder 不等式（相关桶也成立）得待收费对数的期望至多 C_mom(v)。前缀坏的事件（某 (x, y) 由 v+1 个不同 key 实现）的全程概率至多 δ_src(v)：把 v+1 条首次曝光行按时间排列，后续每一条在指定端匹配后命中另一端的概率至多 1/(M−q_0)。好前缀用 C_mom，坏前缀用 G_u 下的确定性计数 C_U(u)，或直接付 δ_src。三个选项都是同一事件的上界，取最小值。∎

**引理 10（已知分支）**（共享地址/05 §4–5（内部记录，未随仓库公开））。B_final 在可见池上枚举

```text
KnownU = {A_t} ∪ {D_{t,i} : 两个 com 相同} ∪ {U_{t,i}(a,b′) : a, b′ ∈ K_vis,t 的对应桶}  ⊆  ∪_t F_t^+，
```

（实际用线性哈希的字典查找，不枚举 u² 个组合）。若找到 f 使 H(f) = ũ，令 W = d ⊕ f[0:ℓ]。则在推论 7 与 ¬BadE ∩ ¬BadU 下，存在一个在 chi2 抽取前已固定的语义矩阵 V*，使所有兼容的后续开示满足

```text
Q = V* ⊕ f·Δ^T，  W = d ⊕ f[0:ℓ]。
```

*证明。* 每棵多洞树的 u_t ∈ F_t^+ 与 f ∈ F^+ 有相同 H 值，¬BadU 迫使 u_t = f。单洞树按其唯一通过点定义 v* = q ⊕ β·f；多洞树按字典序首个通过点定义，引理 8 保证它覆盖该树全部通过点。V* 只依赖 E、历史输入与 chi1，B_final 不需要计算它。∎

**引理 11（未知分支）**（共享地址/05 §7–8（内部记录，未随仓库公开））。若 KnownU 中没有任何元素匹配 ũ（且未溢出桶帽），则：要么兼容的 128 位 Δ 至多两个，且这个集合在 chi2 前已固定；要么发生事件 TwinUnknown，并且

```text
Pr[TwinUnknown 在任一普通 H_2 发生 ∩ G_u] ≤ a_2·C_X(u)·ρ = ε_Twin。
```

*证明。* 没有匹配意味着每树 H(A_t) ≠ ũ，即 Γ_t ≠ 0，由引理 8(b)，每树通过的洞只能落在同一底层对，至多两个。若至多一棵树有两个洞，整个森林的洞向量至多两种组合，加上固定的 grinding 零位，兼容的 Δ 至多两个。若至少两棵树各有两个洞，它们给出同一个 u（¬BadU），并有 u = U_{t,i}(a, b′)，其中 a ≠ b′（否则 U 退化为 KnownU 中的 D），且 a、b′ 至少一个不在 K_vis,t（否则已被枚举）。这就是 TwinUnknown：两棵不同树 t < s 的四元组满足 U_{t,i}(a, b′) = U_{s,j}(c, d)。

概率：固定该 H_2 切口的来源历史（先删私有读取），在分析中揭示当前森林的全部父格与承诺列（每 key 至多多 3τ 个点）。此时全桶、K_vis、canonical 与四元组名单都已固定，且不揭示任何带值。对每个四元组，在看带之前选出不在 K_vis,t 的那个 seed p：由可见池的定义，(p, T_{t,c}) 从未被来源触达，p 也不是树 t 的 canonical seed（p 可以在别的树里作为 canonical 或候选出现，这些引用至多占用 E_p 的 m(τ−1) 个带输入，已计入下面的 d_0）。再揭示其余所有相关带。等式要求 m_t(p) 等于一个已确定的 L 位目标。E_p 已曝光的输入至多 d_0 = q_0 + 3τ + m(τ−1) 个，m 个新的互异输入的输出是剩余置换上的无放回采样；前 m−1 块必须完全命中，最后一块只用前 b 位，可行补全至多 M/2^b 个，所以概率至多 ρ。四元组至多 C_X(u) 个，对 a_2 个切口并合。∎

这里直接对整条 L 位带的相等计费，没有把“迟到叶命中”与“VOLE 一致性通过”两个概率相乘。项目早期的一个小参数反例说明那种相乘不成立：条件于迟到匹配后，一致性检查通过的条件概率可以是 1（重做02 §8（内部记录，未随仓库公开））。

### 5.7 第二段之四：QuickSilver 与 Rain 关系

**引理 12（关系健全与最高次系数）**（重做01 §6（内部记录，未随仓库公开））。把 Δ 换成形式变量 X，每条源码约束 x_r·y_r + 1 = 0 在验证方变为

```text
f_r(X) = A_{r,0} + A_{r,1}·X + e_r·X²，   e_r = x_r(W)·y_r(W) + 1。
```

最高次系数 e_r 只依赖 W 与公开 Rain 参数。并且 e(W) = 0 当且仅当 W 的首块 k 是官方实例在 F 中的 Rain 原像（Rain_k(P) = C）且各轮 S 盒输入非零；此时 ψ^{−1}(k) 是线格式挑战 (P_T, C_T) 的原像（§1.3）。

*证明。* 验证方每行 K_i = M_i + Δ·W_i；rain_combine 只做固定 GF(2) 线性组合，公开常数 c 在验证方表示为 c·Δ。于是 x_r、y_r 在验证方都是 X 的一次式，其一次项系数分别为 x_r(W)、y_r(W)，乘积的 X² 系数为 x_r(W)·y_r(W)；约束中的常数 1 在验证方以 Δ² 的系数出现，合起来即 e_r。若所有 e_r = 0，则每轮 x_r·y_r = 1，故 x_r ≠ 0 且 y_r = x_r^{-1}；依次代入线性层、轮常数和末轮 y_{R−1} = C ⊕ k，得 Rain_k(P) = C；由引理 0，ψ^{−1}(k) 满足塔域实例，且塔域 S 盒输入同样非零。反之有效原像使所有 e_r = 0。∎

这一条正是 2026 年 ePrint 2026/2235 强调的“关系编码健全性”：满足约束的见证必须解码成真正的原像。原030的 `x·y = 1` 编码在 x = 0 时变为 0 = 1，等式本身排除零输入，不依赖建钥时的拒绝采样；末轮输出直接取 ct ⊕ k，公钥被绑定进关系；见证只有 k 和前 R−1 轮的 y，全部受约束。所以不存在“零分支”见证（§8.1）。

**CheckW。** 已知完整 W 时，B_final 不做 R 次求逆，只检查每轮 x_r·y_r = 1：Rain-3 用 3 次域乘法、2 次线性层、7 次 128 位异或和 3 次“等于 1”比较；Rain-4 分别为 4、3、9、4。通过即输出原像；失败则恰有 e(W) ≠ 0。

**引理 13（ZHash）**（重做02 §5（内部记录，未随仓库公开））。对每个在 chi2 抽取前固定的非零 e，经 chi2 哈希后的二次系数 E 为零的概率至多 ε_Z = 2^−128 + (R−1)²/2^192；对 a_2 个首次普通 H_2 并合得 a_2·ε_Z。

*证明。* 令 E_e(z) = Σ_r e_r z^{R−1−r}，次数至多 R−1 的非零多项式。H_2 的完整域键 s 与 64 位键 t 独立均匀，两次求值同时为零的概率至多 (R−1)²/2^192；否则均匀的组合系数使 E 均匀，为零的概率 2^−128。∎

E ≠ 0 时，验证等式 b′(X) = b̃ 是 X 的非零二次方程，在任意已固定的 H_Δ 输入下至多两个根。

### 5.8 第二段之五：挑战

**引理 14（挑战并合）**（签名模拟/03（内部记录，未随仓库公开））。除已计费事件外，最终有效伪造落在“某次普通新 H_Δ 回答命中一个至多两点的目标集合”或“最终验签首次 H_Δ 恰等于签名中的 Δ”之中，概率合计至多 (2a_Δ + 1)/M。

*证明。* 对 A 的第 i 个新 H_Δ 输入，在其回答 Y_i 抽取之前，用此前记录唯一追溯到 H_2 记录，定义目标集合 R_i：已知分支且 e ≠ 0、E ≠ 0 时，R_i 为该二次式在合法 Δ 子集中的根，|R_i| ≤ 2；未知分支时 R_i 为引理 11 的至多两个 Δ；其他情形（e = 0 已得原像、E = 0 已由 ZHash 计费、链异常、桶溢出等）R_i 为空。分支类型在 Y_i 抽取前已确定，所以 Pr[Y_i ∈ R_i | 历史] ≤ 2/M。对至多 a_Δ 次并合得 2a_Δ/M；最终验签新点另付 1/M。∎

注意：两个分支“最终结果互斥”本身不足以把 3/M 改成 2/M；关键是分支在回答抽取之前已经确定，每次只面对一个至多两点的集合。grinding 的每一次原始查询都计入 a_Δ，不按成功次数折算；条件于 grinding 成功后再声称 2/M 是不对的，这里是对每次无条件的 128 位回答计费。

### 5.9 合成

在模拟游戏中依次排除：哈希链与编程行（ε_Chain，引理 2、3）→ 全域桶（δ_u，引理 4）→ 双承诺绑定（ε_Canon，引理 5）→ 迟到父节点（ε_Parent，引理 6）→ 全桶 AU（ε_AU，引理 9）→ 跨树带等式（ε_Twin，引理 11）→ ZHash（a_2ε_Z，引理 13）→ 挑战（(2a_Δ+1)/M，引理 14）。在全部补集上，最终有效伪造所指的 H_2 记录 j 只能落入：

1. **已知分支且 CheckW 通过**：B_final 输出 Rain 原像（§6）；
2. **已知分支且 CheckW 失败**：e(W) ≠ 0 在 chi2 前已固定，被引理 13 与引理 14 覆盖；
3. **未知分支**：被引理 11 与引理 14 覆盖。

此外 HitKey 已经给出原像。所有坏事件只做并合，从不相乘，也不假设彼此独立；使用 G_u 的各项共同只付一次 δ_u。加上第一段的 ε_Sim，得到定理 1 的不等式。

**关于“事后选择”。** B_final 实际只对最终伪造指向的那一条记录 j 做提取，而 j 由 A 最后的输出决定。证明没有在“j 被选中”的条件下声称 chi2 新鲜：对每一个首次普通 H_2 记录 j，都在分析中预先定义一个历史函数 Φ_j = Φ(E, j 的不可变输入, 旧 Source/RO 水位, 固定候选次序, u)，包含 canonical、K_vis、桶帽状态、已知/未知分支、f 和 W。Φ_j 不读取 chi2，也不依赖将来选哪个 j。坏事件对全部 a_1、a_2、a_Δ 次查询并合；B_final 事后按旧水位重放所选 Φ_j，得到的结果与在线计算相同（引理 1 保证私有读取不影响来源）。**实际只执行一次提取，并不把 a_1、a_2、a_Δ 改成 1**；它只减少归约的资源。

## 6. 归约者 B_final 的算法与资源

来源：提取收紧/01（内部记录，未随仓库公开）。B_final 输入 Rain 挑战 (P, C)，可访问一个与挑战独立的理想分组密码（只作普通正、逆查询），所有随机预言在本地模拟。

### 6.1 算法

**阶段一：来源运行（不做任何私有提取）。**

1. 运行 A，用 §5.3 的只用公钥的模拟器回答签名请求，在本地模拟随机预言。
2. 所有理想分组密码调用规范化为 (K, x, y)，记录 Full 与 Source 以及每行的首次曝光序号；记录每个随机预言首次输入、输出或预留状态、编程行标记与全局先后序号。
3. 对 A 的每个合规首次普通 H_1/H_2 查询，在回答（含零长度预留）之前保存不可变输入引用、Source 水位与随机预言水位。模拟器的编程行和最终验签新建的 H_1/H_2 不建立提取记录。
4. 对 A 的每个首次完整 H_s 输入运行密钥检测器（§5.3）；命中即输出该密钥并停止。

**阶段二：选择唯一最终链。** A 输出后执行完整的最终验签（全部 IC 与随机预言调用计入来源）。若不是有效的新消息伪造，输出失败。否则按旧的随机预言水位，从日志中解析出伪造所指的更早普通 H_1/H_2 记录（多个旧记录按事先固定的顺序；相关碰撞已由 ε_Chain 支付）。没有满足时序的旧链则输出失败（由 ε_Chain 或最终新 H_Δ 的 1/M 覆盖）。记该链的 Source 水位为 s_1 ≤ s_2。

**阶段三：只对选中的森林做历史过滤。** 由选中 H_1 的快照恢复 IV、承诺向量和 c_t，建立当前森林的角色地址表（x_{C,t}、x_{0,t}、x_{1,t}、T_{t,c}，共 τ(m+3) 个互不相同的输入）。扫描首次曝光不晚于 s_2 的 Source 行：

- **承诺行**（输入为 x_{C,t}）：其 key 是 seed，输出就是真实承诺；
- **带行**（输入为某 T_{t,c}）：其 key 是 seed；若尚无承诺值，普通读取一次 E_K(x_{C,t})；
- **父行**（输入为 x_{0,t} 或 x_{1,t}）：按 (树, 父 key) 去重，补读另一父格至多一次、两个孩子的承诺至多两次，两个孩子都加入 K_vis,t。

首次支持不晚于 s_1 的父节点参与 canonical 的竞争（规则见 §5.5）；s_1 与 s_2 之间新增的父支持只扩大可见池，不改 canonical。所有遍历顺序按旧描述符与 seed 的字典序，不用 Full 的插入顺序。

**阶段四：桶帽与带。** 所有承诺分类完毕、canonical 确定之后，若某个目标承诺的去重 seed 数超过 u，输出失败（该事件包含于 ¬G_u，已由 δ_u 支付），不读任何带。否则为每个保留的 seed 普通读取 m 个带块（末块只用前 b 位）。

**阶段五：只算 A_t 和 W，不算 V 列。** 令 M_{t,j} 为 canonical 的带（无 canonical 时为零），A_t = c_t ⊕ (⊕_j M_{t,j})。按固定顺序：(1) 检查各 A_t；(2) 检查同承诺底层对的 D_{t,i}（含空桶）；(3) 对每个底层对，把左桶各 seed 的 H(m_t(a)) 放入有序字典（同值只留最小 seed），按右桶顺序查找异或补值 ũ ⊕ H(D_{t,i}) ⊕ H(m_t(b′))，命中即生成完整 f。找到 f 时令 W = d ⊕ f[0:ℓ]（已知分支），否则为未知分支。B_final 从不计算 V_{t,h}、语义 V* 或全桶族。

**阶段六：CheckW 与输出。** 把 W 读为 F 中的 (k, y_0, …, y_{R−2})，令 y_{R−1} = C ⊕ k（C = ψ(C_T)），按 §2.6 的式子逐轮检查 x_r·y_r = 1（§5.7）。通过则输出 ψ^{−1}(k)；否则输出失败。

§5.9 的“事后选择”论证保证：阶段三至五按旧水位重放的结果，恰是该记录在线定义的历史函数 Φ_j。

### 6.2 理想分组密码调用

令 R_rel 为 s_2 之前、输入落在选中森林角色表中的不同 Source 行数。每条这样的行至多匹配一种角色，所以补读次数满足 n_T + 3n_P ≤ 3R_rel ≤ 3q_anchor；可见池的成员数 ≤ 2R_rel；过滤后实际读带的不同 seed 数 K ≤ min(N·u, 2q_anchor)。因此

```text
Q_priv ≤ 3q_anchor + m·min(N·u, 2q_anchor)，
P_final ≤ q_0 + 3q_anchor + m·min(N·u, 2q_anchor) ≤ q_0 + (2m+3)·q_anchor。        (F-IC)
```

Rain-3 的系数 2m+3 = 15，Rain-4 为 17；此前在线提取器 ST 的对应系数为 138 和 174。这是归约的 IC 调用上界，不是签名速度。

### 6.3 时间与空间

令 T_src 为运行 A、模拟器与最终验签的全部普通工作（已含其 IC 与随机预言费用），C_key,R 为一次完整 Rain 正向检验，C_wit,R 为一次 CheckW，C_VH(L) 为一次 VOLE 一致性哈希，c_IC 为一次新增私有 IC 调用，K̄ = min(N·u, 2q_anchor)，S 为全部有限记录数上界，w ≥ max(128, ⌈log₂(S + B_IO + 2)⌉)，B_IO 为需处理与保存的输入、输出及预留总位数，h = λ + b = 176。用确定性有序索引实现时：

```text
T_final ≤ T_src + [3q_anchor + m·K̄]·c_IC + a_s·C_key,R + C_wit,R + C_PSI
          + (K̄ + τ)·C_VH(L)
          + O( B_IO·log S + (q_0 + H_call + a_s + q_anchor + m·K̄ + K̄ + N + τ(m+3))·w·log S
               + (K̄ + τ)·L + N·L + N·u·(h + w)·log(u+1) + N·h + L )。                     (F-T)

Space_final ≤ S_src + O( B_IO + P_final·(128 + w) + (H_call + q_anchor + N + τ(m+3))·w
                          + K̄·(L + h + w) + τ·L + a_s·(128 + w) + u·(h + w) + L )。          (F-S)
```

其中 H_call 为全部普通与编程随机预言请求数，S_src 为 A、模拟器与验签原有状态的峰值空间。全桶族、整列揭示与 V* 只存在于证明中，不进入 B_final 的运行或内存。

**旧的在线提取器仍然有效。** 重做01（内部记录，未随仓库公开） 给出了在每个首次 H_2 回答前在线运行的多项式时间提取器（对应保守定理 C）。B_final 是同一归约的事后执行方式，二者各有各的资源账。

## 7. 原语依据：Rain-128-3 与 Rain-128-4

定理 1 把伪造归约为求 Rain 原像。本节说明为什么把 Rain-128-3 与 Rain-128-4 都当作 128 档原语是合理的。标准与 rFAEST 对其 AES 原语所用的相同：**原语设计者公开声明了该安全档位，并且至今没有已确立的、快于穷举的攻击。** 详细材料见[Rain128原语依据](Q4_01_Rain128_primitive.md)。

### 7.1 明示的计算假设

> **假设 H_Rain,R（R ∈ {3, 4}）。** 在普通游戏 G^OWF（§3.3，不访问任何预言）中，对官方 Rain-128-R 实例与真实拒零 KeyGen 产生的挑战，任何经典算法以不可忽略的概率求出一个有效原像（Rain_{K′}(P) = C 且各轮 S 盒输入非零），所需计算量与穷举 128 位密钥同量级。

说明：

- **与定理一致。** 定理 1 的原语项经引理 L 换成普通游戏（推论 1′），所以本假设正是定理右边使用的假设；被评价算法 C_final 的资源完整列在 §6 与引理 L 中。辅助理想分组密码不是被当作免费能力，它的代价已经计入 C_final。
- **表示。** 假设对 F 中的官方实例陈述，这是公开密码分析的对象；塔域线格式经域同构 ψ 精确等价（§1.3），不需要另外的假设。
- **文献的成功条件。** 原030 需要的是“任意有效原像”，不是“找回生成时的密钥”。Rain 设计论文 §4.3（第 13 页）把攻击目标定义为“recover a full key k which maps vin to vout”，即找到任意一个把该明文映到该密文的密钥，这正是任意原像问题。代数攻击用 x·y = 1 建模逆元（设计论文注明该建模以概率 (1 − 2^{−n})^r 成立），解出的是满足方程组、各轮 S 盒输入非零的密钥，即本文的受限原像；穷举返回第一个一致的密钥。所以 §7.3 所列的分析测量的就是本假设的问题。若某项公开结论只保护“原生成密钥”，要转到任意原像还需纤维控制（认证窗口/原语连接/01 §5.3（内部记录，未随仓库公开）：H_any ≤ μ·H_orig + Pr[m > μ]）；本文不走这条路，直接采用任意原像假设。
- **受限原像不会更容易。** 带非零限制的原像是全部原像（按 0 ↦ 0 的规范逆）的子集，能求前者就能求后者，所以“任意原像困难”蕴含本假设。
- **分布。** 拒零采样与均匀分布的总变差不超过 R/2^128，可以忽略。

### 7.2 设计者的声明

Rain 设计论文（Dobraunig 等，CCS 2022，ePrint 2021/692）§4.3.3：

> “We conclude that 3 rounds provide security against attackers who are only allowed to use a single (plaintext, ciphertext) pair. … While our analysis shows that 3 rounds are sufficient, we propose to primarily use Rain4, with an additional round of security margin.”

其表 2 给出各攻击需要的轮数：全轮 Gröbner 需 2 轮，引入中间变量的 Gröbner 需 3 轮，猜测-求解需 2 轮；差分、线性、积分、高阶差分、插值与线性化在单对模型下不适用。论文 §4 第 11–12 页明确：攻击者只能得到**一对**已知明密文。原030每个公钥恰好只公开一对 (P, C)。

### 7.4 判定

| 原语 | 判定（与 rFAEST 作者同层级） | 依据 | 必须同时写明的限定 |
|---|---|---|---|
| Rain-128-4 | **支持** | 设计者首选；没有任何 4 轮攻击；最偏向攻击方的估计（2^147.3）仍高于 NIST 1 级门数 | 计算假设；分析成熟度低于 AES |
| Rain-128-3 | **支持** | 设计者声明 3 轮足够；全部已确立的攻击都慢于穷举（最强约 2^139 次加密）；EUROCRYPT 2026 的最新评价为“unbroken” | **风险披露**：存在两项依赖未证假设的估计接近或低于 128 档（AIM 的强独立性 XL 估计；LMM24 的推测下界），均未被确立；已攻破的 2 轮只比它少一轮。其安全余量与可信度低于 Rain-4 |

两组都满足与 rFAEST 相同的判据：设计者声明加上没有已确立的攻击。差别在余量与可信度，而这一点 rFAEST 的 AES 远优于 Rain，需在结论中如实写出。

### 7.5 多用户说明（非定理）

定理 1 是单公钥结论。每个公钥都有独立均匀的公开输入 P，对不同用户而言 K ↦ Rain_K(P_u) 是不同的函数，一次密钥猜测只能检验一个用户，所以穷举无法在 U 个用户之间摊薄：找到任一用户密钥的期望工作量仍约为 2^128 次 Rain 求值。这与 EM 型单向函数用每个公钥独立的公开输入抵御多目标搜索的思路相同。这是对通用穷举的说明，不是多用户安全定理。

### 8.1 关系编码健全性

ePrint 2026/2235（2026-09）对 AIMer v2.0 给出了概率为 1、只用公钥的伪造：证明系统的约束中有乘积因子为零的分支，使中间值不受约束，满足约束的见证不一定解码为单向函数原像。作者把“关系编码健全”列为独立于单向函数困难性与证明系统可靠性的一项安全义务。

原030逐项满足：每轮约束是 x·y + 1 = 0（quicksilver.hpp:549（内部记录，未随仓库公开）），x = 0 时等式变为 0 = 1，约束本身排除零输入，不依赖建钥时的拒绝采样；末轮输出直接取 ct ⊕ k（owf_proof.inc:770（内部记录，未随仓库公开）），公钥被绑定进关系；见证只有 k 与前 R−1 轮的 y，全部受约束。引理 12 给出 e(W) = 0 ⇔ 有效原像。这与 2026/2235 §6.4 对 AIMer v3.0 的判断相同。该文 §6.1–6.2 也表明 rFAEST 底座 FAEST v2 的范数压缩编码对“0 的逆取 0”的语义是健全的；§6.3 的非唯一见证需要私钥，不构成伪造。
