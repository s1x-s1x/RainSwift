# 综合速度数据（全面测试方案 55 项）

这里是一套合成数据，主体为本项目的实测，缺失的项和指定的项用队友的实测补上。共两张表：

| 文件 | 内容 | 行数 |
|---|---|---:|
| [server_primitives.csv](server_primitives.csv) | 服务器原语：签名、公钥、私钥长度，建钥、签发、验签时间 | 55 |
| [laptop_tls.csv](laptop_tls.csv) | 笔记本：同一批签名接入混合 TLS 1.3 后的原语时间、握手字节和握手时间 | 41 |

编号与全面测试方案一致：1–41 为主清单（同类方案），42–55 为只在服务器上测的对照（MandaRain 变体、BN++Rain 对照）。CSV 为 UTF-8（带 BOM），Excel 可直接打开。

## 测量环境

| 项目 | 本项目服务器 | 本项目笔记本 |
|---|---|---|
| 硬件 | AMD EPYC 7R32（Zen 2，AVX2，无 VAES／GFNI），每次绑定一个逻辑 CPU（三个轮换） | Intel Core i7-14700HX，绑定性能核 |
| 系统与编译 | Linux 5.15；本轮 36 项中，FAEST 树与锚点用 Zig 0.13.0（clang 18）-O3，其余用 gcc／g++ 11.4.0；Q5、Q6 窗口为同一服务器、同一计时规程 | Windows 11；MSYS2 UCRT64 GCC 16.2.0 |
| 调用 | C 程序直接调用 `crypto_sign_keypair`／`crypto_sign`／`crypto_sign_open` | Python 3.13 ctypes 调用原生库（建钥含 ctypes 固定开销） |
| 样本 | 每实现每窗口 1,503 个样本，取中位数 | 签发、验签各 300 次，建钥 100 次，握手 200 次，取中位数 |
| 握手 | — | v9 混合 TLS 1.3：X25519＋ML-KEM-768；ECDSA P-256 与后量子签名同签 CertificateVerify；X.509 链；进程内 |

队友的环境如下：

- 服务器：conda GCC 14.4，`-O2 -march=native`，取主窗口中位数。
- 笔记本：AMD Ryzen 7 8845HS，GCC 16.2。签发、验签各 50 次，建钥 10 次。握手以 ML-KEM-768 为 KEM，不含 X.509 链，所以 38、39 的握手字节与时间不能和其余行直接比较。

## 使用注意

- 不同机器的绝对时间不能直接比较；比较方案时请用同一来源的行，或看倍数。
- 短档签发的三个值（编号 3、6、8）来自同一台队友服务器，三者之间可以互相比较。
- 本项目服务器是共享机器，三个窗口之间有 0%–34% 的差异；表中给的是三个窗口的平均值。
- 这些数字是速度测量，不代表 KAT 正确性、常数时间或安全性结论。安全性口径见 [Q4 完整安全证明](../Q4_03_security_proof.md)。
