# 追加记录：组件测试与写法选定（A1–A1d）

2026-10-16；候选 C030-Q5-KEYGEN。本文是对[冻结计划](Q5_plan.md)的追加记录：不改计划的不变量、关卡和止损条件，只记录第 3 节 K1–K3 的具体写法是怎样由服务器组件测试选定的。

## 1. 为什么要在服务器上选写法

本机（i7-14700HX，P 核与 E 核混合）的初测显示新求逆只快约 4%。可能原因是测试进程跑在 E 核上：E 核把 256 位向量指令拆成两半执行，查表多次平方吃亏；而 clmul 是 128 位指令，不受影响。所以本机测得的组件快慢不能代表服务器（Zen 2，原生 256 位）。因此在服务器上做了四次只编译单个测试程序的小运行（不是正式计时窗口）。每次先跑完整的新旧差分测试，再在 CPU 16、17、18 上做组件微基准（链式调用，201 批中位数）。四次差分测试全部 0 不一致。

| 运行 | 内容 | 差分测试 | 脚本时长 |
|---|---|---|---:|
| 01_A1 | 四种求逆加法链（V1–V4），线性层用可变移位 vpsllvq | 1,470 万次对比 0 不一致 | 62 s |
| 02_A1b | 线性层与多次平方改为立即数移位，选列 M1（vpcmpgtq）／M2（vblendvpd） | 1,733 万次 0 不一致 | 71 s |
| 03_A1c | 模约化两种写法：RED1（一次 clmul 折叠 + pshufb）／RED2（纯移位折叠） | 两种各 1,733 万次 0 不一致 | 100 s |
| 04_A1d | 选列再加 M3（常数掩码 vpand+vpcmpeqq）、M4（M2/M3 交替） | 2,207 万次 0 不一致 | 87 s |

各次运行的上传包、门控预检、负载记录和服务器输出（已脱敏）都在 `原始数据/运行记录/` 的对应子目录中。

## 3. 选定的写法及理由

- **K1 选列：M2。** 先在各 64 位通道预先放 x、x>>1、…，再统一做立即数左移，把待测位移到符号位，然后用 vblendvpd 按符号位选列。这是冻结计划 K1“移到符号位、按符号位常数时间选择”的具体实现：原计划写的是可变移位 vpsllvq，实测在 Zen 2 上更慢，改为预移位加立即数移位。常数掩码（M3）和混合（M4）都不如 M2。
- **K2 加法链：V4。** 即原实现的链 1,2,3,6,7,14,15,30,31,62,63，2^7、2^15、2^31 查表，2^3 用 3 次平方。冻结计划写的链 1,2,3,6,12,15,30,60,63（V2）同样实测过，两者速度相同（R=3：411 vs 414 ns；R=4：559 vs 556 ns）。选 V4，是因为它的链与已审的原实现相同，2^15、2^31 两张表直接取冻结常数 SQ15、SQ31，只有 2^7 一张表在编译期生成，并由编译期断言核对过。
- **K3 模约化：RED1。** 第一次折叠仍用 clmul，第二次折叠（不足 3 位）用寄存器内 16 项 pshufb 表，与冻结计划 K3 相同。纯移位折叠（RED2）实测没有更快，不采用，代码中已删去。
- 头文件中保留其余写法（V1–V3、M1、M3、M4），只供差分测试与微基准使用。建钥路径由常量 `INV_CHAIN = 4`、`MAP_METHOD = 2` 固定，不受编译参数影响。
